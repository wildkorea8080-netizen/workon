# 입력형 앱 일괄 실행 (2026-11-09, 0077)

같은 앱을 입력만 바꿔 여러 번 돌리는 일(민원 수십 건의 답변 방향, 사업 수십 개의 위험 검토)을 한 번에 맡긴다. 실행 화면 아래 **'여러 건 한 번에 실행(일괄 실행)'**에서 표를 붙이면 줄마다 앱을 실행하고, 결과를 줄마다 모아 엑셀로 받는다.

## 넣는 법

- **엑셀에서 표를 복사해 붙이거나 CSV 파일**을 고른다(`src/lib/apps/batch-spec.ts` `parseBatchTable` — 잎 파일). 첫 줄은 **입력 항목 이름이나 키**(대소문자·공백 무시), 아래로 한 줄에 한 건, **100줄까지**. 첫 줄에 탭이 있으면 탭, 아니면 쉼표로 가른다. 따옴표 칸(쉼표·`""`·줄바꿈)·BOM을 읽고 빈 줄은 건너뛴다. 모르는 머리글·같은 항목 두 번·칸이 넘치는 줄은 줄 번호와 함께 거절. '머리글 넣기' 단추가 이 앱의 항목 이름을 넣어 준다.
- 화면이 줄마다 앱 규칙(`renderAppInput` — 필수·조건부 필수·목록 값)으로 미리 검사하고 **많으면 AI 호출 수**(줄마다 `estimateAppCalls`의 많으면 값 합)를 보인다. 서버가 같은 규칙으로 다시 본다.
- **파일 첨부가 꼭 필요한 앱은 '파일마다 한 건'(아래, 0079)으로만** 일괄 실행한다. 문서함 고르기는 일괄 실행에 없다. 시험 판 실행 화면에는 이 칸이 없다(일괄 실행은 언제나 지금 판).
- 한 사람에 **실행 중 3개**까지.

## 실행

- `POST /api/apps/batches { agent_id, name?, rows }` — 쓸 수 있는 앱(`canUseAgent`)·링크형 아님·입력형 앱만. 만들 때의 **앱 판·부서**를 박아 둔다.
- **앱 예약 실행기(pg_cron 5분마다)** 가 예약 실행·결과 보내기와 나란히 돌린다(`runDueBatchItems`). 실행 중인 묶음의 줄을 **만든 순서·줄 순서**로 조건부 차지(pending → running, 15분 넘게 running이면 끊긴 것으로 보고 다시 차지)해 예약과 같은 `runAppAs`로 실행한다 — **그 직원의 세션 꼴**이라 권한·한도·사용 기록·숫자 확인·결과 보내기(0076)가 손 실행과 같다. 대화 제목 앞에 `[일괄] `.
- **두 줄씩 나란히**, 새 줄은 실행기 호출 시작 90초 안에서만 시작하고, 새 모델 호출 마감은 150초(함수 300초 안에 끝나게). 그래서 5분마다 몇 줄씩 — 100줄이면 몇 시간 걸릴 수 있다(창을 닫아도 이어 간다).
- 결과:

| 실행 결과 | 처리 |
|---|---|
| 마침 | 줄 `done` — 그 실행의 대화·답변 메시지를 가리킨다(결과 글을 따로 저장하지 않음) |
| 앱 판 바뀜(409)·앱을 쓸 수 없음(403·404)·한도(429)·계정 비활성·부서 바뀜 | **묶음을 멈춤**(`stopped`·사유) — 그 줄과 남은 줄은 건너뜀 |
| 그 줄의 입력 문제(400 등) | 그 줄만 실패, 다음 줄로 |
| 모델 오류·응답 끊김 | 한 번 더(두 번째도 실패면 실패) |

- 열린 줄이 없으면 묶음 `done`. 직원이 **그만두면**(`DELETE /api/apps/batches/[id]`) 기다리던 줄은 건너뛰고, 실행 중인 줄은 끝까지 간다.

## 파일마다 한 건 (2026-11-10, 0079)

- 파일을 받는 앱(앱 설정의 '파일 첨부 받기')이면 일괄 실행 칸에 **'표로 여러 건' / '파일마다 한 건'**을 고른다(파일이 꼭 필요한 앱은 '파일마다 한 건'만). 파일을 **10개까지**(`BATCH_MAX_FILES`) 올리면 파일 하나마다 줄 하나로 앱을 실행한다 — 공문·민원 파일 여러 개를 같은 앱으로 하나씩 처리하는 일.
- 입력 항목은 같은 표 칸에 **한 줄**(모든 파일에 같은 입력)이나 **파일 수와 같은 줄**(올린 순서대로 짝, `pairRowsWithFiles`)로 넣는다. 입력이 필요 없으면(필수 항목 없음) 비워 둔다. 화면이 같은 규칙으로 미리 검사하고 파일 하나씩 붙인 실행의 많으면 AI 호출 수를 보인다(`previewFileBatch`).
- 파일은 실행 화면과 같은 길(`uploadAttachment` — 직접 올리기·읽기·스캔 PDF)로 첨부가 되고, 만들기(`POST /api/apps/batches { …, attachment_ids }`)가 **요청자의 읽힌 첨부만**(`ready`) 줄마다 사본 `app-batch-files/{기관}/{직원}/{id}.{확장자}`로 복사해 줄의 `file`(0079)에 적는다(`copyAttachmentsTo` — 예약의 올린 파일 0073과 같은 복사). 원본 첨부는 복사한 뒤 묘비로 지운다 — 직원의 '보내지 않은 첨부' 상한(20)을 빨리 돌려주려고(실행 때 다시 붙일 몫). 10개 상한도 그 상한 때문이다.
- 실행기는 그 줄을 돌릴 때 사본을 **그 직원의 새 첨부로 다시 붙여**(`attachStoredObject` — 형식·크기·읽기·사용 기록 규칙이 손 실행과 같다) 함께 실행한다(`runBatchItem`). 사본을 불러오지 못하는 일시 오류는 한 번 더, 사본이 없거나 붙인 파일을 읽지 못하면 그 줄만 실패(그 첨부는 묘비로), 시작 전에 거절되면 붙인 첨부를 묘비로.
- **사본은 묶음이 끝나면 지운다**(마침·멈춤 — 실행기가 그 묶음을 끝낸 호출에서, 그만둠 — 그만두기에서, `removeBatchFiles`). 줄의 파일 이름은 남아 결과 엑셀에 **'파일'** 열로 나온다. 실패는 운영 기록 warning만(경로와 함께). 직원이 탈퇴하면 실행기가 다음 차례에 '계정을 쓸 수 없음'으로 묶음을 멈추며 사본을 지운다.

## 마침 알림 (2026-11-10, 마이그레이션 없음)

- 묶음이 **모두 마치거나(`done`) 멈추면(`stopped`)** 만든 직원에게 메일 한 통(`notifyBatchFinished` → `batchFinishedMail`). 묶음을 끝낸 조건부 갱신(`… .eq('status', 'running').select('id')`)을 **실제로 한 호출만** 보내므로, 두 줄이 나란히 끝나거나 실행기가 겹쳐도 한 번이다. 직원이 그만둔 묶음은 알리지 않는다(직원이 한 일).
- 글: 앱·일괄 실행 이름·마친 시각(KST)·줄 수(전체·마침·실패·건너뜀)·멈춘 이유, 이 묶음의 답변 중 **보내기 전 확인(0078)을 기다리는 결과 수**(그 직원의 기록만 — 7일 안에 정하라는 안내), '실행 화면 열기'·'결과 엑셀 받기'(마친·실패한 줄이 있을 때, 로그인한 주인만 받음). **입력값·결과 글은 싣지 않는다.**
- 메일이 설정되지 않았거나 주소가 없으면 보내지 않는다. 보내지 못하면 운영 기록 warning(`앱 일괄 실행 마침 메일을 보내지 못했습니다` — 묶음 id·오류만)만 남기고 실행기는 이어 간다(다시 보내지 않음). 실행기 결과에 `notified`(보낸 수).
- 끄는 설정은 없다 — 묶음 하나에 한 통이라 예약 완료 메일(0069)처럼 고르게 하지 않았다(구현자 판단).

## 결과

- 실행 화면 목록(`GET /api/apps/batches?agent=`): 이름·상태·완료/실패/건너뜀·시각·멈춘 사유, 실행 중이면 30초마다 다시 읽음.
- **결과 엑셀**(`GET /api/apps/batches/[id]/export`): 번호·입력 항목들(지금 앱의 항목 이름, 없어진 항목은 키)·상태·**결과 글**(그 실행의 답변 — 만든 사람의 대화만)·오류·대화 주소. 값만, 수식 주입 막음(`safeText`), 칸 32,000자.
- 모든 일괄 실행 API는 **만든 사람만**(관리자도 남의 것은 못 봄). 대화를 지우면 그 줄의 대화·답변 칸만 비고(결과 글이 엑셀에서 빠짐), 묶음을 지우면 줄도 지워진다.

## 남은 것

- 표 모드의 줄마다 파일을 붙이지는 못한다(파일은 '파일마다 한 건'으로, 줄 하나에 파일 하나·10개까지). 문서함 문서는 붙이지 못한다. 실제 파일로 끝까지 돌려 보지 않았다(시험은 가짜 첨부). 관리자 화면에 일괄 실행 현황은 없다(사용 기록·앱 실행 현황에는 실행마다 잡힌다). 마침 메일을 실제 메일함에서 받아 보지는 않았다(글·보낼지 판단만 시험).
- 처리 속도는 5분마다 몇 줄 — 실제 대용량(수백·수천 건)·병렬 처리량은 재지 않았다. 화면은 브라우저로 보지 않았다.
