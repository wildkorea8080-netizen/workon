# 입력형 앱 외부 연동(Webhook) (2026-11-03)

알리웍스 Agent Builder는 에이전트에 스케줄과 **Webhook(멤버 토큰)** 트리거를 건다([REA 재분석](REA_PUBLIC_WEB_ANALYSIS_2026-10-31.md)). 스케줄은 [앱 예약](APP_SCHEDULES.md)으로 넣었고, 이번에 Webhook을 넣었다. 기관의 다른 시스템(민원 접수·그룹웨어·업무 포털)이 입력값을 보내면 직원이 만든 입력형 앱이 그 직원의 권한으로 한 번 돈다.

## 직원이 보는 것

- 입력형 앱 실행 화면(`/apps/run`) 아래 **'외부 시스템 연동(Webhook) 만들기'** → 연동 이름(40자)과 유효 기간(30·90·365일)을 고르면 **연동 토큰이 한 번만** 보인다(복사 단추·호출 예시 `curl`). 다시 볼 수 없다.
- **앱 연동**(`/apps/webhooks`, 메뉴 '앱 예약·연동'): 연동마다 이름·앱·토큰 앞부분(`wo_wh_…` 12자)·만료일·실행 횟수·마지막 실행·마지막 실패 이유, **회수** 단추, 마지막 결과 대화.
- 쓸 수 있는(회수·만료 안 된) 연동은 한 사람당 5개. 파일을 받는 앱은 외부 시스템이 **호출마다 파일을 함께 보낼 수 있다**(아래 '보내는 파일', 2026-11-08 — 그래서 파일이 필요한 앱도 연동을 만들 수 있다). '문서함에서 고르기'를 허용한 앱은 고른 문서를 연동에 함께 저장한다(아래 '문서함 문서', 0063). 대리 접근 중에는 토큰을 만들 수 없다(슈퍼관리자가 직원 이름으로 토큰을 남기지 않게).
- 결과는 그 직원의 대화로 저장되고 제목 앞에 `[연동] `이 붙어 앱 실행 기록에 함께 보인다. 사용량은 그 직원의 기록으로 남는다.

## 문서함 문서 (2026-11-05, 0063)

- 실행 화면에서 문서함 문서를 고른 채 연동 토큰을 만들면 문서 id가 `app_webhooks.document_ids`(3개까지)에 저장된다. 만들 때 지금 고를 수 있는 문서인지 서버가 다시 본다(예약과 같은 `appDocumentChoice`·`verifyChosenDocuments` — `src/lib/apps/app-document-choice.ts`).
- **외부 시스템은 문서를 보내지 않는다**(본문은 지금처럼 `{ inputs }`). 호출마다 저장한 문서의 **지금 근거 판**으로 읽는다(`executeWebhook` → `currentEditionIds` — 새 판이 시행되면 새 판, 시행일 전·읽는 중이면 옛 판). 새 판으로 따라간 호출이 완료되면 연동의 문서 id를 새 판으로 바꾼다.
- **쓸 판이 없으면(지움·읽기 실패·지난 판만) 앱을 돌리지 않고 422**(`WEBHOOK_DOCUMENTS_UNAVAILABLE` — 문서를 다시 골라 연동을 새로 만들라는 안내). `Idempotency-Key`가 있으면 4xx라 같은 키에 같은 응답을 돌려준다. 문서 행을 못 읽으면 실행 오류(502).
- 연동 목록에 '문서함 문서 N개'가 보인다. 어느 판을 썼는지는 결과 답의 `source_references.app_documents`에 남는다(외부 응답에는 싣지 않는다).

## 보내는 파일 (2026-11-08, 마이그레이션 없음)

엑셀 취합·접수 문서 요약처럼 파일이 있어야 하는 앱은 연동을 만들 수 없었다(문서함 문서만 됐다). 외부 시스템이 파일을 가진 경우가 많다(예: 접수 시스템이 첨부를 넘김).

- 본문 `files`: `[{ "name": "자료.xlsx", "content_base64": "…" }]` — **3개까지, 풀어서 합계 3MB**(base64로 약 4MB — Vercel 요청 본문 상한 4.5MB 안). 형식은 채팅 첨부와 같다(엑셀·CSV·한글·워드·PDF·파워포인트·TXT). 파일이 있는 호출은 본문 4.3MB까지, 입력(`inputs`) 부분은 그대로 64KB. 파일이 없으면 예전과 같다(본문 64KB).
- 꼴·base64·형식·개수·크기는 **차지 전에** 본다(`parseWebhookFiles` — 틀리면 400·413, 호출 횟수를 쓰지 않음).
- 차지한 뒤 파일마다 **그 직원의 새 첨부로 올린다**(`attachBytes` — 직접 올리기·지난 파일과 같은 발급·확인 길이라 형식·크기·읽기·스캔 PDF(NODA `/parse`)·보내지 않은 첨부 상한·사용 기록 `file_attached`가 같다). 그 실행의 대화에 손 실행과 같은 `attachment_ids`로 붙고 대화와 함께 산다. 따로 보관하지 않는다.
- **읽지 못하면 앱을 돌리지 않고 422**(`보낸 파일 'x'을 읽지 못했습니다(이유)` — 만든 첨부는 묘비로). 발급 거절은 그 상태 그대로(형식 400·크기 413·보내지 않은 첨부 상한 429). 실행이 시작 전에 거절되면(입력 400·앱 변경 409 등) 올린 첨부를 묘비로 지운다.
- 문서함 문서와 함께 쓰면 합쳐 3개(실행기가 본다). 파일이 필요한 앱을 파일·문서 없이 부르면 실행기가 400(`이 앱은 파일 첨부가 필요합니다.`).
- `Idempotency-Key` 요청 해시에 파일 **이름·SHA-256**을 더한다(파일이 없으면 예전과 같은 해시 — 같은 키·다른 파일이면 422).
- 연동 만들기 화면이 파일을 받는 앱이면 안내와 `files`가 든 호출 예시를 보인다.
- 한계: 파일 내용이 그 직원의 대화 첨부로 남는다(외부 시스템이 보낸 자료가 기관 저장소에 들어온다 — 손으로 올린 첨부와 같은 수명). 3MB 넘는 파일은 못 보낸다(서명 주소로 올리는 길은 없음).
- 검증: `tests/app-webhook-files.test.ts`(9 — 꼴·base64·형식·개수·빈 파일·합계 3MB, 실행기에 풀어 넘김·64KB 넘는 본문도 파일이면 받음·입력 64KB, 꼴이 틀리면 차지 안 함, 요청 해시(파일 없으면 예전과 같음·내용 다르면 다름), 새 첨부로 실행·읽지 못하면 422와 정리·발급 거절 상태 그대로·시작 전 거절이면 정리·시작했으면 둠, 화면·예시), `tests/app-webhooks*.test.ts`·`app-webhook-documents.test.ts`(바뀐 상한·문구).

## 외부 시스템이 부르는 법

```
POST /api/apps/webhook
Authorization: Bearer wo_wh_…
Content-Type: application/json
Idempotency-Key: order-2026-11-03-42      (선택 — 요청마다 다른 값)

{ "inputs": { "항목 키": "값", … }, "files": [{ "name": "자료.xlsx", "content_base64": "…" }] }   (files는 선택)
```

- 입력은 앱의 항목 키와 글·숫자·참거짓 값(글로 바뀐다). 검사(필수·형식·길이)는 실행기가 그 앱 판으로 다시 한다. 본문 64KB까지(파일이 있으면 입력 64KB·파일 합계 3MB — 위 '보내는 파일').
- 실행이 끝날 때까지 기다린다(최대 300초). **응답에는 상태와 대화 id만** 온다 — 앱의 결과 글은 외부로 돌려주지 않는다.

| 상황 | 상태 |
| --- | --- |
| 실행 완료 | 200 `{ ok: true, data: { status: 'completed', conversation_id } }` |
| 토큰이 없음·꼴이 틀림·없는 토큰·회수·만료 | 401 — 사유를 가르지 않는다 |
| 같은 토큰을 60초 안에 다시 | 429 + `Retry-After` |
| 같은 토큰 하루(한국 날짜) 100번 넘음 | 429 |
| 본문이 JSON이 아님·inputs 꼴이 틀림·필수 입력 빠짐 | 400 |
| 본문이 64KB 넘음 | 413 |
| 직원 계정 비활성·탈퇴·부서 이동, 앱을 쓸 수 없음 | 403·404 |
| 앱 설정이 바뀜(만들 때 판과 다름) | 409 — 연동을 다시 만들라는 안내 |
| 기관 한도 초과 | 429(실행기 안내 그대로) |
| 모델 오류·응답이 끝나지 않음 | 502 |
| `Idempotency-Key` 꼴이 틀림(영문·숫자·`_.:-` 1~100자가 아님) | 400 |
| 같은 키를 다시 보냄(처음 호출이 끝남) | 처음 응답 그대로 + `Idempotent-Replayed: true` (완료면 200에 `replayed: true`) |
| 같은 키를 다시 보냄(처음 호출이 아직 도는 중) | 409 + `Retry-After: 30` |
| 같은 키로 다른 입력을 보냄 | 422 |

### 재시도 중복 막기(Idempotency-Key, 2026-11-03, 0051)

외부 시스템은 응답을 못 받으면(시간 초과·연결 끊김) 같은 요청을 다시 보낸다. 60초 간격 제한은 그 안의 재시도만 막고, 그 뒤의 재시도는 앱을 한 번 더 돌려 모델 비용이 두 번 들고 대화가 둘 생긴다.

- 요청에 `Idempotency-Key`를 실으면 **같은 연동·같은 키**의 호출은 24시간 동안 앱을 다시 돌리지 않고 처음 응답(상태·대화 id·안내)을 돌려준다. 다시 보내기는 60초 간격·하루 상한·실행 횟수를 쓰지 않는다. 머리글이 없으면 예전과 같다.
- 판정은 차지 함수(`app_webhook_claim`)가 토큰 행을 잠근 채 한다 — 같은 키가 동시에 와도 하나만 돈다(나머지는 409). 무효 토큰은 키가 있어도 401.
- 같은 키로 **다른 입력**이면 422(입력은 저장하지 않고 키 순서를 맞춘 입력의 SHA-256만 `app_webhook_calls.request_hash`에 둔다).
- **지나가는 실패는 기록하지 않는다** — 502(모델 오류·실행 오류)와 기관 한도 429는 같은 키로 다시 보내면 새로 돈다. 완료와 그 밖의 4xx(입력 오류 400·권한 403·앱 변경 409)는 같은 응답을 돌려준다.
- 처음 호출이 10분 넘게 `running`이면(함수가 죽음) 멈춘 실행으로 보고 같은 키를 새로 받는다. 24시간 지난 키는 다시 쓸 수 있다(그 연동의 오래된 기록은 차지 때 지운다).
- 화면의 호출 예시(`curl`)에 머리글이 들어 있다.

### 비동기 호출 (2026-11-11, 0087)

- 본문에 `"async": true`를 넣거나 머리글 `Prefer: respond-async`를 실으면 앱이 끝나기를 기다리지 않고 **202** `{ ok: true, data: { status: "accepted", batch_id, result_delivery } }`를 바로 돌려준다(`src/lib/apps/webhooks.ts` `enqueueWebhookRun`). 300초를 넘는 앱도 이 길로 돈다.
- 받은 호출은 그 직원의 **한 줄짜리 일괄 실행**([일괄 실행](APP_BATCHES.md) — 이름 `[연동] 앱 이름`, `source='webhook'`)이 된다. 넣기 전에 기다리는 호출과 같은 문턱을 본다: 계정(비활성·탈퇴 403)·부서(바뀌면 403)·연동이 박은 앱 판(바뀌면 409)·앱 입력 규칙(400)·기관의 일괄 실행 상한. 일괄 실행 실행기(5분)가 그 직원의 권한으로 손 실행과 같은 길로 돌린다.
- **결과는 앱의 '결과 보낼 곳'**([결과 보내기](APP_OUTBOUND.md) — 기관 전체 관리자가 승인한 https 주소)이 정해져 있으면 그리로 간다. 몸의 `run.batch_id`가 202 응답의 `batch_id`와 같아 외부 시스템이 맞춰 본다(이것이 콜백 — 임의 콜백 주소는 받지 않는다). `result_delivery: false`면 결과는 직원의 앱 실행 기록에만 남는다.
- 받지 않는 것: 본문 `files`(400 — 파일은 기다리는 호출로), 문서함 문서를 고른 연동(400). 직원의 실행 중인 일괄 실행이 3개면 429(기록하지 않아 같은 키로 다시 보낼 수 있다).
- `Idempotency-Key`: 같은 키로 다시 보내면 처음 받은 `batch_id`를 그대로(202, `replayed: true`). 같은 키로 기다리는 호출과 비동기를 섞으면 다른 요청이라 422.
- 비동기 묶음은 **마침 메일을 보내지 않는다**(호출마다 메일이 가지 않게). 연동 목록의 '마지막 결과'는 그 줄이 끝날 때 일괄 실행 실행기가 바꾼다(2026-11-11 — 마침이면 완료와 대화, 실패·멈춤이면 실패와 이유).
- **상태 묻기**: `GET /api/apps/webhook/batches/{batch_id}`(같은 연동 토큰 Bearer, `src/lib/apps/webhook-status.ts`) → 200 `{ batch_id, status, conversation_id, error, accepted_at, finished_at, delivery }`(`Cache-Control: no-store`).
  - `status`: `queued`(차례 기다림)·`running`·`completed`·`failed`(그 줄만 실패 — `error`에 안내)·`stopped`(묶음이 멈춤 — 앱 판·권한·한도, `error`에 이유)·`cancelled`. `conversation_id`는 완료·실패일 때만.
  - `delivery`: 결과 보낼 곳이 있을 때 `{ status: pending|awaiting_approval|sent|gave_up|rejected, receipt_reference }`(접수 번호는 보냈을 때만), 아직 보내기 기록이 없으면 null.
  - **그 연동이 넣은 묶음만** 보인다(`app_batches.webhook_id`, 0087) — 다른 연동·손으로 만든 묶음·없는 번호·꼴이 틀린 번호는 모두 같은 404. 토큰이 없거나 회수·만료면 401, 기관이 연동을 끄면 403.
  - 결과 글·입력값은 싣지 않는다. 묻기는 실행이 아니라 60초 간격·하루 상한·사용 횟수를 쓰지 않는다. 연동을 지우면 묶음의 `webhook_id`만 비어 더 묻지 못한다(묶음·결과는 직원의 것이라 남음).

## 지키는 것

- **토큰 원문은 저장하지 않는다.** `wo_wh_` + 32바이트 무작위(base64url 43자)이고 DB(`app_webhooks.token_hash`)에는 SHA-256만, 화면에는 앞 12자만 남는다. 유효 기간은 필수(무기한 없음), 회수는 되돌릴 수 없고 행은 지우지 않는다(사용 기록이 남게).
- **실행은 그 직원으로**: `src/lib/apps/run-as.ts`의 `runAppAs`를 예약 실행과 같이 쓴다 — 그 직원의 세션 꼴로 대화 실행기를 손 실행과 같은 본문으로 태운다(앱 권한·기관 한도·모델 정책·금지어·사용 기록·대화 저장).
- **차지는 DB가 원자적으로**(`app_webhook_claim`, 0049): 토큰 행을 `FOR UPDATE`로 잠그고 유효·60초 간격·하루 상한을 본 뒤 사용 기록을 올린다. 동시에 세 번 불러도 하나만 통과한다(실제 Postgres 시험). 실행 권한은 `service_role`만. 꼴 검사(토큰·본문)에서 거절된 호출은 횟수를 쓰지 않는다.
- **데이터가 기관 밖으로 늘지 않는다**: 외부 시스템이 보내는 것은 입력값(앱에 사람이 넣을 것과 같은 것)이고 받는 것은 상태뿐이다. 운영 기록(`system_logs` `api`)에는 연동 id·앱 id·상태만 남기고 입력값·결과 글은 남기지 않는다.
- 공개 라우트라 `tests/route-auth.test.ts`의 공개 목록에 이유와 함께 적었다.

## 배포 순서

1. 운영 DB에 0049 적용(`npm run db:migrate -- 0049`) — **코드 배포 전**. 없으면 연동 화면·API만 503.
2. 가지 푸시 → Preview Ready 확인 → `main` 푸시(운영 배포).
3. 직원 계정으로 연동을 하나 만들어 토큰으로 한 번 불러 보고 `[연동]` 대화와 '실행 1회'를 확인한 뒤 회수해 401이 되는지 본다.

## 알려진 한계

- 응답 본문에 결과 글을 싣지 않는다 — 일부러. 결과를 외부로 보내는 길은 기관 전체 관리자가 승인한 '결과 보낼 곳'뿐이고, 비동기 호출(0087)은 그 몸의 `run.batch_id`로 맞춘다. 호출마다 임의 콜백 주소를 받지 않는다.
- 기다리는 호출은 300초를 넘는 앱에서 끊긴다 — 그런 앱은 비동기 호출(0087)로 부른다. 파일은 본문에 담아 보낸다(2026-11-08 — 합계 3MB까지, 위 '보내는 파일'). 문서함 문서는 0063. 재시도 중복은 `Idempotency-Key`(0051)로 막는다 — 외부 시스템이 키를 싣지 않으면 60초 뒤 재시도는 다시 돈다.
- (2026-11-03 0050) 기관 관리자가 관리 범위 직원의 연동을 보고 사유와 함께 회수할 수 있다([관리자 통제](APP_AUTOMATION_ADMIN.md)). 계정 탈퇴 때 쓰는 연동은 자동으로 회수된다. 기관 전체를 한 번에 끄는 스위치는 2026-11-08에 넣었다(0068 — 기관 전체 관리자, 호출은 차지 전에 403, 토큰은 그대로 — [관리자 통제](APP_AUTOMATION_ADMIN.md)).
