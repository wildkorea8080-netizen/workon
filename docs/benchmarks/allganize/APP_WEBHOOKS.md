# 입력형 앱 외부 연동(Webhook) (2026-11-03)

알리웍스 Agent Builder는 에이전트에 스케줄과 **Webhook(멤버 토큰)** 트리거를 건다([REA 재분석](REA_PUBLIC_WEB_ANALYSIS_2026-10-31.md)). 스케줄은 [앱 예약](APP_SCHEDULES.md)으로 넣었고, 이번에 Webhook을 넣었다. 기관의 다른 시스템(민원 접수·그룹웨어·업무 포털)이 입력값을 보내면 직원이 만든 입력형 앱이 그 직원의 권한으로 한 번 돈다.

## 직원이 보는 것

- 입력형 앱 실행 화면(`/apps/run`) 아래 **'외부 시스템 연동(Webhook) 만들기'** → 연동 이름(40자)과 유효 기간(30·90·365일)을 고르면 **연동 토큰이 한 번만** 보인다(복사 단추·호출 예시 `curl`). 다시 볼 수 없다.
- **앱 연동**(`/apps/webhooks`, 메뉴 '앱 예약·연동'): 연동마다 이름·앱·토큰 앞부분(`wo_wh_…` 12자)·만료일·실행 횟수·마지막 실행·마지막 실패 이유, **회수** 단추, 마지막 결과 대화.
- 쓸 수 있는(회수·만료 안 된) 연동은 한 사람당 5개. 파일 첨부가 필수인 앱은 연동할 수 없다. 대리 접근 중에는 토큰을 만들 수 없다(슈퍼관리자가 직원 이름으로 토큰을 남기지 않게).
- 결과는 그 직원의 대화로 저장되고 제목 앞에 `[연동] `이 붙어 앱 실행 기록에 함께 보인다. 사용량은 그 직원의 기록으로 남는다.

## 외부 시스템이 부르는 법

```
POST /api/apps/webhook
Authorization: Bearer wo_wh_…
Content-Type: application/json
Idempotency-Key: order-2026-11-03-42      (선택 — 요청마다 다른 값)

{ "inputs": { "항목 키": "값", … } }
```

- 입력은 앱의 항목 키와 글·숫자·참거짓 값(글로 바뀐다). 검사(필수·형식·길이)는 실행기가 그 앱 판으로 다시 한다. 본문 64KB까지.
- 실행이 끝날 때까지 기다린다(최대 300초). **응답에는 상태와 대화 id만** 온다 — 앱의 결과 글은 외부로 돌려주지 않는다.

| 상황 | 상태 |
| --- | --- |
| 실행 완료 | 200 `{ ok: true, data: { status: 'completed', conversation_id } }` |
| 토큰이 없음·꼴이 틀림·없는 토큰·회수·만료 | 401 — 사유를 가르지 않는다 |
| 같은 토큰을 60초 안에 다시 | 429 + `Retry-After` |
| 같은 토큰 하루(한국 날짜) 100번 넘음 | 429 |
| 본문이 JSON이 아님·inputs 꼴이 틀림·필수 입력 빠짐 | 400 |
| 본문이 64KB 넘음 | 413 |
| 직원 계정 비활성·탈퇴·부서 이동, 앱을 쓸 수 없음 | 403·404 |
| 앱 설정이 바뀜(만들 때 판과 다름) | 409 — 연동을 다시 만들라는 안내 |
| 기관 한도 초과 | 429(실행기 안내 그대로) |
| 모델 오류·응답이 끝나지 않음 | 502 |
| `Idempotency-Key` 꼴이 틀림(영문·숫자·`_.:-` 1~100자가 아님) | 400 |
| 같은 키를 다시 보냄(처음 호출이 끝남) | 처음 응답 그대로 + `Idempotent-Replayed: true` (완료면 200에 `replayed: true`) |
| 같은 키를 다시 보냄(처음 호출이 아직 도는 중) | 409 + `Retry-After: 30` |
| 같은 키로 다른 입력을 보냄 | 422 |

### 재시도 중복 막기(Idempotency-Key, 2026-11-03, 0051)

외부 시스템은 응답을 못 받으면(시간 초과·연결 끊김) 같은 요청을 다시 보낸다. 60초 간격 제한은 그 안의 재시도만 막고, 그 뒤의 재시도는 앱을 한 번 더 돌려 모델 비용이 두 번 들고 대화가 둘 생긴다.

- 요청에 `Idempotency-Key`를 실으면 **같은 연동·같은 키**의 호출은 24시간 동안 앱을 다시 돌리지 않고 처음 응답(상태·대화 id·안내)을 돌려준다. 다시 보내기는 60초 간격·하루 상한·실행 횟수를 쓰지 않는다. 머리글이 없으면 예전과 같다.
- 판정은 차지 함수(`app_webhook_claim`)가 토큰 행을 잠근 채 한다 — 같은 키가 동시에 와도 하나만 돈다(나머지는 409). 무효 토큰은 키가 있어도 401.
- 같은 키로 **다른 입력**이면 422(입력은 저장하지 않고 키 순서를 맞춘 입력의 SHA-256만 `app_webhook_calls.request_hash`에 둔다).
- **지나가는 실패는 기록하지 않는다** — 502(모델 오류·실행 오류)와 기관 한도 429는 같은 키로 다시 보내면 새로 돈다. 완료와 그 밖의 4xx(입력 오류 400·권한 403·앱 변경 409)는 같은 응답을 돌려준다.
- 처음 호출이 10분 넘게 `running`이면(함수가 죽음) 멈춘 실행으로 보고 같은 키를 새로 받는다. 24시간 지난 키는 다시 쓸 수 있다(그 연동의 오래된 기록은 차지 때 지운다).
- 화면의 호출 예시(`curl`)에 머리글이 들어 있다.

## 지키는 것

- **토큰 원문은 저장하지 않는다.** `wo_wh_` + 32바이트 무작위(base64url 43자)이고 DB(`app_webhooks.token_hash`)에는 SHA-256만, 화면에는 앞 12자만 남는다. 유효 기간은 필수(무기한 없음), 회수는 되돌릴 수 없고 행은 지우지 않는다(사용 기록이 남게).
- **실행은 그 직원으로**: `src/lib/apps/run-as.ts`의 `runAppAs`를 예약 실행과 같이 쓴다 — 그 직원의 세션 꼴로 대화 실행기를 손 실행과 같은 본문으로 태운다(앱 권한·기관 한도·모델 정책·금지어·사용 기록·대화 저장).
- **차지는 DB가 원자적으로**(`app_webhook_claim`, 0049): 토큰 행을 `FOR UPDATE`로 잠그고 유효·60초 간격·하루 상한을 본 뒤 사용 기록을 올린다. 동시에 세 번 불러도 하나만 통과한다(실제 Postgres 시험). 실행 권한은 `service_role`만. 꼴 검사(토큰·본문)에서 거절된 호출은 횟수를 쓰지 않는다.
- **데이터가 기관 밖으로 늘지 않는다**: 외부 시스템이 보내는 것은 입력값(앱에 사람이 넣을 것과 같은 것)이고 받는 것은 상태뿐이다. 운영 기록(`system_logs` `api`)에는 연동 id·앱 id·상태만 남기고 입력값·결과 글은 남기지 않는다.
- 공개 라우트라 `tests/route-auth.test.ts`의 공개 목록에 이유와 함께 적었다.

## 배포 순서

1. 운영 DB에 0049 적용(`npm run db:migrate -- 0049`) — **코드 배포 전**. 없으면 연동 화면·API만 503.
2. 가지 푸시 → Preview Ready 확인 → `main` 푸시(운영 배포).
3. 직원 계정으로 연동을 하나 만들어 토큰으로 한 번 불러 보고 `[연동]` 대화와 '실행 1회'를 확인한 뒤 회수해 401이 되는지 본다.

## 알려진 한계

- 결과를 외부에 돌려주는 길(콜백·응답 본문)이 없다 — 일부러. 필요해지면 기관 승인과 함께 따로 설계한다.
- 호출은 동기(끝날 때까지 기다림)라 300초를 넘는 앱은 끊긴다. 파일 입력은 없다. 재시도 중복은 `Idempotency-Key`(0051)로 막는다 — 외부 시스템이 키를 싣지 않으면 60초 뒤 재시도는 다시 돈다.
- (2026-11-03 0050) 기관 관리자가 관리 범위 직원의 연동을 보고 사유와 함께 회수할 수 있다([관리자 통제](APP_AUTOMATION_ADMIN.md)). 계정 탈퇴 때 쓰는 연동은 자동으로 회수된다. 기관 전체를 한 번에 끄는 스위치는 없다.
