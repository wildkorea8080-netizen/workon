# 앱 결과 HWPX 내보내기

입력형 앱의 최종 결과 아래 **한글(HWPX) 파일 만들기**를 추가했다. 단계 없는 입력형 앱과 완료된 단계형 앱 모두 사용할 수 있다. 저장된 대화를 다시 열었을 때도 앱 답변에서 내보내기를 사용할 수 있다.

## 내용과 권한

- 모델을 다시 호출하지 않는다. 서버의 messages 본문을 그대로 포장하므로 파일 만들기 때문에 내용이 재작성되지 않는다.
- 클라이언트가 보낸 본문을 문서로 만들지 않는다. 대화 소유권·현재 기관/앱 접근 권한·assistant 메시지 여부를 서버에서 확인한다.
- 화면 내용의 SHA-256과 DB 답변의 SHA-256이 다르면 409로 거절한다. 다른 창에서 추가 답변이 생겼을 때 현재 화면과 다른 결과를 내려받지 않는다.
- 단계 상태에 failed/pending/not_run 등이 있으면 파일 생성 차단. 중단된 작업을 완성된 문서로 표시하지 않는다.
- 검증된 표준 보고서 자산을 재사용해 제목·생성 시각·실행 설정 버전·본문·출처·확인 필요 안내를 넣는다. 관련 없는 빈 추진 경과/향후 계획/건의 사항 구역은 제거한다.
- 모든 파일에 AI 작성 초안 표시. 문서 없이 답한 사실·확인되지 않은 숫자·근거 검증 주의를 해당 기록이 있는 경우 포함한다. 자동 검토를 사람의 승인으로 표시하지 않는다.
- XML/패키지 구조·본문 보존·남은 양식 표시를 검사한 후 저장한다. 마크다운 표시 기호는 걷어내고(2026-10-31) 마크다운 표는 한글 표로 넣는다(2026-11-01, 아래 '표'). 그 밖의 레이아웃을 재해석하는 편집기는 아니다.

## 저장·다운로드

기존 generated_files 저장과 /api/files/[id]의 소유자 전용 60초 서명 다운로드 경로를 사용한다. 파일은 대화 삭제 시 함께 정리된다. 0044의 부분 고유 인덱스가 동일 사용자/답변 식별자/본문 해시에 대한 중복 생성을 막는다. 동시 요청이 충돌하면 기존 저장 도우미가 패한 업로드를 정리하고 API는 먼저 생성된 파일을 반환한다.

새 API는 /api/apps/export POST. 파일 이름·경로·기관·주인·양식은 서버가 정한다. source_references의 경고와 출처는 기존 답변 기록에서 가져오며 새로운 원문 자료를 조회하지 않는다.

- 로컬 타입 검사 통과.
- 대화 소유권·기관 변경·현재 앱 접근·본문 일치·중단 결과 차단·중복 재사용·동시 생성 충돌과 실제 HWPX 내용 보존 테스트 추가.

- 가상 대화/파일로 실제 Supabase 업로드 → 소유자 조회 → 서명 다운로드 → 원본과 SHA-256 일치 → HWPX 패키지 검사 통과.
- 다른 사용자 조회 거절과 동일 결과의 중복 삽입 거절 확인. 시험 대화·파일·저장 객체 삭제 확인.
- 실제 다운로드한 [가상 HWPX 결과](evidence/app-result-export.hwpx)를 증거로 보관한다.
- 로그인한 운영 화면의 버튼 클릭 및 한글에서 페이지 배치 확인은 미완료. 패키지 검사와 텍스트 읽기 결과를 시각 검증으로 간주하지 않는다.
- 기존 기능 회귀 83개 파일 1,659개 통과. 원격 운영 빌드/타입 검사 통과 후 dpl_2uFKtKyFSyqDEBfXFKP9JSxYah8F를 기존 주소로 promote했다. 운영 실행 화면 200 및 비로그인 내보내기 API POST 401 확인.

## 표 (2026-11-01)

답에 마크다운 표(머리 줄 바로 다음 줄이 `|---|---:|` 꼴의 구분 줄 — GFM 규칙)가 있으면 ` | `로 이은 글이 아니라 **진짜 한글 표**로 넣는다.

- 칸 글은 프로그램이 답에서 그대로 옮긴다(모델 호출 없음). 굵게·코드·링크 표시는 본문과 같이 걷어내고, 칸 안 `<br>`은 칸 안 새 문단, `\|`는 글자 `|`다. 행마다 칸 수가 달라도 칸을 버리지 않고 가장 많은 칸 수로 맞춘다(빈 칸).
- 구분 줄이 없는 세로줄 글은 표가 아니라 지금처럼 ` | `로 이은 글이다. 20열·500행을 넘는 표도 글로 넣는다(`MAX_HWPX_TABLE_COLS`·`MAX_HWPX_TABLE_ROWS`).
- 만드는 곳: `src/lib/apps/markdown-text.ts`의 `markdownToDocumentBlocks`(글·표 묶음) → `src/lib/doc-fill/hwpx-table.ts`의 `insertHwpxTables`. 채우기 엔진이 본문에 표지 문단(사용자 영역 글자 U+E000으로 감싼 `표N`)을 넣고, 그 문단을 표를 품은 문단으로 바꾼다. 표지를 하나라도 못 찾으면 파일을 만들지 않는다(표가 조용히 빠지지 않게).
- 서식: 실선 0.12mm 테두리, 머리 행은 옅은 바탕·굵은 글자(`header="1"`, 쪽이 넘어가면 머리 행 반복). header.xml의 테두리·글자 서식 목록 **끝에 더하고** `itemCnt`를 고친다 — 기존 번호는 그대로다. 열 폭은 칸 안 여백 + 가장 긴 줄 글 폭에 비례(합은 본문 폭). 줄 배치 캐시는 넣지 않고 한글이 다시 계산한다.
- 열 정렬(2026-11-01 추가): 구분 줄의 `:---`·`:---:`·`---:`를 왼쪽·가운데·오른쪽으로 머리 행과 본문 행 모두에 넣는다. 표지 문단의 문단 서식을 **정렬만 바꿔 복사**해 header.xml 문단 서식 목록 끝에 더한다(같은 서식·같은 정렬은 한 번만, `itemCnt` 고침). 지정 없는 열(`---`)은 본문 문단 서식 그대로(양식은 양쪽 정렬).
- 패키지 검사는 표 밖 글 줄과 모든 칸 글이 파일에 있는지 본다.
- 하지 않은 것: 칸 병합 없음. 운영 배포 전.

검증:

- 한글 2018(Hancom 10.0.0.11808)로 [표가 든 가상 결과](evidence/app-result-table.hwpx)를 `scripts/hancom-verify.ps1`로 열기 → 기대 글 9개 모두 있음 → 편집·다시 저장 → 다시 열기 → PDF 1쪽. 다시 저장한 파일을 다시 읽어도 표 두 개의 칸이 그대로였다. ## 기관 양식에 담기 (2026-11-08)

앱 비서에 올려 둔 기관 양식(비서 편집 창 '양식' 탭 — `agent_templates`, 지금 판에 쓰는 것) 중 **한글(HWPX)** 양식이 있으면 내보내기 칸에 '담을 양식' 고르기가 나온다(표준 보고서 / 기관 양식 · 이름). 마이그레이션 없음.

- **본문 자리는 표시로만 정한다**: 양식에 `{{주요 내용}}`·`{{본문}}`·`{{결과}}`·`{{내용}}` 중 하나(앞의 것부터)가 있어야 한다. 없으면 넣을 곳을 짐작하지 않고 422 `이 양식에는 결과를 넣을 {{주요 내용}}(또는 {{본문}}) 표시가 없습니다…`. 자동 자리 찾기(대화의 양식 채우기)는 쓰지 않는다 — 결과 전체를 엉뚱한 칸에 넣는 쪽이 더 나쁘다.
- `{{제목}}`은 `[AI 작성 초안] 앱 이름`, `{{작성일}}`은 `파일 생성: 시각`. **AI 초안 안내·확인 필요 안내**(문서 없이 답함·확인되지 않은 숫자·근거 검증)는 `{{개요}}`가 있으면 개요에, 없으면 **본문 맨 앞에** 둔다 — 어느 양식이든 빠지지 않는다. 출처 목록·마크다운 표 → 한글 표·패키지 검사는 표준 보고서와 같다(`composeAppResult` 한 곳).
- **그 밖의 표시(`{{수신}}`·`{{붙임}}` 등)는 빈 칸으로 두고** 응답의 `emptied`로 이름을 돌려준다. 화면은 '양식의 빈 칸으로 둔 항목: … — 한글에서 채워 주세요'. 양식의 다른 글·서식은 그대로다(표준 보고서의 빈 구역 지우기는 하지 않는다).
- 권한: 내보내기와 같은 검사(대화 주인·지금 앱을 쓸 수 있음) 뒤, 양식은 **이 대화 앱의 지금 양식**에서만 찾는다(다른 앱의 양식 id는 404). DOCX·HWP 양식은 목록에 안 나오고, 이름이 HWPX여도 바이트가 zip이 아니면 422. 양식을 못 받으면 503.
- 같은 답·같은 양식은 한 번만 만든다 — 캐시 열쇠가 `app-result:{메시지}:{해시}:{양식 id}`(0044의 부분 유일 색인이 그대로 막는다). 양식 행은 바뀌지 않고(교체는 새 행) id가 내용을 정한다. 캐시로 돌려준 파일에는 `emptied`가 없다.
- 목록은 `GET /api/apps/export?conversationId=` — 양식 id·이름만(저장소 경로 없음). 화면은 대화마다 한 번만 읽는다.

검증: `tests/app-result-template-export.test.ts`(공문 양식 — 본문·제목·안내가 본문 앞·빈 칸 이름, 보고서 양식 — 안내는 개요에 한 번, 표는 한글 표, 회의록(본문 표시 없음)·zip 아님 거절, 라우트 — 목록은 이 앱의 HWPX만·경로 없음·로그인/권한, 기관 양식 저장·캐시 열쇠·양식 이름, 표준 보고서는 그대로, 다른 앱 양식·없는 양식 404·DOCX 422·잘못된 id 400, 본문 표시 없음 422·양식 못 받음 503, 캐시 재사용 — 12개). 표준 공문 양식에 표가 든 가상 결과를 담아 한글 2018(Hancom 10.0.0.11808)로 `scripts/hancom-verify.ps1` — 열기·기대 글 6개 모두·편집·다시 저장·PDF 1쪽 통과, 쪽에서 제목 줄·본문 앞 안내·표(오른쪽·가운데 정렬)·빈 수신·붙임 확인([가상 결과](evidence/app-result-official-template.hwpx)). 로그인한 화면의 고르기·내려받기는 브라우저로 보지 않았다(개발 서버가 운영 DB를 씀). 2026-11-08 운영 배포(`dpl_CJiXcrNHWRm9LReriozmHQCVgk5L`).
