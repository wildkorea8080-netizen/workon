## 이번 조사에서 쓰는 구분

공개 데모에는 예시·가상 데이터가 포함된다. 공개 목록의 앱 100개, 최신 제품 페이지의 '100+' 표현, 계약한 계정에서 실제 사용할 수 있는 앱 수는 구분한다. 일본어 마켓의 앱이 한국 SaaS 계정에서 모두 동일하게 제공된다고 확인한 것은 아니다.

## 제품 방향

WORKON은 **ReadLayer를 공통 문서·근거 계층으로 사용하고, 기관이 역할·자료·양식·허용 도구를 구성한 업무 앱을 직원에게 제공하는 SaaS**로 발전시킨다. 앱은 저장한 수행 방식, 작업은 실행 한 건, 워크플로우는 처리 단계, 도구는 검증된 실행 기능이다.

기존 대화 비서와 업무 작업은 모두 유지·재사용한다. 앱을 100개씩 독립 프로그램으로 만드는 대신 문서 읽기·검색·요약·추출·비교·계산·파일 생성·검토·전달을 공통 기능으로 쌓고 이를 구성한다. 모든 앱을 단순 프롬프트로만 구현하는 접근도 피한다. 계산·권한·외부 쓰기·파일 형식은 각각 명시적인 계약과 검증이 필요하다.

SaaS부터 진행한다. 데스크톱, 온프레미스, 완전 폐쇄망은 조사 대상에는 포함하되 이번 구현 대상으로 늘리지 않는다. 내부 모델·배포 체계를 지금 임의로 추가하지 않는다.

## 근거의 한계

- 공식 제품·가이드·앱 상세·업데이트를 조사했다. 계정 생성·구매·영업 문의·외부 메시지 발송은 하지 않았다.
- 알리웍스의 인증된 앱 실행, 실제 고객 데이터 처리, 성능·보안 검증은 하지 않았다.
- 공식 사이트의 제품 설명도 시기·언어별로 차이가 있다. Works·Coworker·Desktop의 기능 경계와 계약별 제공 범위는 실제 도입 계정에서 추가 확인해야 한다.
- REA MCP 연결 후 별도 공개 브라우저에서 Works·Desktop·앱 목록을 관찰했다. 공개 UI 조작 결과와 제품 설명을 구분하며, 인증된 SaaS의 업무 실행은 미확인이다. 실제 근거는 REA_PUBLIC_WEB_ANALYSIS.md를 따른다.
- 기존 `docs/PLATFORM_PLAN_NODA_REA_2026-10.md`는 작성 당시 설계 이력이다. 그 안의 'REA는 SaaS 트래픽 관찰을 맡지 않는다', 기관 단위 NODA 테넌트 등의 문장을 현재 구현 사실로 그대로 사용하지 않는다. 현재 코드는 비서 단위 NODA 보관함과 공통 자료실을 사용한다.

공급자의 비공개 구현·디자인 자산·프롬프트를 복사하는 계획이 아니다. 공개된 기능과 사용자 동작을 참고해 WORKON에 독립 구현한다.
