# 업무 앱 인증·권한 경로 검증

2026-10-29. 운영 DB와 실제 사용자 계정은 변경하지 않았다.

## 구현 보완

- 비서 설정 로더에서 부서 조회 결과가 없을 때 SOURCE_UNAVAILABLE로 중단한다. 부서 조회 실패와 소속 소실을 구분 없이 허용하지 않는다.
- 기관 문서 제공자는 검색 부서의 실제 기관과 작업의 기관이 같은지 확인한 뒤 비서·문서를 조회한다.

## 실행한 검증

work-app-route-auth.test.ts는 실제 작업 POST 핸들러·getWorkActor·기본 설정 로더·createTask·canUseAgent를 호출한다. 세션 공급자·사용자 범위 조회·Supabase 응답·작업 저장소는 대체하고 작업 상세 DTO만 시험 응답으로 바꾼다.

비로그인 401, 대리 접근·비활성 사용자·소속 없음 403, 타 기관·타 소유자·비활성·부서 범위 밖·외부 링크·비공개 공식 비서 404, DB 오류·부서 소실 503을 확인했다. 요청 본문의 기관·소유자·가짜 설정은 저장되지 않고 서버가 가져온 지침·버전만 저장됨을 확인했다. 문서함 선택도 공개 공식 비서의 검색 능력 검사에 묶여 있다.

별도로 실제 loadTask 서비스에서 관리자의 비공유 작업 접근 거부와 viewer의 조회 허용·수정 거부를 확인했다. 비서 관리·사용 권한은 직원 작업 원문의 열람 권한을 자동 부여하지 않는다.

work-provider-scope.test.ts는 운영 기관 문서 제공자를 호출하고 DB·ReadLayer 응답만 대체한다. 선택 비서 하나로 문서 조회·검색을 제한하는지, 현재 공개·활성·기관·부서·검색 능력 조건에서 빠진 비서는 검색 호출 전에 차단하는지, 준비 문서가 없거나 DB가 실패하면 검색을 생략하는지, 다른 문서 ID의 근거는 거부하는지 확인했다.

관련 5개 파일 63개 통과 후 작업 원문 권한 2개를 추가해 인증 파일 17개를 재검증했다. 고유 사례 총 65개다. TypeScript·diff 공백 검사 통과.

## 아직 남은 범위

실제 로그인 브라우저·운영 Supabase·배포 환경에서 실행한 검증은 아니다. 기존 실제 ReadLayer·Claude 점검과 이번 서버 권한 검증은 서로 다른 시험이다. 운영 배포 전에는 정식 시험 계정으로 비서 선택·작업 생성·출처 열람·파일 다운로드를 한 흐름에서 확인해야 한다.
