모두 같은 시각이면 역할로 가른다(이력은 답 먼저 받아 뒤집고, 화면은 질문 먼저) — 운영에서 새 순서 확인(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 슈퍼관리자 계약 화면 요약 카드를 대시보드와 같은 규칙으로(`contractsSummary`) — '활성 계약'·'월 매출'이 상태가 활성인 계약을 모두 세고 더해 끝날 날이 지난 계약(상태를 자동으로 바꾸는 작업이 없음)·아직 시작 안 한 계약까지 들어갔고, 이번 달에 해지한 계약은 매출에서 빠져 대시보드 '이번달 매출'과 달랐다. 이제 활성 = 끝날 날이 지나지 않은 활성 계약, 매출 = 이번 달(한국 시간)에 유효했던 계약('이번 달 매출'), 쪽마다 끝까지 읽고 못 읽으면 503(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 사용 한도를 읽지 못해 '허용'으로 연 것을 알림 — 한도 판정이 부서·기관·계약·부서/개인 한도 읽기 오류를 보지 않아 기관 미연결·한도 없음과 같게 열었고(기관 정지 확인도 건너뜀) 어디에도 남지 않았으며, 관리자 '예산 소진 현황'은 그 '허용'을 사용 0·한도 없음으로 보였다. 이제 확인하지 못한 단계를 `unverified`로 돌려주고 운영 기록(error·payment)에 부서마다 10분에 한 번, 예산 화면은 503·안내(대화는 그대로 막지 않음). 예산 알림은 계약을 못 읽으면 보내지 않음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 슈퍼관리자 사용량 화면의 기관별 '한도 사용률'을 이번 달 토큰(한도 판정과 같은 셈)으로 — 고른 기간의 토큰 ÷ 월 한도라 '오늘'·'이번 주'는 낮게, 두 달에 걸친 직접 고른 기간은 높게 보였다(열 이름 '이번 달 한도 사용률'). 기관 목록을 못 읽으면 모든 기관이 '알 수 없음'·'한도 없음'으로, 실시간 카드는 읽기 실패를 '활성 0명·대화 0건'으로 보였던 것을 오류·안내로, 실시간 토큰은 숫자만(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 직원 '내 사용현황'의 토큰을 기록한 실제 사용량으로 — 대화 글자 수 ÷ 4 어림이라 실제의 몇 분의 일로 보였다(한글·시스템 프롬프트·참고 문서·도구 결과가 빠짐, 개인 월 한도 알림 메일이 이 화면으로 보냄). 이제 본인의 사용 기록(토큰을 쓴 모든 활동)으로 세고 비서별 토큰도 기록 기준, 메시지 글 전체를 읽던 두 조회를 없앰, 읽기 실패는 0건·0토큰 대신 503(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). '내 사용현황'에 이번 달 개인 한도(사용액 / 한도·%·한도에 닿으면 멈춤 안내) — 개인 한도 알림 메일의 단추가 이 화면인데 한도·사용액이 없어, 막힌 직원이 얼마를 썼는지 볼 곳이 없었다. 판정과 같은 규칙(개인 값 우선·부서 기본값), 한도가 없으면 안 보이고 못 읽으면 0원 대신 '확인하지 못함'. 부서 한도는 아직(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 관리자 대시보드·통계 화면의 첫 카드를 관리 범위로 — 자기 부서 한 곳만 세어 같은 화면의 사용량 추이·이용통계와 어긋났고 기관 전체 관리자의 첫 화면이 거의 0이었다. 지운 비서·나만의 비서·탈퇴/사용 중지 계정·지난 판 문서는 세지 않고, 토큰은 이번 달(한국 시간)만(예전엔 열 때마다 모든 사용 기록을 읽음), 읽기 실패는 0 대신 503. 옛 보고서 템플릿 수를 '생성된 보고서'로·늘 '정상'인 시스템 상태를 보이던 카드를 빼고, 최근 활동에 활동 코드가 그대로 나오던 것(AI 대화 등)을 이름으로. 사용량 추이도 읽기 실패는 빈 차트 대신 오류(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 관리자가 직원의 권한·부서·개인 월 한도를 바꾸면 보안 로그에(전후 값·그때의 부서 이름, 달라진 것만) — 예전에는 직원을 관리자로 올려도 어디에도 남지 않았다. 슈퍼관리자·탈퇴 계정은 대상에서 빼고 대리 접근 중 권한 변경은 막음. 감사 화면 '보안 이벤트'는 이름표 열쇠가 실제 사건 종류와 달라 금지어·개인정보 감지·업로드 차단·IP 차단이 코드 그대로 보이던 것을 고치고, 상세에 대상 이름(관리 범위 안만)·사유·전후 값을 보임(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 관리자 설정 화면 '보안 이벤트 로그'가 기록 원문을 통째로 펼치던 것을 막음 — 금지어 기록에 든 직원 질문 앞 100자가 사유 없이 보였다. 이제 사건 이름·심각도(한국어)와 상세 한 줄만, 범위는 관리 범위(예전엔 자기 부서만), 읽기 실패는 '없음' 대신 오류. 이름표는 감사 화면과 한 곳(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 관리자의 직원 초대·초대 취소를 보안 로그에(관리자 초대는 높음) — 예전에는 누군가를 관리자로 초대해도 남지 않았고 취소가 수락된 초대까지 지워 흔적이 사라졌다. 취소는 수락하지 않은 초대만, 대리 접근 중 관리자 초대는 막음, 가입·초대 여부 확인의 읽기 실패를 '없음'으로 보지 않음, 이메일 꼴 확인, 사용자 수 상한에 닿았으면 초대를 만들지 않음, 목록·취소는 관리 범위(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 비서 카테고리 바꾸기(추가·이름·순서·삭제)를 기관 전체 관리자만 — 이름 바꾸기·삭제는 그 이름을 쓰는 기관의 모든 비서를 함께 고치는데 하위 부서 관리자도 할 수 있었다(목록은 관리자 누구나, 화면은 단추를 숨김). 이름만 바뀌고 비서를 못 옮기면 이름을 되돌림(예전엔 '다시 시도'가 아무 일도 안 하고 성공해 비서가 미분류로 남음), 순서 저장이 카테고리를 못 읽으면 성공 대신 오류, 묶인 비서 수는 지운 비서·나만의 비서를 빼고 못 세면 0 대신 '확인 못 함', 부서·대상 읽기 실패는 '없음' 대신 503, 이름의 보이지 않는 글자 빼기(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 부서 삭제가 남은 것을 못 세면 '없음'으로 보고 지우던 것을 막음 — 부서를 지우면 DB가 그 부서의 대화·문서를 함께 지우고 직원·사용 기록·보안 로그의 부서 칸을 비우는데, 검사는 하위 부서·직원·비서 수만 봤고 조회 오류면 그대로 지웠으며, 직원·비서를 옮긴 '빈' 부서를 지우면 그 부서의 대화가 함께 지워졌다. 이제 못 세면 지우지 않고(503), 이 부서로 남은 기록(대화·사용 기록·보안 로그·접속 기록·문서·답변 평가·앱 예약/연동/일괄 실행·업무 작업·만든 파일·첨부, 탈퇴 처리된 계정·지운 비서·수락된 초대)이 있으면 지우지 않음(이름을 바꾸거나 옮겨 정리하라고 안내). 부서 목록의 직원·비서 수는 탈퇴 계정·지운 비서를 빼고 못 세면 '—'(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 부서 만들기·고치기·삭제를 보안 로그에 — 부서를 다른 부서 아래로 옮기거나(관리 범위가 바뀜) 부서 월 한도·1인당 월 한도를 바꿔도 어디에도 남지 않았다. 고치기는 실제로 달라진 것만 전후 값으로(상위 부서 바꾸기는 높음, 한도는 보통, 이름은 낮음), 감사 화면 상세에 대상 부서·상위 부서·한도를 읽을 말로(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). CSV 일괄 등록이 관리 범위를 보지 않던 것을 막음 — 기관 안의 아무 부서나 이름으로 찾아 넣어, 하위 부서 관리자가 기관 직속 부서 이름과 권한 ADMIN을 적으면 기관 전체 관리자 계정이 만들어졌다(상위 없는 새 부서도). 이제 관리 범위 안의 부서에만 등록하고 새 부서는 관리 범위 안에만 만든다. 관리자의 계정 만들기(바로 만들기·일괄 등록)를 보안 로그에(관리자 계정은 높음, 일괄 등록은 수만 한 줄, 이메일·임시 비밀번호 없음), 대리 접근 중에는 관리자 계정을 만들지 못함, 등록 여부·부서 읽기 실패를 '없음'으로 보지 않음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 정보를 저장하면 접속 허용 IP 칸이 비고 모델 목록이 사라지던 것 — 저장 응답에 그 칸들이 없었고 화면이 응답으로 상태를 통째로 바꿨다. **그대로 한 번 더 저장하면 접속 허용 IP가 지워졌다.** 저장 응답을 조회와 같은 칸으로, 화면은 응답을 앞 값에 합침. 접속 허용 IP 변경(전후 목록, 높음)·기관명·로그인 경로·AI 고지·테마 색·로고 변경을 보안 로그에(그 전에는 접속 허용 IP를 바꾸거나 없애도 남지 않았다), 모델 정책 이력은 실제로 달라졌을 때만(이름만 고쳐도 한 줄씩 쌓였다), 고치기 전 값을 못 읽으면 저장하지 않음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 비서 공식 등록 신청·반려를 변경 기록에 — 승인은 남았지만 반려는 어디에도 없었고 사유 칸은 다시 신청하면 덮였다(누가 언제 왜 반려했는지·어느 판을 신청했는지). 반려는 아직 승인 대기일 때만 — 예전에는 대기 상태를 본 뒤 다른 관리자가 승인하면 공식이 된 비서의 상태를 '반려'로 덮었다. 반려 응답은 필요한 칸만(예전엔 지시문까지 든 행 전체), 신청은 그 사이 지워졌으면 성공으로 답하지 않음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 업무 설정(업무 켜고 끄기·기관 양식 등록·시험 생성·확인 기록·사용 중지·대화 양식 가져오기)을 바꾸는 일을 기관 전체 관리자만 — 기관의 모든 직원에게 걸리는 설정인데 하위 부서 관리자도 바꿀 수 있었다. 보기는 관리자 누구나(화면은 단추를 막고 안내), 업무 현황은 관리 범위(자기 부서 + 하위)의 작업만 셈 — 예전엔 하위 부서 관리자에게도 기관 전체 수가 보였다(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 관리자가 사용자 목록의 부서 드롭다운으로 본인을 하위 부서로 옮기던 것을 막음 — 옮기는 순간 관리 범위가 줄어 스스로 되돌릴 수 없고, 기관 직속 관리자가 한 명뿐이면 기관 전체를 관리할 사람이 없어진다(화면도 본인 줄 표시·드롭다운 막음). 사용자 관리 목록에 '관리자로 지정/관리자 해제' 단추 — 권한 바꾸기 API는 있었지만 화면에 없어 직원을 관리자로 올리려면 새로 초대하거나 운영자에게 요청해야 했다(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포 — 새 단추가 든 화면은 브라우저로 확인하지 못함). '내 사용현황'에 이번 달 부서 한도(부서 전체 사용액 / 한도·%) — 부서 한도에 닿으면 그 부서 직원 전체가 멈추는데 직원이 얼마나 남았는지·얼마를 썼는지 볼 곳이 없었다. 판정과 같은 규칙, 부서 합계만(직원별 없음), 한도가 없으면 안 보이고 못 읽으면 '확인하지 못함'(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 대화 입력 필터: 금지어를 읽지 못하면 개인정보 패턴 검사(주민등록번호·카드번호)까지 함께 꺼지던 것을 고침(금지어 검사만 건너뛰고 운영 기록에 남김), 금지어·주민등록번호 사이에 보이지 않는 글자를 끼우면 검사에 안 걸리던 것·붙여 넣은 금지어에 딸려 온 글자 때문에 영영 안 걸리던 것을 고침, 금지어는 2~50자만(한 글자 금지어는 그 글자가 든 질문을 모두 막는다)·부서마다 300개(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). **대화에서 금지어·개인정보가 걸려도 보안 로그에 한 번도 남지 않던 것**(대화 준비가 필터에 사람 id를 넘기지 않았다 — 운영 보안 로그 0건)을 고침. 붙여 쓰거나 띄어 쓴 카드번호(16자리)·띄어 쓴 주민등록번호가 통과하던 것을 막음(카드번호는 검증식, 주민등록번호는 날짜 꼴로 한 번 더 봐 연도 넷·금액 둘 같은 업무 글은 통과), 같은 주민등록번호가 사건 둘로 남던 것을 하나로. 긴 숫자 규칙이 나라장터 공고번호를 막는 것·사업자등록번호 꼴을 막는 것은 그대로(결정 필요)(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 대화 공개 공유(로그인 없이 보는 링크): 링크가 대화의 '지금'을 보여 줘 **공유한 뒤 이어 쓴 대화까지 보이던 것**을 공유한 때까지의 대화만 보이게(이후 대화는 '공유 링크 복사'를 다시 눌러 갱신), 공유·중단을 보안 로그에(누가 언제 만들었는지 남지 않았다), 사용 중지·탈퇴한 계정이 만들어 둔 링크는 닫음, 공개 응답은 정해 둔 칸만. 기관이 공개 공유를 끄는 스위치는 아직 없음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). 기관 관리자가 관리 범위 직원이 공개 링크로 공유 중인 대화를 보고 멈춤(관리자 설정 화면) — 직원이 만든 공개 링크를 기관이 알 방법도 멈출 방법도 없었다. 누가·언제 공유했는지만 보이고(제목·내용·링크 주소 없음), 중단은 사유를 적어야 하며 보안 로그에 높음으로 남음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포 — 새 패널은 브라우저로 확인하지 못함). 비서 양식을 더할 때 지금 양식을 못 읽으면 **있던 양식이 모두 비서에서 빠지던 것**(새 양식 하나로 덮어씀)을 막음 — 못 읽으면 파일을 올리지도 저장하지도 않음, 양식 목록·빼기의 읽기 실패를 '없음' 대신 오류로. 나만의 비서 저장·앱 시험 판 저장·배포도 지금 값을 못 읽으면 저장하지 않음(2026-11-18, 마이그레이션 없음, 2026-11-18 운영 배포). CSV 내보내기의 수식 주입 막기 — 감사 기록·이용통계·직원 일괄 등록 결과·슈퍼관리자 로그 CSV가 '='로 시작하는 이름(직원·비서·올린 CSV의 이름)을 엑셀에서 수식으로 실행되게 두던 것을 한 곳(`csv-cell.ts`)으로 막음, 직원 등록 결과에서 쉼표가 든 이름이 칸을 밀던 것도 고침(2026-11-18, 마이그레이션 없음, 2026-11-19 운영 배포). **이어지는 대화의 이력을 못 읽으면 앞 대화 없이 답하던 것**을 막음 — 빈 이력으로 보아 이어지는 질문이 앞 대화 없이 모델에 가서 엉뚱한 답이 오류 없이 나갔다(화면에는 앞 턴이 보여 직원은 알 수 없다). 이제 답하지 않고 잠시 뒤 다시 보내라고 안내. 대화 준비의 비서·대화 읽기 실패, 일괄 실행 보기·결과 엑셀·그만두기·다시 실행의 읽기 실패도 '없음'·빈 표 대신 오류로(2026-11-18, 마이그레이션 없음, 2026-11-19 운영 배포). **대화 이름 바꾸기·지우기가 실패해도 화면에서는 된 것처럼 보이던 것**을 고침 — 사이드바가 응답을 보지 않아 실패한 이름 바꾸기가 화면에만 남고 실패한 지우기도 목록에서 사라졌다(다시 열면 그대로). 이름은 1~100자로 다듬어 받고(줄바꿈·보이지 않는 글자 뺌), 없는 대화는 404, 대화 열기·지우기 전 확인의 읽기 실패는 '찾을 수 없음' 대신 오류로(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). **슈퍼관리자 기관 상세의 '계약 수정 / 새 계약'이 계약을 만들지 않던 것**을 고침 — 시작일·종료일·이용료를 받고도 기관의 요금제 이름만 바꾸고 '계약이 업데이트됐습니다'라고 알렸다(계약·한도 그대로). 이제 계약 화면과 같은 계약 만들기로 보내고, 계약 만들기는 표 밖 요금제(예전엔 체험 한도로 조용히 저장)·틀린 이용료·날짜를 지금 계약을 끝내기 전에 거절한다(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). **슈퍼관리자 추가가 이미 있는 계정을 덮어쓰던 것**을 고침 — 등록 여부를 못 읽으면 '없음'으로 보고 같은 이메일의 로그인 계정 비밀번호를 바꾼 뒤 직원 행을 슈퍼관리자로 덮어쓸 수 있었다. 이제 못 읽으면 만들지 않고, 행은 새로만 넣으며, 실패하면 이번에 만든 로그인 계정을 지운다. 로그인 계정 찾기는 첫 1,000명이 아니라 끝까지(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). **슈퍼관리자가 0명이 될 수 있던 것**을 막음 — 두 슈퍼관리자가 거의 동시에 서로를 끄면 둘 다 통과해 사용 중인 슈퍼관리자가 없어지고(첫 설정은 슈퍼관리자가 있으면 막혀 DB를 고치지 않고는 못 들어옴), 직원 계정 화면의 API는 슈퍼관리자 계정도 받아 본인·마지막 슈퍼관리자를 끌 수 있었다. 이제 끈 뒤 다시 세어 0명이면 되돌리고, 직원 API는 슈퍼관리자 계정을 받지 않으며, 계정·수를 못 읽으면 바꾸지 않는다(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). 슈퍼관리자 기관 상세의 사용자·초대 링크·API 키 탭과 시스템 API 키 화면이 **읽기 실패를 '없음'으로** 보이던 것(부서를 못 읽으면 '사용자가 없습니다', 키를 못 읽으면 '시스템 키 사용'·'(미설정)')을 503·실패 안내로, 풀지 못하는 암호문은 500 대신 '(풀지 못함)', 업무 화면 설정은 기관을 못 읽으면 404 대신 503·저장 오류는 한국어 500, API 키 탭의 '보관 안 함'은 응답을 보고 알림(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). **계약 갱신·해지**(`PATCH /api/super/contracts/[id]`)도 입력을 먼저 본다 — 예전엔 표 밖 요금제를 체험 한도로 기관에 넣고, 틀린 날짜·1억 원 넘는 이용료·소수 경고 비율은 500, 이미 끝난 계약을 다시 해지해도 기관을 정지, 끝난 옛 계약의 요금제를 고쳐도 기관 한도를 덮었으며, 갱신 창은 메모를 비워 두면 있던 메모를 하루 끝까지)·표 밖 중요도와 기관 없는 '특정 기관' 공지(직원에게 영영 안 보임)·발행된 공지를 고칠 때마다 맨 위로 올라오던 것·없는 공지 500을 고침(2026-11-19, 마이그레이션 없음, 2026-11-19 운영 배포). 직원·기관 관리자 API 응답에 DB·Auth 오류 원문을 싣지 않음 — 대화·문서 라우트의 `details: ## 이번 구현: 앱 즐겨찾기와 업무 분야 탐색

공식 가이드의 카테고리·즐겨찾기를 참고했다. 기존 AI 비서 즐겨찾기는 있었으나 새 통합 앱 목록과 문서 업무에는 연결되지 않았으므로 이 부분을 보완했다.

- 홈과 앱 라이브러리에 별 버튼·즐겨찾기 필터·업무 분야 필터·필터 초기화 추가.
- 계정별 서버 저장. 비서 즐겨찾기는 기존 favorite_agent_ids를 그대로 사용하므로 기존 대화 화면과 공유한다.
- 문서 업무 즐겨찾기는 users.favorite_workflow_keys에 별도 저장. 마이그레이션 0042.
- 저장 함수는 사용자 행 잠금과 원하는 상태 설정을 사용해 중복 등록과 새 API 내 동시 저장 덮어쓰기를 방지한다. 함수 실행 권한은 service_role에만 부여한다.
- API에서 사용자 ID를 세션에서 결정하고 기관 소속·비서 접근 권한·업무 키를 검증한다. 즐겨찾기는 실행 권한을 부여하지 않는다.
- 사용 불가/삭제된 앱은 현재 권한으로 받은 앱 목록과 교차하므로 즐겨찾기를 통해 다시 노출하지 않는다. 저장 실패는 알리고 완료로 표시하지 않는다.
