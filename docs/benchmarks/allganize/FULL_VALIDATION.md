# 업무 앱 15종 — 전체 회귀·빌드·결과 재사용 검증

2026-10-29. 이번 단계는 신규 앱 추가가 아니라 현재 변경 전체의 정합성 검증이다. 운영 DB와 배포 환경은 변경하지 않았다.

## 전체 검사

분리된 로컬 PostgreSQL의 WORK_TEST_DATABASE_URL을 설정하고 전체 Vitest를 실행했다. **114개 테스트 파일·2,076개 테스트 통과, 생략 0개**. 전용 DB는 마이그레이션 41개를 적용한 시험 DB다. 실제 업무·DB·파일 생성 통합 사례도 실행됐다. 외부 모델·검색 응답은 해당 자동 테스트의 시험 응답이며, 기존 실제 모델 점검과는 별개의 검증이다.

최초 실행에서 기존 보안·모델 경계·사용 한도 검사 3개가 Unix find 명령 의존성으로 Windows에서 시작하지 못했다. Node 파일 탐색 공통 도우미로 교체했고, 검사 조건과 실제 파일 수집 여부 검증은 유지했다. 고친 뒤 해당 20개 사례와 전체 검사를 통과했다.

프로덕션 Next.js 빌드도 종료 코드 0으로 통과했다. 기존 일부 동적 API가 정적 생성 시도 중 출력하는 진단과 Browserslist 데이터 경고는 남아 있으나 빌드 실패는 없었다. 이를 운영 동작의 무오류 보증으로 해석하지 않는다.

## 업무 사이의 결과 재사용

새 통합 사례에서 문서 요약 생성 → 검토 승인 → 요약 HWPX를 번역 작업의 원자료로 복사 → 원자료 읽기 → 후속 HWPX 생성을 확인했다.

- 원래 작업 ID·문서 판 ID·파일 ID와 SHA-256을 원자료 출처에 보존.
- 복사된 바이트의 해시가 원래 결과 파일 기록과 일치.
- 같은 결과 파일을 다시 가져와도 원자료 중복이 없음.
- 가져온 자료로 다음 작업이 ready가 되고 후속 translation HWPX가 valid로 생성됨.

이 사례의 생성기는 가짜다. 실제 번역 품질이 아니라 서비스·DB·권한·원자료 복사·실행기·파일 생성 연결을 검증했다. 승인 단계까지 추가한 최종 업무 흐름 파일 27개 테스트와 TypeScript도 다시 통과했다.
