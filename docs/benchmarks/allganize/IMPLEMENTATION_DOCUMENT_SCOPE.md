# 규정 확인 — 선택한 공식 비서 문서함 연결

2026-10-29. 알리웍스 공개 페이지의 앱별 문서 소스 설정 개념을 WORKON의 기존 규정 검색에 적용했다. 경쟁사 내부 구현을 재현한 것이 아니다.

## 동작

규정·지침 확인 작업에서 문서 검색 능력이 설정된 공개 공식 비서를 선택하면, 기관 문서 검색을 그 비서의 문서함 하나로 제한하는 옵션을 제공한다. 기본값은 기존 검색 범위다. 공통 기준·법령·직접 첨부 자료는 계속 함께 확인한다.

서버는 작업 생성 시 비서 사용 권한과 문서 검색 자격을 확인하고 선택 범위를 app_snapshot에 저장한다. 기관 문서를 실제 검색할 때는 현재 기관·공개 상태·활성 상태·부서 범위·검색 능력으로 허용된 공식 비서 목록 안에서 선택한 비서 하나만 사용한다. 목록에서 빠졌거나 준비된 문서가 없거나 검색 설정이 없거나 반환 근거와 문서 행이 맞지 않으면 SOURCE_UNAVAILABLE로 실패한다. 다른 비서의 문서함으로 검색 범위를 넓히지 않는다. 기존 실행기의 재시도·체크포인트 규칙은 유지하므로 이미 보존된 근거는 해당 실행의 체크포인트로 재사용될 수 있다.

원문 위치와 근거 번호는 기존 ReadLayer/NODA 매칭·검토 메모 경로를 사용한다. 문서 원본의 특정 버전을 작업 생성 시 동결하는 기능은 아니다. 실제 검색 당시 수집한 근거는 기존 실행 체크포인트에 저장한다.

## 범위

이번 연결은 규정 확인의 공개 공식 비서 문서함만 지원한다. 개인·부서 비서의 문서함과 보고서·회신의 직접 검색 연결은 후속이다. 임의의 문서함 ID·프롬프트·클라이언트 자격 플래그를 받아 권한을 부여하지 않는다.

추가 DB 칸은 만들지 않고 앞서 준비한 0036의 스냅샷에 선택 범위를 보관한다. 따라서 0036 적용과 배포가 먼저 필요하다. 운영 DB에는 아직 적용하지 않았다.

## 검증

관련 3개 테스트 파일 36개 통과. 선택 범위 제한·허용 목록에서 빠진 경우의 거부·첨부/공통/법령 유지·생성 시 자격 거부·스냅샷 저장을 검증했다. TypeScript와 diff 공백 검사 통과. 실제 ReadLayer 호출·운영 DB·로그인 UI·최종 HWPX 다운로드는 이번 단위 검증 범위에 포함하지 않았다.
