# 업무 앱 설정과 실행 연결 — 1차

2026-10-28. SaaS의 기존 업무 실행기에 비서 작성 설정을 연결했다. 운영 DB 적용·배포 전이다.

## 사용 흐름

작업 생성 화면에서 작성 비서를 선택하면 서버가 canUseAgent로 기관·소유자·부서·활성 상태·공개 범위를 검사한다. 외부 링크 비서는 연결할 수 없다. 한 번의 agents 조회에서 지침·모델·버전을 읽어 작업의 app_snapshot과 agent_id에 함께 저장한다. 클라이언트가 보낸 지침이나 버전은 받지 않는다.

작업실은 비서 이름과 설정 버전을 보여준다. 원래 비서가 바뀌어도 기존 작업은 고정한 지침을 사용한다. 모델 호출마다 요청 모델을 현재 기관 정책에 다시 통과시키므로 정책에서 제외된 모델을 강제로 고정하지 않는다. 실제 사용 모델·토큰은 기존 사용량 기록에 남는다. task.created 이벤트에는 비서 ID·버전을 기록하며 지침 원문은 넣지 않는다.

양식 채우기, 규정 계획·검토, 항목 추출, 질문별 회신, 기존 문서 현행화의 모델 호출에 작성 지침을 전달한다. 기존 출력 형식·근거 번호·필드 검증은 유지한다. 취합·정산은 결정적 계산을 하므로 비서 선택을 제공하지 않고 서버에서도 거부한다.

## 저장과 권한

- 0036_work_app_snapshot.sql: nullable JSONB 칸과 최소 형태·agent_id 일치 제약.
- 기존 작업의 스냅샷은 null이며 기본 실행을 유지한다.
- agents 외래키의 기존 ON DELETE SET NULL을 유지한다. 원본이 삭제되어도 당시 스냅샷은 보관한다.
- 작업 응답은 이름·버전·캡처 시각만 반환한다. 지침과 요청 모델 원문은 DTO에 노출하지 않는다.
- 비서 사용 권한과 작업 접근 권한은 별개다. 저장된 작성 지침은 작업의 실행 설정이며, 원본 비서의 도구·문서에 대한 접근 권한을 유지해 주지 않는다.
