# 문서 찾기 일괄 평가 (2026-11-04)

기관이 '질문 · 기대 문서 · 기대 쪽' 세트를 만들어 두면, 비서의 문서 찾기가 맞는 문서를 찾는지 한 번에 재고 실행마다 기록해 비교한다.

- 지금까지는 관리자 문서 화면의 단건 검색 시험(`/api/rag-test`)만 있었다.
- 그래서 문서를 바꾸거나 비서를 고친 뒤 '전보다 나빠졌는지'를 잴 방법이 없었다.
- 알리웍스의 '리트리버 최적화'도 사람이 올린 데이터셋(질문·파일명·쪽)으로 한다. 다만 그쪽은 담당 PM이 수작업으로 맞추는 서비스다([REA 재분석](REA_PUBLIC_WEB_ANALYSIS_2026-10-31.md)).
- 우리는 사람이 세트를 만들고, 재는 일은 프로그램이 한다.

## 무엇을 재나

**검색만** 잰다. AI 답변은 만들지 않으므로 모델 사용량이 없다. 찾기는 대화와 **똑같다**(`searchLikeChat` — 대화의 preflight → prepare를 그대로 태운다, 2026-11-05).

- NODA `/context`, 유사도 하한 0.80
- 이 비서의 문서 행과 맞춘 근거만
- 섞임·고아 처리도 대화와 같다

- **공통 자료실도 찾는다**(2026-11-05). 기관 유형의 공통 보관함을 대화처럼 함께 찾고(예산 비서 3000 + 공통 2000), 공통 번호를 민다. 판·시행일 규칙도 같다.
  - 그 전에는 비서 보관함만 찾아 '대화와 같은 규칙'이 다 맞지는 않았다. 공통 자료가 있는 기관에서는 예산이 4000에서 3000으로 줄고 공통 근거가 더해지므로 결과가 달라질 수 있다.
  - 공통 문서는 기대 문서로 적을 수 있고(이름 일부), 상위 문서에 `[공통] 이름`으로 보인다. 요약에 '공통 자료 근거 N개 질문'이 붙는다.
  - 실행 요약에 찾은 범위(`searchScope: 'chat'`)를 남긴다. 칸이 없는 옛 기록은 '비서 문서만 찾음'으로 보이고, 범위가 다른 두 실행을 비교하면 '차이가 공통 자료 때문일 수 있습니다'를 붙인다.
  - 대화에서 503으로 거절할 경우(공통 자료실만 실패해도)는 그 질문을 '찾기 실패'로 둔다.
  - 대화처럼 고아 사본 지우기·섭임 기록이 일어날 수 있다.
- 단건 검색 시험(`/api/rag-test`)은 여전히 비서 보관함만 찾는다.

| 판정 | 뜻 |
| --- | --- |
| 찾음 | 기대 문서가 근거에 있다(순위 = 처음 나온 자리) |
| 다른 문서만 | 근거는 왔지만 기대 문서가 없다 |
| 근거 없음 | 기대 문서가 있는 질문인데 근거가 하나도 없다(하한에 다 걸림) |
| 걸러짐(맞음) | 기대 문서를 비운 '엉뚱한 질문'에 근거가 없다 |
| 엉뚱한 근거 | 엉뚱한 질문에 근거가 붙었다 |
| 찾기 실패 | NODA를 부르지 못했다(그 질문만, 비율에서 뺀다) |

요약에 내는 값은 다섯이다.

- 찾음 비율(기대 문서 있는 질문 중)
- 쪽 맞음 비율(기대 쪽을 준 질문 중, 기대 문서의 조각에 그 쪽이 있나)
- 평균 역순위(MRR — 못 찾으면 0, 1이면 늘 첫 근거)
- 엉뚱한 질문 걸러짐 비율
- 찾기 실패 수

문서 이름은 확장자·공백·대소문자를 무시하고 비교한다. 기대 문서는 이름의 **일부만** 적어도 된다(`여비` → `공무원 여비 규정(2026).pdf`).

## 세트

엑셀에서 세 칸을 복사해 붙이거나(탭) CSV(쉼표)로 적는다. 첫 줄의 첫 칸이 '질문'이면 머리글로 보고 건너뛴다.

```
질문	기대 문서	기대 쪽
출장 일비는 하루 얼마인가요?	여비 규정	12
점심 메뉴 추천해 줘
```

- 한 번에 50개까지다. 질문은 500자, 기대 문서는 120자 이내로 적는다.
- 기대 쪽은 `12`·`p.12`·`12쪽` 꼴로 적는다. 쪽만 적고 문서를 비우면 거절한다.
- 잘못된 줄은 줄 번호와 함께 모두 알린다(최대 20개). 빈 줄은 건너뛰되 줄 번호는 밀리지 않는다.
- 보이지 않는 글자(서식 글자·제어 문자)는 다듬는다.

## 기록과 비교

- 실행마다 `rag_eval_runs`(0054)에 남긴다.
  - 남기는 것: 기관·비서·그때의 비서 판·실행한 사람·질문 수·상태(`done` / 일부 찾기 실패면 `partial`)·요약·질문별 결과.
  - 질문별 결과: 질문, 기대값, 판정, 순위, 쪽 맞음, 근거 수, 최고 유사도, 상위 문서 이름 3개. **근거 원문은 남기지 않는다.**
- 지난 실행 목록(20개)에서 하나를 골라 '지금 결과와 비교'하면, 같은 질문끼리 좋아짐·나빠짐을 보인다. 찾기 실패는 비교하지 않는다.
- **세트 다시 쓰기**(2026-11-05): 지난 평가마다 '이 세트 다시 쓰기'를 누르면 그 실행의 질문·기대 문서·기대 쪽이 세트 칸에 다시 채워진다(`ragEvalSetText` — 다시 읽으면 같은 세트). 세트를 따로 저장하지 않고 실행 기록이 세트를 품는다(마이그레이션 없음).
- 결과는 CSV로 내려받는다. BOM을 붙이고, 수식으로 읽힐 칸에는 앞에 `'`를 붙인다.

## 권한·한도

- 기관 관리자만 쓴다(`isAdminSession`). 비서는 요청자 기관이어야 하고, **공식 비서이거나 요청자가 관리하는 부서의 비서**여야 한다. 아니면 없는 것처럼 404다. 기록 하나를 열 때도 그 비서를 지금 볼 수 있어야 한다.
- 질문 50개를 3개씩 동시에 찾는다. 시간 예산은 240초이고, 남은 질문은 찾기 실패로 둔다(`maxDuration` 300).
- 한 질문의 NODA 실패는 그 질문만 '찾기 실패'다. **모두 실패하면 저장하지 않고** 503을 돌려주고, 운영 기록에 경고를 남긴다.

## 화면

관리자 '문서 관리' 화면의 검색 시험 아래 '문서 찾기 일괄 평가'(`RagEvalPanel`)에서 한다.

1. 비서를 고르고 세트를 붙여 넣는다. 질문 수 미리보기와 줄 오류가 화면에서 먼저 보인다.
2. 평가를 실행한다. 요약 한 줄과 질문별 표가 나온다.
3. 결과를 CSV로 내려받거나, 지난 평가와 비교한다.

## 남은 것

- 답변 품질(근거를 제대로 옮겼나)은 재지 않는다. 그것은 모델 비용이 든다.
- 세트에 이름을 붙여 따로 보관하는 칸은 없다(지난 실행에서 다시 쓴다). 비서를 바꾸면 그 비서의 지난 평가만 보인다.
- 단건 검색 시험은 공통 자료실을 찾지 않는다.
- 화면은 브라우저로 보지 않았다.
