# 알리웍스 플랫폼·서비스 상세 분석

조사일: 2026-10-28. 상태 표시는 [README](README.md)의 정의를 따른다. 아래 A 번호는 이 문서의 출처 식별자이며 REA Evidence ID가 아니다.

## 1. 제품군과 WORKON의 대응

| 제품·서비스 | 공식 설명에서 확인한 역할 | WORKON 대응 | 판단 |
|---|---|---|---|
| Alli Works | 앱 목록·검색·대화, 업무 앱 구성·공유·운영 | 직원 포털·비서·업무 실행 | SaaS 주 벤치마크 |
| App Market / 앱 라이브러리 | 준비된 업무 앱 선택·추가·팀 배포 | 비서 프리셋·정적 업무 10종·새 통합 앱 목록 | 공통 앱 정의와 설치 흐름 보완 |
| App / Agent Builder | 지시·문서·응답 형식·처리 단계 구성 | AgentEditorModal·능력 레지스트리·고정 워크플로우 | 기존 비서 설정에서 확장 |
| Documents 2.0 | 문서 분류·필터·판 비교·관계·검색 | ReadLayer + documents/common_documents | 검색 엔진 위에 문서 관리 기능 필요 |
| Answer / 기업 검색 | 내부 문서·DB에서 근거 기반 답변 | ReadLayer /context·출처 패널·/verify | 기본 경로 있음, 원문 위치 연결·평가 보완 |
| Deep Research | 내부·웹 조사, 공백 확인·재탐색·인용 리포트 | regulations·외부 공공 커넥터·보고서 엔진 | 웹 조사·계획·재탐색 일반화 신규 |
| BI Agent | 자연어 기반 데이터 분석·리포트 | 표 계산·취합·정산·XLSX | DB 읽기 권한·질의 검증 신규 |
| AX Report | 사용 데이터에서 도입 효과·ROI 월간 분석 | usage_logs·통계·업무 현황 | 채택·재작업·실측 시간 기록부터 필요 |
| Alli Coworker | 자연어 앱·에이전트 작성, 시스템 연결·실행 | 향후 설정 도우미·승인된 커넥터 | Works와 겹치는 부분이 있어 실제 경계는 확인 필요 |
| Desktop | 웹 자산 재사용 + 로컬 파일·코드 실행·예약 | 향후 PC 클라이언트 | 현재 이연 |
| SaaS / On-prem / Hybrid | 같은 플랫폼의 배포 선택 | SaaS 우선 | 온프레미스·폐쇄망 이연 |
| API / SDK / MCP | 기존 화면·외부 시스템에 검색·앱 제공 | 기존 업무 API·ReadLayer HTTP | 플랫폼 공개 API·토큰 범위 신규 |

근거: A01~A09. Works·Coworker 경계는 공급자 사이트의 설명이 페이지별로 달라 딱 잘라 '비서 대 앱'으로 구분하지 않는다. 동일한 역할·자료·도구 구성은 두 제품 모두 존재할 수 있다.

## 2. 직원이 사용하는 기능

| ID | 문서 확인한 기능 | 직원에게 주는 효과 | WORKON 코드 기준 | 우리 구현 방향 |
|---|---|---|---|---|
| U01 | 하나의 입력창과 앱 목록 | 일반 요청과 전문 업무를 쉽게 시작 | ChatHome·AgentSelector, 별도 /assistants | /apps로 찾는 입구 통합, 실행 방식은 유지 |
| U02 | 카테고리·즐겨찾기·전체 앱 보기 | 자주 쓰는 앱을 다시 찾음 | 비서 카테고리·즐겨찾기 있음 | 업무 앱에도 동일한 탐색 언어 적용 |
| U03 | 앱 사용 설명·예시 질문 | 무엇을 입력할지 알 수 있음 | usage_guide·starter_prompts 있음 | 필요한 자료·예상 결과·제한을 함께 표시 |
| U04 | 프로젝트 이동·대화 이력 | 기관·팀 업무 맥락 복귀 | 기관/부서·대화 이력 있음 | 별도 프로젝트 계층을 바로 만들지 않음 |
| U05 | 특정 앱으로 새 대화 | 같은 역할로 반복 요청 | 화면에서 비서 선택 가능 | 앱 딥링크 추가, URL 진입만으로 모델 호출 금지 |
| U06 | 개인·공유 문서함 | 자료를 반복 첨부하지 않음 | 비서 참고 문서·채팅 첨부·작업 원자료 분리 | 권한을 유지하며 선택·가져오기 동선 정리 |
| U07 | 문서·폴더 선택 후 질의 | 조사 범위를 사용자가 이해·제한 | 서버가 비서·공통 범위 결정 | 서버 검증된 문서 선택만, 클라이언트 tenant 금지 |
| U08 | 진행 과정 표시·취소 | 실행 중 무엇을 하는지 확인 | SSE tool_start/end·work run·취소 있음 | 공통 실행 상태 표현, 내부 추론 공개와 구분 |
| U09 | 답변 근거 미리보기·하이라이트 | 근거 확인 시간 단축 | 출처 글·쪽·절 패널 있음 | 원본 문서의 같은 위치에 연결하는 화면 보완 |
| U10 | 결과 복사·다운로드·추가 질문 | 결과물을 후속 업무에 사용 | 대화 생성 파일·업무 산출물·가져오기 있음 | 파일 권한과 저장 수명 분리 유지 |

근거: A01, A02, A03. 앱 카탈로그가 있다고 모든 앱이 자동 실행·외부 시스템 쓰기를 하는 것은 아니다.

| B04 | 문서 소스·폴더 지정 | 비서 문서 연결 있음 | 문서 선택 시점·실행 시점 재권한 확인 |

## 4. 문서·RAG·검색을 위한 기능

| ID | 문서 확인한 항목 | ReadLayer와 WORKON의 분담 | 차이·우선순위 |
|---|---|---|---|
| R01 | 다양한 문서 형식·OCR | ReadLayer 문서 읽기·구조·표·근거, WORKON 업로드·권한 | 기존 경로 유지, 기관 파일로 점검 |
| R02 | 개인/공유 자료·폴더 구조 | WORKON 자료 소유권·분류, ReadLayer 검색 | 기관 자료실의 중복·배포 규칙 설계 |
| R03 | 문서 유형·키워드 자동 분류 | ReadLayer 추출 정보 + 별도 분류 정책 | 메타데이터 초안·사람 수정·검색 필터 신규 |
| R04 | 자연어 조건을 메타데이터 필터로 변환 | 모델이 필터 후보, 서버가 허용 키·값 검증 | 검색 전 권한·조건 결합 필수 |
| R05 | 문서 버전 묶기·최신 판 선택·차이 확인 | 공통 자료실 판 교체는 있음 | 일반 기관 문서 개정·효력일 모델 신규 |
| R06 | 문서 간 참조·보완 관계 | 근거 목록·문서 식별자 유지 | 자동 연결은 제안 수준부터, 확정 관계와 분리 |
| R07 | 표·이미지 등 복합 문서 검색 | ReadLayer 지원·품질 범위 확인 필요 | 사이트의 성능을 우리 성능으로 옮기지 않음 |
| R08 | 원본 레이아웃의 근거 하이라이트 | ReadLayer anchors/view 활용 후보 | 현재 SourcePanel은 발췌 텍스트, 같은 기능으로 표시 금지 |
| R09 | 답변 검증·재검색 | /verify는 현재 감사 기록, 로컬 숫자 확인 별도 | 검증 실패→재검색→재작성은 신규 정책·횟수·비용 상한 필요 |
| R10 | RAG 평가·질문/정답·근거 묶음 | 엔진 평가 + WORKON 기관별 답변 평가 | 단건 rag-test에서 배치·회귀 기록으로 확장 |
| R11 | 연결 원본 권한·메타데이터 유지 | 미래 커넥터가 원본 ACL을 매핑 | 새 커넥터의 필수 완료 조건 |
| R12 | 수정·삭제·동기화 | NODA webhook+events 조정 있음 | 외부 저장소 원본과 양쪽 삭제·실패 재처리 신규 |

근거: A02, A03, A05, A08. ReadLayer가 이미 제공하는 함수가 있더라도 현재 WORKON이 소비하는 필드·권한·화면까지 연결됐는지 따로 검증해야 한다.

## 7. 소스 경로

현재 코드에서 확인한 재사용 지점:

- 비서: `src/lib/agent-catalog.ts`, `agent-form.ts`, `agent-store.ts`, `agent-permissions.ts`, `src/components/agents/AgentEditorModal.tsx`.
- 도구: `src/lib/capabilities/settings.ts`, `index.ts`, `document.ts`, `table-merge.ts`.
- RAG: `src/lib/noda.ts`, `src/lib/capabilities/doc-search.ts`, `src/lib/assistant/stream.ts`, `src/components/chat/SourcePanel.tsx`.
- 업무: `src/lib/work/types.ts`, `services.ts`, `workflows/index.ts`, `runs/executor.ts`, `runs/worker.ts`, `documents/renderer.ts`.

핵심 간극: `work_tasks.agent_id` 칸은 있으나 작업 생성이 비서 설정·판·프롬프트·모델을 묶어 실행하지 않는다. 링크 하나를 추가하는 것만으로 '구성 가능한 업무 앱'을 구현했다고 말할 수 없다.
