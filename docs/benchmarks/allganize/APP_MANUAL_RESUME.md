# 중단된 텍스트 앱의 수동 재개

2026-10-31. 단계형 앱이 중단됐고 완료된 중간 단계가 있는 경우, **완료된 단계부터 이어서 실행**을 추가했다. 새 실행으로 기록하면서 앞 단계의 저장된 작업 결과를 재사용하고 남은 단계만 호출한다.

## 사용 흐름

- 앱 실행 화면에서 실패 기록이 정상 저장되면 재개 버튼을 제공한다.
- 대화 기록의 중단된 앱 답변에서도 같은 버튼으로 원래 입력을 불러올 수 있다. 페이지를 여는 것만으로 모델을 호출하지 않는다.
- 입력을 변경하면 재개 버튼을 비활성화한다. 변경 입력은 새 실행으로 처리한다.
- 재사용한 단계는 ‘이전 결과 재사용’으로 표시한다. 완료 단계의 생성 호출은 반복하지 않으며, 남은 호출의 입력에 포함된 텍스트 토큰은 정상 과금 대상이다.

## 허용 조건

1. 현재 사용자가 소유한 대화의 assistant 실패 기록이어야 한다. 현재 앱 접근 권한과 기록의 앱 ID도 확인한다.
2. 저장된 실행 버전이 현재 앱 버전과 같아야 한다.
3. 원래 정규화 입력과 새 입력이 같아야 한다. 서버가 저장한 결과만 사용하며 요청의 임의 중간 결과는 무시한다.
4. 단계 이름·개수·상태 순서가 같고 실패 전 완료 결과만 재사용한다. 완료 결과 길이·선택 조건의 일관성도 확인한다.
5. 결과가 입력 글에만 기대는 실행만 지원한다 — 켜진 능력이 첨부 읽기(`file_read`·`table_merge`)뿐이고 **그 실행에 파일이 없을 때**(`src/lib/apps/resume.ts` `isInputOnlyRun`, 입력 저장과 재개 허용이 같은 규칙). 문서 찾기·공공 데이터 등 다른 능력이 켜진 앱, 파일을 붙인 실행, 재개 요청에 파일을 붙인 경우는 외부 근거 변경을 안전하게 확인할 수 없으므로 새 실행을 안내한다. (2026-10-31 이후 세션: 처음에는 능력이 하나라도 켜지면 막아, 파일 첨부를 켠 앱은 파일 없이 실행해도 재개할 수 없었다 — UAT 발견)

현재부터 저장하는 해당 앱 기록에 정규화 입력을 app_inputs로 함께 보관한다. 입력은 이미 사용자 메시지에 저장되는 내용이며 동일한 대화 소유권·삭제 수명을 따른다. 이전 기록에 재개용 입력이 없거나 첫 단계부터 실패해 완료 결과가 없으면 새로 실행해야 한다.

## 실행·추적

검사 실패는 새 대화 생성 전에 거절한다. 재개 원본 메시지 ID와 재사용 표시를 새 답변에 저장하고 사용량 기록에도 출처/재사용 단계 수를 남긴다. 남은 각 모델 호출에서 기관 제한과 모델 정책을 다시 검사한다. 재개가 또 실패해도 완료된 결과는 새 실패 기록에 보존한다(저장소가 정상일 때).

새 실행은 독립 대화다. 원본 대화를 지워도 사용자가 재개하여 만든 새 결과까지 자동 삭제하지는 않는다. 새 결과를 지우려면 해당 대화를 삭제한다.

새 DB 마이그레이션은 없다. 기존 메시지 JSON 기록과 버전 정보를 사용한다.

## 검증과 한계

- 로컬 타입 검사 통과.
- 소유권·다른 앱·버전/입력 변경·임의 결과 위조·자료 연결 앱 차단·완료 결과만 재사용·새 호출만 과금하는 테스트 추가.
- 실제 모델로 가상 자료의 첫 단계를 실행한 뒤 시험용 오류를 넣어 중단했다. 저장 형태의 기록을 복원해 첫 결과를 동일하게 재사용하고 남은 2개 모델 호출로 최종 인원 30명·새빛회의실을 유지했다. [시험 기록](evidence/app-resume-smoke.json).
- 모델 시험은 DB·사용자 세션을 쓰지 않는 독립 시험이고, 권한/저장은 별도 경로 테스트로 확인했다. 로그인 운영 화면 전체 클릭 검증은 미완료.
- 실제 연결 DB의 메시지→대화 관계/소유자/앱 필터 구문을 존재하지 않는 시험 ID로 읽기 전용 확인했다. 오류 없이 결과 없음 확인.
- 기존 기능 회귀 84개 파일 1,680개·원격 운영 빌드/타입 검사 통과 후 dpl_CtxSL9CDi618D33oCitkaqieVQ7A를 기존 주소로 promote했다. Ready 연결, 실행/빌더 200 및 비로그인 재개 요청 401 확인.

한 요청 안에서 실행하는 수동 재개다. 서버 프로세스 종료/강제 시간 제한으로 실패 기록조차 남지 않은 실행의 자동 복구, 백그라운드 작업자, 예약 재시도, 사용량 예약, 모든 외부 근거의 동일성 검증을 구현한 것은 아니다.
