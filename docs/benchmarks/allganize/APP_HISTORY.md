# 앱 실행·대화 기록 화면

2026-10-31. `/apps/history`와 공통 메뉴 **앱 실행 기록**을 추가했다. 앱 목록 상단과 각 입력형 앱 카드에서도 해당 기록으로 이동할 수 있다.

## 제공 기능

- 현재 사용할 수 있는 입력형 앱에 연결된 내 대화를 생성 시각 순으로 표시한다. 일반 비서 대화 전체나 고정 업무 작업함의 대체 화면은 아니다.
- 앱별 서버 필터와 불러온 기록 안의 제목/앱 이름/응답 미리보기 검색, 상태 필터.
- 최근 저장된 assistant 응답 기준으로 ‘응답 저장됨’, ‘중단됨’, ‘응답 기록 없음’, ‘상태 확인 필요’를 구분한다.
- 단계 상태·재사용 표시와 최근 응답 미리보기, 실행 버전 표시. 입력 원문·중간 결과 전문은 목록 응답에 포함하지 않는다.
- 대화/결과 확인, 새 실행, 지원 조건이 맞는 중단 기록의 수동 재개 연결.
- 20건씩 커서 페이지 조회. 앱 권한 때문에 숨긴 행이 있어도 마지막 스캔 행을 커서로 사용해 다음 기록을 누락하지 않는다.

## 범위와 권한

API는 세션 사용자·현재 기관으로 쿼리하고 현재 canUseAgent를 다시 적용한다. 현재 삭제/중지/접근 불가 앱의 기록은 이 화면에 표시하지 않는다. 이 정책은 기존 대화 상세/파일 보존 정책을 바꾸는 것이 아니다.

서버에서 최근 assistant 메시지만 1건씩 조회한다. 목록 상태는 실시간 작업자 상태가 아니다. 응답이 없을 때 ‘진행 중’으로 추정하지 않는다. 현재 입력형 앱으로 변경된 비서에 연결된 이전 일반 대화가 포함될 수 있으므로 새로운 실행 장부로 꾸미지 않는다.

상태/텍스트 필터는 이미 불러온 기록에만 적용됨을 화면에 표시한다. 더 많은 기록은 ‘다음 기록 불러오기’로 확인한다. 앱 필터는 서버에 적용한다. 페이지 커서는 날짜·UUID를 엄격히 검사하고 원래 DB 시각의 마이크로초 정밀도를 유지한다.

## 검증

- 로컬 TypeScript 검사 통과.
- 사용자/기관 필터·현재 앱 권한·재개 가능성·미리보기 상한·원입력/중간 결과 비노출·상태 구분·잘못된 커서·숨긴 마지막 행 뒤 페이지 이동을 검증했다.
- 실제 DB에서 존재하지 않는 시험 사용자/기관 ID로 같은 관계 조회·최근 응답 제한·마이크로초 커서를 읽기 전용 점검했다. 오류 없이 빈 결과 확인. 시험 데이터를 새로 쓰지 않았다.
- 로그인 운영 화면의 앱별 기록 탐색→재개→다운로드 전체 클릭 검증은 미완료.
- 전체 회귀 85개 파일 1,696개 통과 후 기록 테스트를 18개로 보강해 재검증했다(나머지 기존 기능 1,680개는 변경 없음). 원격 운영 빌드/타입 검사 통과.
- dpl_8eRu8dysKjK1TBAAajocPcCEFKwW를 기존 주소로 promote. 기록 화면 200 및 비로그인 API 401 확인.

새 DB 마이그레이션이나 모델 호출은 없다. 기존 대화/메시지와 앱 설정을 읽어 요약한다.
