# 입력형 앱 파일 입력

2026-10-31. 앱 빌더에서 파일 입력을 선택·필수로 설정하고 기존 채팅 첨부 업로드·추출·소유권 검사 경로를 연결했다. 새 DB 마이그레이션은 없다.

## 사용

1. 앱 설정에서 **파일 첨부 받기**를 켜고 저장한다. 필요한 경우 **파일 필수**도 켠다.
2. 실행 화면에서 참고 파일을 고르고 읽기가 끝나면 초안을 만든다.
3. 결과 검토·HWPX 내보내기·대화의 첨부 원자료 확인은 기존 기능을 사용한다. 새 실행에는 파일을 다시 첨부한다.

최대 3개, 파일당 10MB. 기존 지원 형식 HWP/HWPX/DOCX/PDF/PPTX/TXT/XLSX/XLSM/CSV를 사용한다. 추출한 본문·표·파일 이름을 JSON으로 직렬화한 합계가 20,000자 이내여야 한다. 원문 자체의 글자 수 상한과 정확히 같지는 않다. 추출 경고, 표 잘림, 읽을 내용 없음, 본문 로드 실패는 실행 전에 거절한다. OCR은 추가하지 않았다.

## 실행·권한

- 앱 설정 검증은 파일 필수 여부만 보존한다. 클라이언트 저장 경로나 임의 본문은 받지 않는다.
- 빌더가 `file_read` 능력을 설정하며 서버는 기존 실제 능력·첨부 ID 형식·개수·소유권·준비 상태·대화 결합 가능 여부를 다시 검사한다.
- 서버가 결합된 사용자 대화에서 추출 데이터를 읽는다. 실제 본문과 표 전체를 사용자 자료로 전달하므로 도구가 없는 중간 단계에도 원자료가 전달된다. 파일의 지시문은 자료로 취급하도록 안내한다.
- 첫 실행의 추출 로드/크기 검증이 실패하면 새 대화와 첨부 저장소를 정리하고 다시 첨부하도록 화면을 비운다. 기존 대화는 삭제하지 않는다.
- 단계형 앱의 외부 도구 제한은 유지한다. 파일 앱은 근거 변경 가능성 때문에 수동 단계 재개 대상에서 제외한다.
- 실행 후 업로드 칩만 비우며 대화에 묶인 원자료는 유지한다. 보내지 않고 떠난 파일에는 기존 미연결 첨부 정리 정책을 적용한다.

## 검증

- 새 단위 테스트: 정의 정규화, 본문·표 전달, 읽기 실패·빈 자료·추출 경고·잘림·합계 길이 거절.
- 준비기 통합 테스트(저장소/DB 모의): 실제 서버 준비 경로에서 결합된 첨부 본문이 단계 공통 입력에 포함되는지, 필수/미허용 첨부 사전 거절, 추출 실패 시 정리 확인.
- 기존 첨부 추출·저장소 격리·단계 실행 회귀와 타입 검사 및 원격 운영 빌드로 검증한다.
- 회귀 86개 파일 1,704개 통과. 이후 실패 정리 테스트 1개를 추가해 해당 준비기 파일 7개를 재실행했고 모두 통과했다. 타입 검사·원격 운영 빌드 통과, 배포 `dpl_B6mjHofZCHENbH8VtEU7zs5Ni2Gy`를 기존 주소에 반영했다. 화면 200·비로그인 실행 401도 확인했다.
- 로그인 브라우저에서 업로드부터 결과 다운로드까지 직접 클릭한 종단 검증은 아직 수행하지 않았다. 위 검증을 실제 기관 문서 정확도나 브라우저 종단 검증으로 해석하지 않는다.
