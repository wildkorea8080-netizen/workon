# 입력형 앱 빌더 1차

이후 확장: [단계별 텍스트 처리](STAGED_APPS.md). 아래 ‘다단계 조합 없음’은 1차 인도 당시 범위이며 현재는 제한된 순차 단계가 추가됐다.

## 사용 흐름

앱 목록의 **입력형 앱 만들기** → 이름·역할·제공 범위 설정 → 입력 항목 추가 → 응답 형식 선택 → 저장 → 저장된 앱 실행 → 텍스트 초안 → 기존 대화에서 추가 요청.

- 입력 종류: 짧은 글·긴 글·숫자·날짜·목록 선택. 최대 8개, 필수 여부 설정.
- 응답 형식: 제목과 문단·항목별 목록·체크리스트. 서버가 모델 지시문에 반영한다. 생성 결과의 형식을 강제로 보장하는 JSON Schema 출력 검증은 이번 범위 밖이다.
- 개인 앱 또는 부서 앱 생성. 기존 권한 모델·비서 버전·사용량 제한·금지어/개인정보 검사·모델 정책·대화 저장 재사용.
- 앱 목록에 입력형 앱 구분과 실행 링크, 권한 있는 사용자의 설정 수정 링크.
- 일반 비서 선택 화면에서 입력형 앱을 고르면 전용 입력 화면으로 이동한다. 기존 대화는 기존 화면에서 이어간다.
- 별도 실행마다 새 대화를 만들며 결과와 입력 자료는 대화 이력에 저장된다.

## 서버 계약과 버전

agents.app_definition JSONB를 0043으로 추가하고 agent_snapshot/save_agent에 포함했다. 기존 비서는 NULL을 유지한다. 앱 정의는 저장 API에서 정규화하며 항목 키/이름 중복·종류·선택값·크기 상한을 검사한다.

실행 API는 기존 /api/chat을 사용한다. 현재 비서 권한과 정책을 확인한 뒤 현재 설정 기준으로 app_inputs를 검증하고 사용자 메시지를 서버에서 구성한다. 폼 입력을 임의 message로 대체할 수 없다. app_version 불일치는 대화 생성 전에 409로 거절한다. 폼 전체 입력은 JSON 직렬화 기준 16,000자, 긴 글은 항목당 6,000자로 제한한다.

예전 버전 복원 시 입력 폼도 복원한다. 앱 정의가 없던 과거 사본은 NULL로 복원하므로 새 폼이 잘못 남지 않는다. 응답 스트림은 done 이벤트가 없거나 error 이벤트가 있으면 완료로 표시하지 않는다.

## 이번 범위 밖

조건 분기·다단계 조합·파일 입력형 필드·앱 고유 파일 산출·예약 실행·외부 쓰기·시각적 노드 편집기는 아직 없다. 이번 기능을 범용 노코드 워크플로우 빌더 완료로 표시하지 않는다. 기본 생성 앱은 텍스트 입력/출력만 사용한다.

## 검증 기록

- 입력/스키마·변경된 판 거절·폼 우회 차단·기존 비서/첨부 경로·SSE 분할/중단 감지 관련 9개 파일 108개 테스트 통과.
- 시험 DB에 0043 적용, 생성 사본·변경 사본·동시 수정 충돌·복원·NULL 해제 확인. 시험 앱과 이력은 모두 ROLLBACK.
- 가상 행사 자료를 실제 Claude에 보내 숫자와 장소가 포함된 응답 생성 확인.
- 로컬 타입 검사와 전체 회귀는 메모리 부족으로 한 차례 중단. 사용하지 않는 도구 세션을 정리하고 원격 빌드/타입 검사 및 워커 1개 회귀로 검증을 이어갔다.
- 로그인된 브라우저의 만들기→저장→실행 전체 화면 검증은 미완료.
- 워커 1개로 기존 기능 회귀 81개 파일 1,639개 통과. 원격 운영 빌드·타입 검사 통과, 배포 dpl_2NpUXbv6QfVJtTFqKxSBqrLyd3xE Ready 확인.
- 검증 후 운영으로 promote 완료. 기존 주소의 앱 목록·빌더·실행 경로 200과 비로그인 실행 요청 401 확인.
