# 보고서·민원 회신의 비서 문서함 근거 연결

후속 검증: [로컬 DB·HWPX 통합 검증](INTEGRATION_VALIDATION.md)에서 실제 PostgreSQL·파일 생성·수정 후 근거 보존을 확인했다. 아래의 통합 미검증 설명은 최초 구현 단계 기준이다. 외부 ReadLayer·LLM·인증 UI·운영 배포는 여전히 미검증이다.

2026-10-29. 규정 확인에서 구현한 공개 공식 비서의 문서함 범위를 새 보고서·민원 회신으로 확장했다. 운영 미배포.

작업 시작 시 문서함 검색을 선택하면 기존 기관·부서·공개·활성·검색 능력 검사를 거쳐 선택 문서함 하나만 검색한다. 회신은 제목·문의 내용, 보고서는 제목·입력 사실을 검색어로 사용한다. 검색어는 2,000자, 근거는 최대 24개·각 1,500자로 제한한다. 첨부 자료와 함께 생성기에 전달하며 기존 필드·인용·수치 검증을 유지한다. 이 두 업무는 공통 자료실·법령을 추가 검색하지 않는다.

검색 결과는 별도의 app_evidence 실행 체크포인트와 문서 판의 appEvidence에 보존한다. 첨부 파일 UUID와 혼동하지 않도록 rag: 접두사의 근거 번호를 사용하며 work_sources 외래키 목록에 넣지 않는다. 작업실은 출처 이름·위치·검색 본문을 펼쳐 보여준다. 직원 수정과 AI 수정에서도 보존된 근거를 이어 쓴다. 원문 파일 직접 열기와 문서 버전 동결은 아직 지원하지 않는다.

선택한 문서함을 검색할 수 없거나 근거가 0건이면 생성 전 SOURCE_UNAVAILABLE로 실패한다. 기존 작업의 문서함 연결이 없으면 검색을 호출하지 않는다. 원래 비서가 수정되어도 저장된 작성 지침은 유지하지만 문서 검색은 검색 당시 자료와 권한을 사용한다. 재시도는 기존 체크포인트를 재사용할 수 있다.

작년 파일을 사용하는 보고서 현행화는 이번 범위에서 제외한다. 문서함을 연결한 작업에서 현행화를 시도하면 지원 범위를 설명하고 실패시킨다. 선택 옵션에도 제한을 표시했다. 감사·공문·회의·개인 비서 문서함은 후속이다.

검증: 관련 5개 파일 55개 테스트, TypeScript, diff 공백 검사 통과. 실제 PostgreSQL·외부 ReadLayer·인증 UI·최종 HWPX 다운로드 통합 검증은 수행하지 않았다. DB 0036 적용과 배포가 필요하며 운영 DB는 변경하지 않았다.
