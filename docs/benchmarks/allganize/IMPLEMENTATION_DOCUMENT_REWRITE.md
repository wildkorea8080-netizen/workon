# 문장 교정·공문체 변환 앱

2026-10-29. 공개 앱 090(문장 교정)과 문체 전환 기능을 참조해 document-rewrite를 추가했다. 전체 앱 구현 완료가 아니다.

입력은 제목·작업 방식·원문 파일·결과 양식이다. 작업 방식은 맞춤법·문장 교정, 공문체, 시민 안내문체 세 가지다. 문서 한 개·읽힌 원문 12,000자까지 지원한다. 기존 보고서형 HWPX 양식에서 개요는 교정 범위와 유의사항, 주요 내용은 다듬은 원문 전체로 사용한다. 요약 앱과 다르게 문장·조건·예외를 생략하지 않도록 지시한다. 실제 참고 자료 이름도 표시한다.

서버는 변환 본문의 숫자 표기를 원문과 개수까지 대조한다. 숫자·날짜 토큰과 일부 붙여 쓴 단위가 바뀌거나 누락·추가되면 결과를 저장하지 않는다. 사람이 읽는 의미·이름·조건·단위의 모든 형태를 완전히 검사하는 것은 아니다. 예를 들어 같은 수가 다른 대상에 붙는 오류는 이 검사만으로 잡지 못하므로 직원 검토가 필요하다. 정당한 수치 재표기라도 원문 표기가 달라지면 거부할 수 있다.

원문 조건을 공문체로 바꾸는 것은 문장 편집이며 승인·발송이 아니다. 비서 문서함 자동 검색·여러 문서 병합·원문 서식 유지·변경 전후 대조표는 이번 범위가 아니다. 결과는 재사용한 보고서 양식이며 빈 보고서 항목 제목이 남을 수 있다.

검증: 전용 PostgreSQL에 마이그레이션 38개 적용 성공. 수치 변경·누락·추가·개수 검사와 실제 HWPX 생성/변경 차단 통합 사례·기존 업무 회귀를 포함해 3개 파일 47개 테스트 통과. TypeScript·diff 공백 검사 통과.

실제 Claude 호출 1회로 가상 안내문을 공문체로 변환했다. 날짜·시간·인원·금액 표기가 보존됐고 우천 조건·미확정 계획이 결과에 남았다. 약 8초·기록 원가 약 16원. 짧은 시험 문서 한 건의 성공이며 일반 정확도를 보장하지 않는다.
