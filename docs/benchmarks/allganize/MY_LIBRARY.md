# 내 자료함 (2026-11-24, 0103)

직원이 자주 쓰는 파일을 **폴더로 모아 두고** 대화·입력형 앱에 다시 붙이는 개인 자료함이다. 알리웍스의 개인 문서함(내 폴더에 올려 두고 대화에서 고르기)에 해당한다.
그 전에는 '지난 파일'(최근 90일 안에 대화에 보낸 첨부·비서가 만들어 준 파일)만 있어, 90일이 지나거나 대화를 지우면 다시 붙일 수 없었다.

## 무엇이 되나

- **담기** — 결과물 화면(`/files`)의 '대화에서 만든 파일'·'대화에 올린 파일' 줄마다 '자료함에 담기', 또는 '내 자료함'의 '파일 올려 담기'. 폴더 이름을 묻는다(비우면 미분류).
  - 담는 것은 **사본**이다(`my-library/{기관}/{직원}/{id}.{확장자}`, 서버가 정함). 원래 대화·첨부를 지워도 남는다.
  - 직접 올리기는 대화 첨부와 같은 길(주소 발급 → 저장소 직접 → 확인·읽기)로 올려 **읽어 본 뒤** 담고, 올린 첨부는 바로 치운다 — 읽지 못한 파일(암호·DRM 등)은 담지 않는다.
- **정리** — 폴더 고르기(전체·미분류·폴더별 수), 이름 바꾸기(확장자는 그대로), 다른 폴더로 옮기기, 지우기(사본 → 행), 내려받기(60초 서명 주소), 이름·내용 찾기(페이지 위 통합 찾기 — 내용은 0117).
- **다시 붙이기** — 대화 입력창·입력형 앱 실행 화면의 '지난 파일'에 '내 자료함' 탭(폴더 고르기 포함). 고르면 `POST /api/attachments/reuse { kind: 'library', id }`가 지난 파일과 같은 길(`attachStoredObject` — 발급·올림·확인·사용 기록)로 새 첨부를 만든다.

## 지키는 것

- **주인만** — 모든 조회·변경·다시 붙이기·내려받기가 `user_id = 요청자` **그리고** `organization_id = 요청자 기관`으로 행을 다시 찾는다(화면이 고른 id를 믿지 않음). 관리자도 남의 자료함을 못 본다. 응답에 저장소 경로를 싣지 않는다.
- 상한: 한 사람 300개(`LIBRARY_MAX_FILES`), 폴더 30개(미분류 제외), 폴더 이름 30자(`/`·`\` 금지, 한 단계), 파일 이름 120자, 파일 하나 10MB(대화 첨부와 같음), 대화에 붙일 수 있는 형식만.
- 사본을 만든 뒤 행을 넣지 못하면 사본을 지운다. 지우기는 사본을 못 지우면 행을 남긴다(다시 지울 수 있게). 원본이 저장소에 없으면 404, 지금 못 받으면 503.
- **탈퇴 처리**가 경로를 먼저 모으고(못 읽으면 멈춤) 대화를 지운 뒤 자료함 행을 지우고, 도장 뒤 사본을 지운다.
- 부서 칸이 없다(개인 자료라 부서 삭제 판정 대상이 아님).

## 부서 자료함 (2026-11-24, 0106)

같은 화면·같은 표에 **자리**(`space`)를 더했다 — `personal`(내 자료함) · `department`(부서 자료함). 결과물 화면의 자료함 칸 위 탭으로 고르고, 아래 두 대화 목록의 '담기'도 고른 자리로 담는다. 대화·입력형 앱 '지난 파일'에 '부서 자료함' 탭.

- **보는 사람**: 요청자의 **지금 소속 부서** 사람(상위·하위 부서는 따로 — 부서마다 자기 자료함). 담기·다시 붙이기·내려받기는 그 부서 누구나.
- **바꾸기·지우기**: 담은 사람이나 관리자만(`canChangeLibraryRow`, 403 — 화면은 남이 담은 줄에 단추를 숨김). 목록에 '담은 사람'(이름만, 사람 id 없음).
- 담은 사람이 **부서를 옮겨도·탈퇴해도 파일은 그 부서에 남는다** — 탈퇴 처리는 내 자료함만 지운다. 부서 자료함이 남은 부서는 지우지 않는다(부서 삭제 판정의 기록 표에 '부서 자료함').
- 상한: 부서마다 500개(`LIBRARY_MAX_DEPARTMENT_FILES`), 폴더 30개. 경로 `my-library/{기관}/d/{부서}/{id}.{확장자}`.
- 다시 붙이기(`kind: 'library'`)·내려받기는 내 자료함의 내 행 → 없으면 지금 내 부서의 부서 자료함 행으로 찾는다.
- API: 목록 `?space=department`, 담기·고치기 몸 `space`, 지우기 `?space=department`.
- 마이그레이션 **0106**: `space`(기본 personal)·`department_id`(부서 외래 키, 지우기를 막음) + 짝 CHECK(내 자료함은 부서 없음·부서 자료함은 부서 있음) + 부서 색인. 추가만, 여러 번 적용해도 안전, **0103 뒤·코드 배포 전에 적용** — 새 코드가 `space`로 조회해 없으면 자료함 화면이 실패한다.
- 시험: `tests/batch-0285.test.ts`.

## 기관 자료함 (2026-11-25, 0112)

같은 표에 자리 `organization`(기관 직원 모두가 함께 보는 자료함 — 공통 서식·기준 자료 등)을 더했다. 결과물 화면 자료함 탭·'지난 파일'에 '기관 자료함'.

- **보기·내려받기·다시 붙이기는 같은 기관 직원 누구나** — 조회 조건은 `space = 'organization'`·`organization_id = 요청자 기관`(부서·사람 조건 없음). 다시 붙이기·내려받기(`findLibraryOriginal`)는 내 자료함 → 지금 부서의 부서 자료함 → 기관 자료함 순으로 찾는다.
- **담기·이름/폴더 바꾸기·지우기는 기관 전체 관리자(최상위 부서 소속 관리자)만**(`canAddToLibrary`·`canChangeLibraryRow` — `LibraryActor.managesWholeOrganization`, 없으면 아닌 것으로, 403 `LIBRARY_ORG_ONLY`). 하위 부서 관리자·담은 사람이어도 기관 전체 관리자가 아니면 못 고친다 — 기관 전체에 보이는 자료라서(기본 비서 세트 설치·태그 분류표와 같은 규칙). 거절은 원본을 읽거나 사본을 건드리기 전에.
- 목록 응답 `canAdd`(이 자리에 담을 수 있는가)로 화면이 '파일 올려 담기'와 결과물 목록의 '기관 자료함에 담기'를 숨긴다(서버가 다시 본다). 담은 사람 이름을 보인다.
- 기관마다 1,000개(`LIBRARY_MAX_ORGANIZATION_FILES`), 폴더 30개, 경로 `my-library/{기관}/o/{id}.{확장자}`. 행은 `department_id`가 없다(CHECK). 담은 관리자가 탈퇴해도 남는다(탈퇴 처리는 내 자료함만).
- 마이그레이션 0112: `my_library_files_space_check`를 세 자리로 넓히고 기관 자리 색인. 값만 넓힘, 여러 번 적용해도 안전, **0106 뒤·코드 배포 전에 적용**(없으면 기관 자료함에 담기만 CHECK로 실패). 시험: `tests/batch-0292.test.ts`.

## 여러 단계 폴더 (2026-11-25, 0113)

세 자료함(내·부서·기관)의 폴더를 `예산/2026/서식`처럼 `/`로 나눠 **3단계까지** 둔다(`cleanFolderName` — 단계마다 다듬고 빈 단계는 버림, 한 단계 30자, `\`·`"`는 거절, 경로 100자).

- 폴더를 고르면 **그 폴더와 그 아래 폴더의 파일**을 함께 보인다(`subtreeFolders` — 이 자리의 폴더 값에서 `고른 폴더` 또는 `고른 폴더/…`만, 이름이 비슷한 옆 폴더 `예산안`은 빠짐, 쪽 읽기는 `.in('folder', …)`).
- 폴더 목록은 나무로(`folderTree` — 파일이 없는 윗단계도 넣고 수는 그 아래까지 합침, 미분류 먼저·깊이 우선 이름 순), 화면 이름은 `예산 › 2026`(`folderLabel`). 결과물 화면·'지난 파일'이 같다.
- 폴더 수 상한(30)은 서로 다른 경로 수로 센다(윗단계는 따로 세지 않음).
- **폴더째 이름 바꾸기·옮기기**(2026-11-25, 마이그레이션 없음): 폴더를 고르면 '폴더 이름 바꾸기·옮기기' → `PATCH /api/my-library/folders { space, from, to }`(`moveLibraryFolder`) — 그 폴더와 그 아래 폴더의 파일을 모두 새 경로 아래로(`to`가 비면 미분류로 풀어 놓음). 계획(`planFolderMove`)은 옮긴 뒤 3단계·한 단계 30자를 보고, 자기 아래로·같은 곳·미분류는 거절, 경로마다 조건부로 바꾸되 **얕은 경로부터**(윗단계로 올릴 때 먼저 옮긴 파일이 다시 옮겨지지 않게). 내 자료함은 나, **부서 자료함은 관리자**(남이 담은 파일도 함께 옮겨지므로), 기관 자료함은 기관 전체 관리자만 — 거절은 읽기 전에. 도중 실패는 옮긴 수와 함께 503(다시 하면 남은 것만). 시험: `tests/batch-0294.test.ts`.
- 마이그레이션 0113: 폴더 칸 CHECK를 30자에서 100자로(옛 CHECK를 찾아 지우고 다시 검). 값만 넓힘, 여러 번 적용해도 안전, **코드 배포 전에 적용**(없으면 두 단계 이상 폴더에 담기·옮기기만 실패). 시험: `tests/batch-0293.test.ts`.

## 자료함 사이 복사·옮기기 (2026-11-25, 마이그레이션 없음)

파일 줄의 '다른 자료함으로' → 보낼 곳(지금 자리 말고 담을 수 있는 자료함 — 목록 응답 `canAddTo`)·복사/옮기기·폴더를 골라 `POST /api/my-library/[id] { space, to, mode, folder? }`(`transferLibraryFile`, 201).

- **복사**(`copy`)는 볼 수 있는 파일이면 누구나 — 내려받아 다시 올리는 것과 같아서(부서 자료함의 남이 담은 파일·기관 자료함 파일을 내 자료함으로). 원래 파일은 그대로.
- **옮기기**(`move`)는 원래 자리에서 바꾸거나 지울 수 있는 사람만(`canChangeLibraryRow` — 부서 자료함에서 남이 담은 파일은 관리자, 기관 자료함은 기관 전체 관리자). 화면은 못 옮기는 파일에서 옮기기를 막는다.
- 받는 자리는 담을 수 있어야 한다(기관 자료함은 기관 전체 관리자만 — 파일을 읽기 전에 403). 받는 자리의 개수(300·500·1,000)·폴더 30개·폴더 규칙을 본다(409·400).
- 새 자리에는 **새 사본·새 행**(새 id, 경로는 받는 자리 꼴)이고 '담은 사람'은 보낸 사람, 담은 곳(올린 파일·만든 파일)은 그대로. 부서 자료함은 보낸 사람의 지금 부서로.
- 순서: 새 사본 → 새 행(못 넣으면 새 사본을 지우고 503) → (옮기기면) 원래 행 → 원래 사본. 원래 행을 못 지우면 성공으로 답하되 **두 곳에 있다는 경고**(`warning` — 화면이 오류 칸에 보인다)를 싣고 원래 사본은 지우지 않는다. 원래 사본을 못 지우면 운영 기록 warning(id·두 자리만)에 남긴다(행이 없어 아무도 못 보는 사본). 원래 사본이 없으면 404, 복사 실패 503.
- 같은 자리 안은 이 길이 아니라 폴더 옮기기(400).

시험: `tests/batch-0296.test.ts`.

### 여러 파일·폴더째 (2026-11-25, 마이그레이션 없음)

목록 줄의 고르기 칸(머리 칸은 이 목록 모두)으로 고른 뒤 '고른 파일 다른 자료함으로', 또는 폴더를 고른 뒤 '폴더째 다른 자료함으로' → `POST /api/my-library/transfer { space, to, mode, folder?, ids? | fromFolder? }`(`transferLibraryFiles`, 둘 중 하나만).

- 한 번에 **50개까지**(`LIBRARY_TRANSFER_MAX` — 고른 파일 수, 폴더째면 그 폴더와 아래 폴더의 파일 수. 넘으면 400 — 아래 폴더로 나눠 보냄). 미분류는 폴더째로 보내지 않는다(파일을 골라 보냄).
- **보내기 전에 한꺼번에 본다** — 볼 수 없는 파일이 섞였으면 404, 옮기기인데 바꿀 수 없는 파일이 하나라도 있으면 403(몇 개인지·복사는 된다고), 받는 자리 개수가 모자라면 409(몇 개만 더 담을 수 있는지), 보낸 뒤 폴더가 30개를 넘으면 409. 하나라도 걸리면 아무것도 보내지 않는다.
- 폴더째면 **폴더 이름과 그 아래 구조를 받는 폴더 아래 그대로** 둔다(`transferFolderPath` — `예산`·`예산/2026`을 받는 폴더 `공유`로 → `공유/예산`·`공유/예산/2026`, 비우면 맨 위에 `예산`). 3단계를 넘게 되면 400. 이름이 비슷한 옆 폴더(`예산안`)는 들지 않는다(`subtreeFolders`).
- 파일마다 한 파일 보내기와 같은 순서(`sendRow` — 새 사본 → 새 행 → 원래 행 → 원래 사본). **도중에 실패한 파일은 건너뛰고 이어 가며** `failed`(이름·까닭)로, 두 곳에 남은 파일은 `warnings`로 돌려준다 — 보낸 것은 되돌리지 않는다. 화면은 보낸 수를 알리고 실패·경고를 다섯 개까지 오류 칸에 보인다.
- 화면은 목록(폴더·찾기·자리)이 바뀌면 고른 것을 비운다(보이지 않는 파일을 보내지 않게). 옮기기 단추는 고른 파일을 모두 바꿀 수 있을 때만(폴더째면 내 자료함이거나 관리할 수 있을 때) 켜진다 — 서버가 다시 본다.

시험: `tests/batch-0298.test.ts`.

## 파일 내용으로 찾기 (2026-11-25, 0117)

결과물 화면의 찾기 칸이 자료함에서는 **이름과 담은 파일의 내용**을 함께 본다(다른 세 목록은 그대로 이름만).

- **담을 때 글로 읽어 둔다**(`saveToLibrary` → `readContent`): 대화 첨부(직접 올려 담은 파일 포함)는 확인 때 읽어 둔 내용(`loadExtract`), 비서가 만든 파일은 원본을 다시 읽는다(`readOriginalText` — **스캔 PDF는 NODA로 보내지 않는다**). 사본 만들기와 나란히 읽고, 못 읽으면 내용 찾기만 빠지고 담기는 그대로(이름으로만 찾힘).
- **얼마나**: 제어·서식 글자를 빼고 공백을 하나로 접은 앞 **100,000자**(`libraryContentText`·`LIBRARY_CONTENT_MAX`, 코드 포인트 — DB CHECK와 같음. 0117은 20,000자였고 0127(2026-11-26)에 넓혔다 — 첨부 읽개는 200,000자까지 읽는다)를 `my_library_files.content_text`에. 찾기는 이름 + 내용을 이은 생성 칸 `search_text`를 `ilike`로(이름을 바꾸면 따라 바뀜).
- **화면**: 내용에서 맞은 파일은 이름 아래 맞은 자리 앞 30자·뒤 60자(`librarySnippet` — 이름에서 맞았으면 없음)를 보이고 맞은 글을 칠한다. **내용 글 자체는 응답에 싣지 않는다**(찾을 때만 읽어 자리만 뽑음). 찾을 때 '이름과 담은 파일의 내용(앞 100,000자)에서 찾습니다…' 안내.
- **보내기**: 다른 자료함으로 복사·옮기면 내용 글도 함께 간다(다시 읽지 않음).
- **내용 채우기**(2026-11-25, 0120): 담을 때 읽지 못한 파일(저장소가 잠깐 응답하지 않음 등)과 0117 전에 담은 파일은 `content_checked_at`이 비어 있고, **5분 실행기**(`/api/cron/app-schedules`)가 그런 파일을 두 개씩(최근 20개 중 섞어 골라, 25초 안) **자료함 사본**에서 다시 읽어 채운다(`src/lib/library-content-fill.ts` `fillLibraryContent` — 같은 `readOriginalText`, 스캔 PDF는 NODA로 보내지 않음, 모델 없음). 읽었으면(글이 없었어도) 확인한 때를 적어 다시 읽지 않고(아직 확인하지 않은 행일 때만 — 조건부), 저장소가 잠깐 안 될 때(503)만 다음 차례에 다시 본다. 담을 때 읽었으면 그때를 적고, 다른 자료함으로 보내면 확인한 때도 함께 간다. 마이그레이션 **0120**: `content_checked_at` + 내용 글이 있는 행은 담은 때로 채움 + 확인 안 한 행 색인. 추가만, 여러 번 적용해도 안전, **코드 배포 전에 적용** — 없으면 자료함 담기가 실패한다. 시험: `tests/batch-0304.test.ts`.
- **한계**: 스캔 PDF·읽지 못하는 파일은 이름으로만 찾힌다. 사본이 저장소에서 사라진 파일은 503으로 보여 차례마다 다시 읽힌다(후보를 섞어 다른 파일을 막지는 않는다). 앞 100,000자 밖은 찾지 못한다(0127 전에는 20,000자). 색인(pg_trgm) 없이 자리 안에서 훑는다 — 자리마다 파일이 300~1,000개라 충분하다고 봤다. 뜻 찾기(비슷한 말)는 아니다.

마이그레이션 **0127**(2026-11-26): CHECK를 1~100,000자로 넓히고, 20,000자에서 잘렸을 파일(19,990~20,000자)은 `content_checked_at`을 비워 5분 실행기가 사본에서 다시 읽어 채우게 한다(값만 넓힘·여러 번 적용해도 안전, **코드 배포 전에 적용** — 옛 CHECK면 20,000자 넘는 글을 담을 때 거절된다). 시험: `tests/batch-0320.test.ts`.

마이그레이션 **0117**: `my_library_files.content_text`(1~20,000자 CHECK — 0127이 100,000자로) + `search_text`(생성 칸). 추가만, 여러 번 적용해도 안전, **0116 뒤·코드 배포 전에 반드시 적용** — 새 코드가 담기·보내기에서 `content_text`를 쓰고 찾기에서 `search_text`를 읽어, 없으면 자료함 담기·찾기가 실패한다. 시험: `tests/batch-0300.test.ts`.

## 공유 자료함 — 여러 부서만 골라 함께 (2026-11-25, 0116)

기관 전체 관리자가 '기관 정보' 화면의 '공유 자료함'(`LibrarySharesPanel` ← `GET`·`POST /api/admin/library-shares`, `PATCH`·`DELETE …/[id]`, `src/lib/library-shares.ts`)에서 이름(1~40자, 기관 안에서 하나)과 함께 쓸 부서(1~50곳)를 골라 만든다. 기관마다 50개, 한 곳에 파일 500개.

- **누가 보나**: 지금 소속 부서가 그 목록에 든 직원. '하위 부서도 함께'(아래 0132)를 켠 공유 자료함은 고른 부서 아래 부서 직원도(상위 부서는 아님). 요청마다 `loadLibraryShares`(부서 → 공유 자료함, 이 기관 것만)로 든 곳을 읽어 요청자에 싣고(`libraryActorOr` — `src/lib/my-library-actor.ts`, 못 읽으면 503), 요청이 고른 공유 자료함(`share`)이 그 안에 있을 때만 다룬다(`placeActor` — 아니면 읽기 전에 404). 관리자도 자기 부서가 든 공유 자료함만 본다(관리 화면은 이름·부서·파일 수만).
- **하는 일**: 부서 자료함과 같다 — 누구나 담고 다시 붙이고 내려받고, 이름·폴더 바꾸기·지우기·남의 파일 옮기기는 담은 사람이나 관리자, 폴더째 옮기기는 관리자. 다른 자료함(공유 자료함끼리 포함)으로 복사·옮기기(`to: 'shared'`, `toShare`)도 된다. 다시 붙이기·내려받기는 내 → 부서 → 기관 → 지금 부서가 든 공유 자료함 순(`findSharedRow`).
- **자리 표시**: `my_library_files.space = 'shared'` + `share_id`(파일이 남은 공유 자료함은 지우지 못함 — 외래 키 RESTRICT, 화면도 409). 경로 `my-library/{기관}/s/{공유 자료함}/…`.
- **고치기**: 부서를 빼면 그 부서 사람은 더 못 보고 파일은 남는다. 부서를 지우면 그 부서 줄만 빠진다(공유 자료함·파일은 남음). 담은 사람이 탈퇴해도 남는다. 만들기·고치기·지우기는 보안 로그 `library_share_changed`(medium), 대리 접근 중 403.
- **화면**: 결과물 화면 자료함 탭 뒤에 내가 든 공유 자료함 이름 탭, 대화·입력형 앱 '지난 파일'에도 같은 탭(`GET /api/my-library/shares` — 못 읽으면 탭 없이 그렇다고 알림), 다른 자료함으로 보낼 곳에 공유 자료함.

### 하위 부서도 함께 (2026-11-26, 0132)

- 공유 자료함을 만들거나 고칠 때 '하위 부서도 함께'를 켜면 고른 부서와 **그 아래 부서(몇 단계든)** 직원이 함께 쓴다 — 본부를 고르면 그 아래 과·팀까지, 과를 새로 만들어도 다시 넣지 않는다. 부서 비서를 하위 부서가 쓰는 것과 같은 방향이라 하위 부서를 고르면 상위 부서는 못 쓴다. 기본은 꺼짐(지금 공유 자료함은 그대로).
- 판정은 `loadLibraryShares` 한 곳(자료함 목록·담기·다시 붙이기·내려받기가 모두 이것으로 든 곳을 읽는다): 내 부서 + 상위 부서(`getVisibleDepartmentIds` — 못 읽으면 던져 503)의 공유 자료함 줄을 읽고 `memberShareIds`(`my-library-spec.ts`, 순수)가 '내 부서를 골랐거나, 켠 공유 자료함이 내 상위 부서를 골랐을 때'만 남긴다.
- API: `POST`·`PATCH /api/admin/library-shares` 몸에 `includeDescendants`(참·거짓, 만들 때 없으면 꺼짐·고칠 때 없으면 그대로), 목록에 `includeDescendants`, 바뀌면 보안 로그 `library_share_changed`의 `changed`에 `include_descendants_on`·`_off`. 화면은 목록 줄에 '하위 부서 포함', 고치기 칸에 체크.
- 마이그레이션 **0132**: `library_shares.include_descendants boolean NOT NULL DEFAULT false`. 추가만, 여러 번 적용해도 안전, **코드 배포 전에 적용** — 새 코드가 모든 자료함 요청에서 이 칸을 읽어, 없으면 자료함 화면이 503. 시험: `tests/batch-0326.test.ts`.

마이그레이션 **0116**: `library_shares`·`library_share_departments`(RLS 켜고 정책 없음·공개 키 권한 없음) + `my_library_files.share_id` + 자리 CHECK(`shared`는 `share_id`만, 다른 자리는 `share_id` 없음). 추가만, 여러 번 적용해도 안전, **0115 뒤·코드 배포 전에 반드시 적용** — 새 코드가 모든 자료함 요청에서 공유 자료함 목록을 읽어, 없으면 자료함 화면이 503. 시험: `tests/batch-0299.test.ts`.

## 마이그레이션 0103

`my_library_files`(id·user_id·organization_id·folder(30자)·file_name(1~200자)·size_bytes(>0)·storage_path(유일, `my-library/` 접두)·source(`attachment`·`generated`)·시각) + 색인 `(user_id, created_at DESC, id DESC)`. 추가만, 여러 번 적용해도 안전, RLS 켜고 정책 없음·공개 키 권한 없음. **코드 배포 전에 적용** — 없으면 내 자료함 화면·담기만 실패한다(대화·지난 파일은 그대로).

## 남은 것

- 폴더는 3단계까지(0113). 폴더째 옮기기는 한 자료함 안에서만 — 다른 자료함으로는 파일 하나·고른 여러 파일·폴더째 복사·옮기기(위, 한 번에 50개). 공유는 부서 자료함(0106)·기관 자료함(0112, 기관 전체 관리자만 담음)·공유 자료함(0116, 고른 부서들 — '하위 부서도 함께'(0132)를 켜면 아래 부서까지).
- 내용 찾기는 앞 100,000자 글 맞춤까지(0117·0127 — 뜻 찾기 아님, 스캔 PDF·0117 전에 담은 파일은 이름만). 자료함 파일을 문서 찾기(NODA)의 근거로 쓰지 않는다 — 붙였을 때 그 대화의 첨부로만 읽힌다.
- 화면은 브라우저로 열어 보지 않았다(자동 시험만).
