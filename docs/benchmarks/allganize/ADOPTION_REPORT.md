# 월별 도입 현황 보고서 (2026-11-04)

공공기관은 AI 도입 효과를 분기·연말에 보고해야 한다. 그런데 우리 통계는 흩어져 있었다(이용통계·앱 실행 현황·업무 현황). 한 달을 전월과 비교해 내보내는 보고서는 없었다.

관리자 **통계 화면 맨 위 '월별 도입 현황'**에서 달을 고르면 지표가 전월과 나란히 나온다. 결과는 CSV로 내려받는다.

## 원칙

- **기록된 사실만 센다.** '절약한 시간'·'생산성 n%' 같은 추정치는 싣지 않는다.
  - 실제 작업 시간을 재는 장치가 없는데 숫자를 만들면, 보고서가 근거 없는 주장이 된다.
  - 시험이 이런 낱말이 줄에 없는지 본다.
- **집계는 DB가 한다**(0056 `adoption_report`).
  - Supabase API는 한 번에 1,000행까지만 돌려준다. 로그를 앱으로 끌어와 세면 큰 기관에서 **조용히 덜 센다.**
- 범위는 관리자의 **관리 범위**(자기 부서 + 하위)와 기관이다.
- 숫자만 돌려준다. 직원 이름·질문 원문·결과 글은 싣지 않는다.
- 달은 **한국 시간** 기준이다. 11월 = 10월 31일 15:00Z 부터 11월 30일 15:00Z 전까지. 이번 달은 '오늘까지'라고 표시한다.

## 지표

| 구분 | 지표 | 세는 법 |
| --- | --- | --- |
| 채택 | 등록 직원 | 지금 활성인 계정(탈퇴·슈퍼관리자 제외). 전월 칸도 지금 기준 |
| 채택 | AI를 쓴 직원 · 쓴 직원 비율 | 그 달 사용 기록이 하나라도 있는 직원 ÷ 등록 직원 |
| 채택 | 자주 쓴 직원(4일 이상) | 그 달에 4일 이상(한국 날짜) 쓴 직원 |
| 사용 | AI 대화(질문 수) · 새 대화 | `chat_message` 기록 수 · 그 달에 시작한 대화 |
| 사용 | 입력형 앱 실행 · 쓰인 앱 | 입력형 앱으로 시작한 대화 수(시험 판 실행 포함) · 그 앱 수 |
| 사용 | 대화에서 만든 파일 | 양식 채우기·표 합치기 기록 |
| 업무 작업 | 새 작업 · 검토 완료 · 결과 파일 | 그 달 만든 작업 · 그 달 승인(`approved_at`, 뒤에 다시 연 작업은 빠짐) · 그 달 만든 결과 파일 |
| 업무 작업 | 사람이 고친 판 · AI 수정 요청 | 직접 수정·AI 수정 적용 판(`edit`·`revise`) · 수정 요청 — 재작업의 크기 |
| 업무 작업 | 완료 작업당 판 수 | 그 달 완료한 작업이 만든 판 ÷ 완료 수. 1에 가까울수록 처음 만든 그대로 완료 |
| 비용 | AI 사용 금액 · 쓴 직원 1인당 | 기록 시점 단가로 확정한 `cost_krw` 합 · ÷ 쓴 직원 |

표기 규칙은 이렇다.

- 분모가 0인 비율은 '—'로 적는다.
- 전월 대비는 늘어난 것은 숫자만, 줄어든 것은 공공기관 표기대로 `△`로 적는다. 비율은 %p로 적는다.
- 그래서 CSV 칸이 `+`·`-`로 시작하지 않아 엑셀이 수식으로 읽지 않는다. 다른 칸도 수식 주입 앞글자에 `'`를 붙인다.

## 남은 것

- 사람이 실제로 일한 시간은 재지 않는다. 대신 2026-11-06부터 '완료까지 걸린 시간(중앙값)'을 싣는다(0066 — 그 달에 검토 완료한 업무 작업의 만들기~검토 완료 시간, 기다린 시간도 들어 있어 작업 시간이 아니다, 완료 작업이 없으면 '—'). 만족도는 2026-11-05부터 답변 평가(0064 `message_feedback` — 답변마다 '도움됨 / 아쉬움'과 정해 둔 이유)로 모으고, 관리자 통계의 '답변 평가' 표가 비서별로 보인다(이 보고서의 숫자에는 아직 넣지 않았다). 2026-11-10부터 '도움됨'을 누른 직원이 **이 답으로 줄인 시간**을 고를 수 있고(10분·30분·1시간·2시간·반나절, 선택 — 0082 `message_feedback.saved_minutes`, 1~480분·도움됨에만 CHECK), '답변 평가' 표가 비서별·전체 합과 고른 답 수를 '줄인 시간(자기 신고)'으로 보인다(`summarizeFeedback`). **직원이 스스로 고른 값이고 측정·추정이 아니다** — 화면에도 그렇게 적는다. 이 월별 보고서·CSV·기관 통계 API에는 아직 싣지 않았다.
- 부서별로 쪼갠 표는 2026-11-06에 넣었다(0065 `adoption_by_department` — 보고서 아래 '부서별 보기', 부서마다 자기 부서 기록만·하위 부서를 올려 더하지 않음·사람은 지금 소속 부서로, 등록·쓴·4일 이상 쓴 직원·질문·앱 실행·만든 파일·업무 작업 완료·사용 금액, 합계 줄·CSV). 전월 대비·재작업 지표는 부서별로 내지 않는다. PDF·한글 보고서 꼴은 없다(CSV만).
- 등록 직원은 '지금' 기준이라 전월 칸이 그때 숫자와 다를 수 있다.
- 화면은 브라우저로 보지 않았다.

## 함께 알게 된 것

기존 이용통계(`/api/admin/usage-summary`)는 사용 기록을 앱으로 **한도 없이** 읽는다. Supabase API의 기본 행 상한(1,000행)에 걸리면 기간 합계를 **덜 셀 수 있다.** 이 보고서는 DB 집계라 영향이 없다. 이용통계는 따로 고쳐야 한다.
