## 폐쇄망 설명의 불일치

[데스크톱 소개](https://www.allganize.ai/ko/products/alli-works-agent)는 로컬·온프레미스 구성과 SaaS 연결을 구분한다. 비교표는 온프레미스의 외부 통신 차단을 설명한다.

그러나 같은 페이지에서 인터넷 관련 FAQ를 직접 펼치면, 생성 코드 실행 중의 네트워크 차단을 설명한 다음 **답변 생성과 문서 검색에는 인터넷 연결이 필요하다**고 안내한다. 이는 배포별 조건을 생략한 설명일 수 있지만, 현재 공개 내용만으로 완전 오프라인 동작을 확정할 수 없다. 생성 코드의 샌드박스 네트워크 차단과 서비스 전체의 폐쇄망 운영은 서로 다른 범위다.

우리 ReadLayer의 자체 호스팅 가능성도 WORKON 전체의 폐쇄망 가능성을 자동 입증하지 않는다. 모델·임베딩·OCR·인증·저장소 등 실제 호출 경로의 내부 구성이 필요하다. 이번 SaaS 구현 범위는 바꾸지 않는다.

## 구현에 반영할 우선순위

1. **앱 설정과 실행 연결:** 기존 에이전트의 역할·자료 범위·모델·버전을 작업 생성 시 고정하고 실행에서 사용한다. 현재 가장 큰 공백이다.
2. **문서 기반 3개 업무를 끝까지 완성:** 규정 질의, 민원 회신 초안, 보고서 작성. 입력 → 근거 → 초안 → 검토 → 파일 산출을 확인한다.
3. **공통 실행 기능 확장:** 텍스트·근거 검색·구조화 추출·결정적 계산·다단계 조사·파일 처리의 6개 계열로 공개 앱 100개를 흡수한다. 세부 대응은 APP_IMPLEMENTATION_MAP.md를 따른다.
4. **실행 이력과 재현성:** 앱 버전, 입력 자료 버전, 단계별 상태, 오류·재시도, 검토자, 최종 산출물을 남긴다.
5. 연결 도구·예약·대량 병렬 처리는 위 세 업무의 결과 품질을 확인한 뒤 추가한다.

## 미확인·실패와 재현 자료

인증된 SaaS 앱 생성·복제·배포·권한 비교·예약·실제 파일 생성·실패 복구는 수행하지 않았다. 공개 마켓 검색 입력은 관찰했지만 검색 실행 후 결과는 검증하지 못했다. 후속 검색 시 CDP 대상이 사라져 도구가 target_unavailable을 반환했으며, 재탐색에서도 허용 origin의 대상이 없어 성공으로 기록하지 않았다.

통신 본문·헤더 값·스토리지 값 수집은 요청하지 않았다. 별도 공개 프로필을 사용했으며 로그인·계정 생성·상담 제출은 하지 않았다. 각 관찰 창 밖의 통신과 서버 내부 동작은 미확인이다.
