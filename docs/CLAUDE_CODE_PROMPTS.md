# Claude Code 시작 프롬프트

아래 프롬프트를 Claude Code의 첫 메시지로 붙여 넣어 사용할 수 있다. 작업마다 `<이번 목표>`만 바꾼다.

## 1. 기본 작업 프롬프트

```text
이 저장소는 WORKON이다. 먼저 CLAUDE.md와 docs/CLAUDE_CODE_HANDOFF.md를 읽고, git status --short와 git diff --stat으로 현재 작업 트리를 확인해라.

중요 규칙:
- 현재 미커밋 변경과 미추적 파일은 사용자의 기존 작업이다. reset, clean, 일괄 checkout, 임의 삭제를 하지 마라.
- 오래된 문서의 완료/미완료 표시를 그대로 믿지 말고 실제 코드, 최신 운영 기록, 테스트 결과를 대조해라.
- 기관/부서 멀티테넌트 범위, 인증, 파일 권한, 사용량 기록을 변경마다 확인해라.
- 비밀값과 .env.local 내용을 출력하거나 문서/커밋에 넣지 마라.
- 구현 전 관련 코드와 테스트를 읽고, 최소 범위로 수정한 뒤 관련 테스트→타입 검사→가능하면 전체 테스트/빌드 순으로 검증해라.
- 실패한 검사를 숨기지 말고 정확한 오류와 미검증 범위를 보고해라.
- DB 마이그레이션 적용, 비용이 드는 실제 모델 시험, 운영 배포, 커밋/푸시는 내가 명시적으로 요청할 때만 해라.

이번 목표: <이번 목표>

먼저 목표와 관련된 현재 구현, 겹치는 미커밋 변경, 위험, 검증 계획을 5~10줄로 요약한 뒤 작업을 시작해라. 질문 없이 안전하게 판단할 수 있으면 바로 진행하고, 결과가 달라지는 필수 선택만 질문해라.
```

## 2. 현재 작업 트리 안정화 프롬프트

```text
CLAUDE.md와 docs/CLAUDE_CODE_HANDOFF.md를 읽어라. 현재 대규모 미커밋 작업을 보존하면서 검증 기준선을 복구해라.

1. git status/diff로 변경을 앱 플랫폼, 업무 엔진, UI, 마이그레이션, 테스트, 문서 묶음으로 분류해라.
2. tests/app-copy.test.ts의 Agent.template_ids 타입 오류를 실제 도메인 모델과 마이그레이션을 대조해 원인부터 설명해라.
3. any나 ts-ignore로 숨기지 말고 최소 수정해라.
4. 관련 테스트와 tsc를 통과시켜라.
5. 전체 테스트는 메모리 상황을 고려해 파일 단위부터 실행하고, 마지막에 전체 실행을 시도해라.
6. 변경하지 않은 기존 파일은 건드리지 마라.

커밋/배포/DB 적용은 하지 말고, 끝에 변경 파일, 검사 결과, 아직 미검증인 항목을 보고해라.
```

## 3. 로그인 브라우저 UAT 프롬프트

```text
docs/CLAUDE_CODE_HANDOFF.md와 docs/benchmarks/allganize/PRODUCTION_DEPLOYMENT.md를 읽고, 앱 플랫폼의 로그인 사용자 UAT를 준비하고 실행해라.

대상 흐름:
- 앱 목록 탐색·즐겨찾기·새로고침 유지
- 입력형 앱 생성과 버전 저장
- 텍스트/파일 입력 실행
- 1~3단계와 선택 조건 양쪽 경로
- 실패 기록 수동 재개
- 실행 이력 재열기
- HWPX 내보내기·다운로드·한글 열기

직원 본인, 같은 기관 타인, 다른 기관, 기관 관리자 권한을 구분해라. HTTP 200이나 CSS 확인을 화면 검증으로 간주하지 마라. 시험 데이터와 삭제/정리 계획을 먼저 제시하고, 운영 상태를 변경하거나 비용이 발생하는 단계는 실행 전에 승인을 받아라. 발견한 문제는 재현 단계, 기대/실제 결과, 증거, 영향으로 기록해라.
```

## 4. HWPX 양식 기능 작업 프롬프트

```text
WORKON의 HWPX 기능을 수정한다. CLAUDE.md의 문서 만들기/업무 작업 절과 docs/CLAUDE_CODE_HANDOFF.md를 먼저 읽고, src/lib/hwp.ts, src/lib/doc-fill/, src/lib/work/documents/, assets/templates/, 관련 테스트를 확인해라.

목표: <양식 기능 목표>

원칙:
- AI는 XML을 직접 만들지 않고 구조화된 값만 만든다.
- 원본 서식 보존, XML 이스케이프, ZIP 경로 안전, 압축 폭탄/DOCTYPE/매크로 검사를 유지한다.
- 단순 패키지 성공과 실제 한글 호환 검증을 구분한다.
- 기존 HWP는 제한된 읽기/대체 경로이고 HWPX가 주 생성 형식이다.
- 실제 양식 fixture와 손상 파일, 긴 글, 표, 빈 필드 테스트를 추가한다.

관련 단위 테스트와 work:template-check를 실행하고, Windows 한글 검증이 필요하지만 실행하지 못했으면 명시해라.
```

반드시 포함할 것:
