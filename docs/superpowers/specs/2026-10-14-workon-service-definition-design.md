## 1. 한 줄 정의

**공공기관 직원이 매일 하는 문서 업무를 돕고 자동화하는 독립 서비스.**
첫 고객은 지방공기업과 협회·재단이고, 연간 정액으로 판매하며, SaaS로 시작해 국내 클라우드와
온프레미스(사내망)로 옮길 수 있게 짓는다.

## 4. 비서와 능력

### 4.1 비서 하나에 들어가는 것

| 항목 | 내용 | 지금 |
|---|---|---|
| 이름 · 설명 · 아이콘 · 사용 방법 · 시작 예시 | 직원에게 보이는 정보 | 있음 |
| 지시문 + 요술봉 | 역할을 한 번만 정해 둔다 | 있음 |
| 모델 | 기관이 허용한 모델 안에서 비서마다 고른다 | 새로 |
| 참고 문서 | 이 비서가 근거로 삼는 문서 | 있음 → NODA로 |
| 양식 파일 | 결과를 채울 기관 서식 (HWP · HWPX · DOCX) | 새로 |
| 능력 | 이 비서가 할 수 있는 일 (4.2) | 새로 |

### 4.2 능력

능력은 켜고 끄는 단위다. **능력을 켠다는 것은 그 도구를 비서에게 꺼내 준다는 뜻**이다(7절).

| 능력 | 하는 일 | 부품 |
|---|---|---|
| 참고 문서 찾기 | 연결된 문서와 공통 자료실에서 근거를 찾아 출처(쪽)와 함께 답한다 | NODA |
| 공공데이터 조회 | 법령·자치법규·통계·입찰·공시를 실시간 조회 | 커넥터 (있음) |
| 파일 받아 읽기 | 대화 중에 한글·PDF·엑셀을 여러 개 첨부받는다 | NODA |
| 표 합치기·집계 | 여러 파일의 표를 기준에 맞춰 합치고 더한다 | 표 계산 엔진 (새로) |
| 양식 채우기 | 양식의 목차를 읽고 항목별로 초안을 채운다 | NODA + 한글 생성기 (새로) |
| 파일로 내보내기 | 결과를 한글(HWPX)·엑셀로 내려받는다 | 한글·엑셀 생성기 (새로) |
| 사진 읽기 | 캡처·사진 | 있음 |

**숫자는 AI가 계산하지 않는다.** AI는 "어느 열을 어떤 기준으로 합칠지"만 정하고, 더하기는 프로그램이 한다.
AI는 계산을 틀릴 수 있고, 공공기관 자료에서 합계가 틀리는 것은 치명적이다.
답변 속 숫자는 NODA의 검증으로 원본·계산 결과에 있는 값인지 한 번 더 확인한다.

### 4.3 비서 단계

| 단계 | 만드는 사람 | 보이는 범위 | 승인 |
|---|---|---|---|
| 나만의 비서 | 본인 | 본인 | 없음 |
| 부서 비서 | 부서원 누구나 + 관리자 | 그 부서와 하위 부서 | **없음.** 누가 언제 무엇을 바꿨는지 기록하고 이전 판으로 되돌릴 수 있다 |
| 공식 비서 | 관리자, 또는 사용자 신청 → 관리자 승인 | 기관 전체, 또는 관리자가 지정한 부서 | 노출 대기 → 검수 → 노출 |

부서 비서와 부서로 좁힌 공식 비서는 **누가 고치느냐**로 갈린다. 부서 비서는 부서원이 함께 고치고, 공식 비서는 관리자만 고친다.

부서 비서에 승인을 두지 않는 이유: 승인 단계가 끼면 쓰기 불편해져 결국 아무도 만들지 않는다.
영향은 그 부서 안으로 한정되고, 변경 기록과 되돌리기로 책임 소재가 남는다.

공식 비서가 되면 지시문·도구 설정·참고 문서 내용은 공유되고, 만든 사람의 대화 기록과 원본 파일 다운로드는 공유되지 않는다.

### 4.4 핵심 업무와 기본 비서

첫 고객용 기본 비서로 미리 깔아 둔다. 기관과 직원은 그대로 쓰거나 고쳐서 단계를 넓힌다.

| 업무 | 기본 비서 | 켜는 능력 |
|---|---|---|
| ① 공문 | 공문 작성 비서 — 표준 기안문 서식 | 양식 채우기 · 한글로 내보내기 · 참고 문서 찾기 |
| ① 보고서·계획서 | 기관 양식 작성 비서 — 기관이 양식을 올림 | 양식 채우기 · 한글로 내보내기 |
| ② 규정·법령 | 규정 안내 비서 — 기관 규정 + 공통 자료실 | 참고 문서 찾기 · 공공데이터 조회(법령) |
| ⑦ 자료 취합 | 자료 취합 비서 | 파일 받아 읽기 · 표 합치기 · 엑셀/한글로 내보내기 |
| ⑦ 회의록 | 회의록 비서 — 기관 회의록 양식 | 양식 채우기 · 한글로 내보내기 |

## 5. 공통 자료실

### 5.1 무엇을 넣나

기관 유형마다 **모든 기관이 똑같이 쓰는 기준·지침·편람**을 넣는다.
법령은 법령 커넥터로 실시간 조회하므로 넣지 않는다. 법령 DB에 없는 정부 기준 문서가 대상이다.

| 유형 | 예 |
|---|---|
| 지방공기업 | 예산편성기준 · 회계기준 · 경영평가 편람 · 인사·보수 운영 기준 |
| 협회·재단 | 보조금 관리 지침 · 보조사업 정산 안내 · e나라도움 사용 안내 |

실제 목록은 첫 고객과 확인해서 정한다.

### 5.2 동작

| 항목 | 설계 |
|---|---|
| 넣는 사람 | 운영자 (슈퍼관리자 화면) |
| 보이는 범위 | 그 유형의 모든 기관 |
| 저장 | NODA에 유형별 공용 보관함 하나. 질문하면 기관 보관함과 공용 보관함을 함께 찾고, 출처에 `[기관]` · `[공통]`을 붙인다 |
| 판 | 문서마다 기준 연도를 붙이고 답에 밝힌다 (예: 예산편성기준(2026) 12쪽). 새 판이 들어오면 옛 판은 "지난 판"으로 표시하고 검색에서 뺀다 |
| 충돌 | 기관 규정과 공통 기준이 다르면 **둘 다** 보여준다. 어느 쪽이 우선인지는 직원이 판단한다 |
| 운영 | 연간 갱신 일정표를 둔다. 넣기 전에 문서마다 이용 조건을 확인하고 바꾼 기록을 남긴다 |

| | 지금 | 이후 |
|---|---|---|
| 문서 원본 | Supabase에 저장 | 그대로 |

## 7. 전체 구조

```
┌──────────────────────── WORKON ────────────────────────┐
│  화면 (직원 · 기관 관리자 · 운영자)                        │
├────────────────────────────────────────────────────────┤
│  비서 층 ─ 나만의·부서·공식 · 모델 · 능력 · 양식 · 변경 기록   │  재편
├────────────────────────────────────────────────────────┤
│  대화 실행기 ─ 비서 하나의 한 턴을 처리하는 단일 엔진          │  재편
│     │  켜진 능력만 도구로 꺼내 쓴다                         │
│     ├─ 문서 찾기 ─┐                                      │
│     ├─ 파일 읽기 ─┼─▶ NODA (국내 · 읽기·검색·검증)          │  교체
│     ├─ 양식 채우기 ┘                                     │
│     ├─ 표 합치기 ──▶ 표 계산 엔진                          │  새로
│     ├─ 내보내기 ───▶ 한글(HWPX)·엑셀 생성기                │  새로
│     └─ 공공데이터 ─▶ 커넥터                                │  유지
│  AI 연결부 ─ 모델 호출을 한 곳으로 (지금은 Claude)           │  새로
├────────────────────────────────────────────────────────┤
│  기반 ─ 기관·부서·권한·격리 · 한도·IP · 감사 · 브랜딩 · 통계  │  유지
└────────────────────────────────────────────────────────┘
```

### 7.1 능력은 비서가 쓰는 도구다

지금 WORKON에는 AI가 필요할 때 법령 커넥터를 도구로 불러 쓰는 장치가 있다. 새 능력도 같은 장치로 만든다.
AI는 무엇을 할지 판단하고, 실제 작업은 도구가 한다. 장치가 하나라 능력을 더할 때 대화 실행기를 고치지 않는다.

### 7.2 흐름 예시 — 자료 취합

```
직원: 부서 엑셀 3개 첨부 + "부서별로 합쳐서 엑셀로 줘"
 → 파일 읽기:  NODA가 세 파일의 표를 읽는다
 → AI 판단:    "부서 기준 병합, 금액 합계"
 → 표 합치기:  표 계산 엔진이 계산한다
 → 내보내기:   엑셀 파일을 만들어 대화에 내려받기 링크를 붙인다
 → 검증:       답변 속 숫자가 원본·계산 결과에 있는지 확인한다
```

### 7.3 기존 코드의 처리

| 구분 | 대상 |
|---|---|
| 유지 | 인증 · 기관/부서/사용자 · 권한·격리 · 한도·IP · 감사·보안 로그 · 브랜딩 · 모델 정책 · 통계 · 슈퍼관리자 · 커넥터 · 테스트 |
| 재편 | 비서 구조 (부서 단계·모델·능력·양식·변경 기록) · 대화 처리 (실행기 하나로) |
| 교체 | 문서 처리 → NODA. 자체 파서·Voyage·벡터 검색은 걷어낸다 |
| 새로 | 표 계산 엔진 · 한글/엑셀 생성기 · AI 연결부 · 공통 자료실 · 생성 파일 보관 |

### 7.4 옮길 수 있게 짓기

| 지금 기대는 곳 | 바꾸는 방향 |
|---|---|
| Vercel | 일반 서버(Docker)에서도 그대로 돈다. Vercel 전용 기능은 쓰지 않는다 |
| Supabase DB | 표준 PostgreSQL 기능만 쓴다 |
| Supabase 파일 저장 | 저장소 연결부를 두어 국내 클라우드·기관 디스크로 바꿀 수 있게 한다 |
| Claude | AI 연결부 하나로 모은다. 나중에 기관 내부 모델로 바꿀 자리다 |
| 메일 (Resend) | 메일 연결부를 두어 기관 메일 서버로 바꿀 수 있게 한다 |

### 7.5 실패할 때의 원칙

- 조용히 빈손을 주지 않는다. NODA가 멈추거나, 양식을 못 읽거나, 표를 못 합치면 그 이유를 화면에 보여준다
- 한 능력이 실패해도 대화는 계속된다. 파일 생성이 실패하면 텍스트 결과라도 남긴다
- 권한·한도 판정은 서버에서 한다. 화면의 제한은 표시일 뿐이다

### 7.6 검증

- 표 계산 엔진은 입력과 기대 결과를 짝지은 테스트로 고정한다
- 한글 생성기는 만든 파일을 NODA로 다시 읽어 내용이 그대로인지 확인한다
- 기존 테스트(권한 전수 검사·한도 규약 전수 검사 등)는 그대로 유지하고 새 라우트에도 적용된다

## 8. 운영

### 8.1 역할

| 역할 | 하는 일 |
|---|---|
| 운영자 (슈퍼관리자) | 기관 등록과 계약 · 공통 자료실 갱신 · 기본 비서 세트 관리 · 시스템 감시와 장애 대응 · 보안 심사용 자료 |
| 기관 관리자 | 기관 정보·로고·IP·허용 모델 · 부서·사용자 등록 · 부서·개인 한도 배분 · 공식 비서 검수와 노출 · 기관 규정 문서 · 사용량·감사 조회 |
| 직원 | 비서 사용 · 나만의·부서 비서 만들기 · 공식 등록 신청 |

### 8.2 기관 도입 흐름 — 목표는 첫날부터 쓰는 것

```
1. 계약 (연간 금액·기간)
2. 운영자가 기관 등록 → 유형 선택 (지방공기업 / 협회·재단)
   → 기본 비서 5종과 그 유형의 공통 자료실이 자동 연결된다
3. 기관 관리자 초대 → 로고·로그인 주소·IP·허용 모델 설정
4. 부서·사용자 일괄 등록 (CSV) → 부서·개인 한도 배분
5. 기관 규정 (보수·복무·위임전결 등) 올리기 → 규정 안내 비서가 기관 규정으로 답한다
6. 직원 사용법 안내 → 시작
```

### 8.3 예산 (연간 정액)

| 항목 | 운영 |
|---|---|
| 한도 | 계약 금액이 연간 한도. 쓸 때마다 차감 |
| 경고 | 소진율 80%에 기관 관리자·운영자에게 알림 |
| 소진 | 100%면 멈춤 → 증액 계약 |
| 보고 | 분기 집행률 보고용 사용량 자료 (CSV) |

월 청구서 생성은 필요 없다. 지금 코드의 종량제 경로는 새로 손대지 않는다.

### 8.4 감시

| 대상 | 이유 |
|---|---|
| NODA 상태 (뜻 검색 켜짐 포함) | NODA가 유일한 문서 검색이라 멈추면 전체가 멈춘다 |
| DB 상태 | 2026-10-14 주에 무료 플랜 비활성 정지로 실제로 멈췄다 |
| AI 호출 실패율 · 한도에 다다른 기관 | 직원 불편이 생기기 전에 알기 위해 |

장애 때는 이미 있는 공지 배너와 점검 모드를 쓴다.

### 8.5 데이터와 보안

| 항목 | 운영 |
|---|---|
| 계약 종료 | 그 기관의 대화·문서·생성 파일을 DB·파일 저장소·NODA 색인·NODA 캐시에서 모두 지우고 파기 확인서를 발급한다 |
| 생성 파일 | 보관 기간을 정해 두고 지나면 자동 삭제한다 |
| 보안 심사 자료 | 데이터 흐름도(6절) · 위탁 관계도 (Anthropic · NODA 서버 · DB 서버) |

### 8.6 운영 단계 전환

| 전환 | 계기 |
|---|---|
| SaaS → 국내 클라우드 | 첫 조달 계약, 또는 기관이 CSAP를 요구할 때 |
| → 온프레미스 (사내망) | 기관이 설치형을 요구하고 그 계약이 될 때 |

폐쇄망(인터넷 없음)은 기관 안에 AI 모델을 따로 설치해야 해서 이 정의서의 범위 밖이다.

## 9. 하위 과제와 순서

각 과제는 따로 설계 → 계획 → 구현을 돈다.

| # | 과제 | 담는 것 | 기대는 것 |
|---|---|---|---|
| S1 | 비서 구조와 대화 실행기 | 부서 단계 (공동 편집 · 변경 기록 · 되돌리기) · 비서마다 모델 · 능력 장치 · 양식 파일 자리 · 대화 실행기 통합 · AI 연결부 | 없음 — 모든 과제의 바탕 |
| S2 | 한글 생성기와 양식 채우기 | HWPX 생성기 · 양식 목차 읽기 · 항목별 초안 · 한글로 내보내기 · 회의록 강화 | S1 |
| S3 | 파일 읽기와 표 합치기 | 대화 중 파일 여러 개 첨부 · 표 계산 엔진 · 엑셀로 내보내기 · 숫자 검증 | S1 |
| S4 | 문서 층을 NODA로 교체 | 업로드 → NODA · 문서 찾기 능력 · 비서별 범위 (ACL) · 답변 검증 · 근거 위치 표시 · Voyage·자체 파서 제거 · 기존 문서 옮기기 | S1 + NODA 쪽 작업 (10절) |
| S5 | 공통 자료실 | 운영자 화면 · 유형별 공용 보관함 · 판 관리 · 출처 `[공통]` 표시 | S4 |
| S6 | 기본 비서와 도입 흐름 | 기본 비서 5종 · 기관 등록 시 자동 연결 · 첫날 쓰기 흐름 점검 | S2 · S3 · S5 |
| S7 | 옮길 준비 | Docker 실행 · 파일 저장소·메일 연결부 · Vercel 종속 제거 | 국내 클라우드 이전 전까지 |

S2·S3이 쓰는 NODA 파일 읽기는 보관이 필요 없는 기능이라 지금도 쓸 수 있다.

```
S1 비서 구조·실행기
 ├─▶ S2 한글 생성·양식 채우기   (① 공문·보고서 · ⑦ 회의록)
 └─▶ S3 파일 읽기·표 합치기     (⑦ 자료 취합)
S4 NODA 교체   ◀── NODA 쪽 작업이 끝나면 (S2·S3와 나란히)
 └─▶ S5 공통 자료실             (② 규정·법령)
S2 + S3 + S5 ─▶ S6 기본 비서·도입 흐름 ─▶ 첫 고객 시범
S7 옮길 준비 ── 나란히, 국내 클라우드 이전 전 완료
```

S2를 S3보다 앞에 두는 이유: 한글 생성은 ① 공문·보고서와 ⑦ 회의록 두 곳에 쓰이고 경쟁 서비스 대비 가장 큰 차별점이다.
② 규정 찾기는 S4 전까지 지금 구조로 동작한다.

새로 만드는 12개 기능(3절 🆕)의 배치: S1 — 부서 단계 · 비서별 모델 / S2 — 양식 채우기 · 파일로 내보내기 · 회의록 강화 /
S3 — 파일 여러 개 읽기 · 표 합치기 / S4 — 참고 문서 교체 · 근거 위치 · 답변 검증 · 문서 국내 처리 / S5 — 공통 자료실.
