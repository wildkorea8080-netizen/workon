# 시민용 민원 상담 창 — 설계

2026-11-27, 사용자와 정함("별도 주소+홈페이지 붙이기" → 운영 규칙 "이대로 설계해 주세요").

## 의도와 왜
공공기관·지방공기업 직원은 시민의 같은 질문(대관 신청·환불 규정·이용 시간·서류)에 반복해서 답한다. 시민이 로그인 없이 기관에 묻고, **기관이 시민에게 공개해도 된다고 정한 문서만** 근거로 답을 받게 해 직원의 반복 응대를 줄인다. 직원용 WORKON은 로그인한 직원만 쓰므로 시민 창구가 없었다(기관 API로 기관이 직접 만들 수는 있었지만 바로 붙일 창은 없었다).

## 목표
1. **별도 주소** `/ask/{기관 slug}` — 로그인 없이 열리는 상담 화면(기관 로고·이름·테마 색, 안내 문구, 자주 묻는 질문 단추, 질문·답, 근거 표시, 담당 연락처).
2. **홈페이지 붙이기** — 관리자 화면이 붙일 코드(스크립트 한 줄)를 준다. 기관 홈페이지 오른쪽 아래에 상담 단추가 생기고 누르면 같은 화면이 작은 창(iframe)으로 뜬다.
3. **답하는 비서 — 시민 전용 비서를 따로**(사용자 결정 2026-11-27) — 기관 전체 관리자가 '시민 상담' 화면에서 **시민 전용 비서**를 만든다(기관에 하나, 최상위 부서 소속, `agents.audience = 'public'` — 새 칸, 기본 `'staff'`). 이 비서는 **직원 화면의 비서 목록·대화·앱·기관 API에 나오지 않고**(직원이 쓰지 못함), 설정·문서 올리기·지우기는 **기관 전체 관리자만**(관리자 시민 상담 화면에서). 그래서 직원이 내부 문서를 실수로 올려 시민에게 새어 나갈 길이 없다. 그 비서의 문서함(+ 기관 유형 공통 자료실)만 근거로, 직원 대화와 같은 찾기·인용 규칙(`prepareLikeChat`)으로 답한다.
4. **모르면** — 근거가 없으면 지어내지 않고 "문서에서 찾지 못했습니다 — 담당 부서로 문의해 주세요"와 관리자가 적은 **부서별 연락처**(이름·전화·안내, 10개까지)를 보인다.
5. **비용 막기** — 같은 IP 하루 20번, 기관 전체 하루 500번(둘 다 관리자가 1~100·1~5,000 안에서 바꿈, 한국 날짜 기준). 넘으면 "오늘은 마감"을 안내하고 모델을 부르지 않는다. 기관 월 한도·정지·종료(`checkTokenLimit`의 기관 판정)도 그대로 — 막히면 안내만.
6. **개인정보** — 질문은 직원 대화와 같은 `filterUserInput`(주민번호·카드·휴대전화·기관 금지어)을 거친다. 걸리면 "개인정보는 적지 마세요"로 거절하고 모델을 부르지 않는다.
7. **기록** — 질문·답·근거 제목·결과(답함·근거 없음·거절·마감)를 **30일** 보관하고 지난 것은 5분 실행기가 지운다. IP는 해시만. 관리자는 '시민 상담' 화면에서 최근 질문 목록(기간·근거 없음만 거르기)을 본다 — 문서를 보강하려는 것.
8. **켜고 끄기** — 기관 전체 관리자만 켠다(사유·보안 로그 high). 기본 꺼짐. 꺼지면 주소·붙인 창이 바로 "운영하지 않음"으로 닫힌다. 점검 모드면 닫힌다.
9. **사용 기록·과금** — 모델 호출은 `usage_logs`(action `public_ask`, 시민 전용 비서의 부서, user_id 없음, model·토큰·원가)로 남겨 **기관** 사용량·예산(월 토큰·연간 정액)에 들어간다. **부서 월 한도·부서 사용액에서는 뺀다**(구현자 판단 — 시민 질문이 그 부서 직원의 사용을 막지 않게, `department_spend_krw`가 `public_ask`를 세지 않게). 시민 길의 한도 판정도 기관 단위만 본다.

## 하지 않음
실제 민원 접수(번호 발급·처리 상태 조회), 담당자 연결 채팅, 카카오톡 연결, 첨부·사진, 법령 조회(운영에서 막혀 있음 — 기관 문서만), 시민 로그인·본인 확인, 여러 기관을 한 창에서.

## 반목표(이러면 실패)
- 내부 문서가 시민에게 새어 나감(시민 전용 비서 밖 문서가 근거로 나옴, 직원이 시민 전용 비서에 문서를 넣음).
- 로그인 없는 창이 기관 예산을 태움(한도가 우회됨).
- 근거 없는 답을 근거 있는 것처럼 냄.
- 시민의 개인정보가 기록에 남음.

## 제약
- 서비스 키로만 DB를 쓴다(RLS 켜고 정책 없음). 새 표는 RLS를 켜고 공개 키 권한을 주지 않는다.
- 공개 라우트는 `route-auth.test.ts`의 공개 목록에 **이유와 함께** 적는다. 미들웨어의 로그인·기관 접속 허용 IP 검사에서 `/ask/*`·`/api/ask/*`를 뺀다(시민은 기관 IP가 아니다). 점검 모드는 그대로 적용.
- 공개 응답에 비서 id·문서 id·저장소 경로·내부 원문(근거 발췌 전체)을 싣지 않는다 — 근거는 문서 제목·위치(쪽)만.
- 시민 전용 비서가 지워졌거나 문서가 하나도 읽히지 않았으면 창은 '준비 중'으로 답한다(조용히 다른 비서로 넘어가지 않음).
- 기존 직원 대화·기관 API 동작은 바꾸지 않는다.

## 방법(정한 것)
- **고른 길**: 직원 대화의 무거운 실행기(`prepareTurn`/`streamTurn` — 대화·메시지·첨부·사용자 행이 필요)를 쓰지 않고, 이미 '사용자 없이' 쓰는 가벼운 길을 엮는다 — `prepareLikeChat`(찾기 + 시스템 프롬프트 덧붙임) → `src/lib/llm`의 `streamChat`(시민 전용 비서의 모델·지시문) → 숫자 확인(`checkNumbers`류) → 새 표에 기록. 답은 SSE로 흘려 보낸다.
- 버린 길: ① 기관 API(`/api/v1/chat`)를 화면에서 부르기 — 키를 브라우저에 실을 수 없고 대화가 관리자 계정에 쌓인다. ② 시민마다 가짜 사용자 계정 — 인원 상한·감사·탈퇴 처리와 얽힌다.
- **대화 이어 묻기**: 브라우저가 이 화면에서 한 앞 질문 하나만 보내 '앞 질문과 묶어 다시 찾기'(`previousQuestion`)에 쓴다. 서버는 시민 대화를 이어 보관하지 않는다(로그는 질문마다 한 줄).
- **설정 저장**: 새 표 `public_ask_settings`(기관마다 한 행 — 켜짐·켠 때·사유, 시민 전용 비서 id, 허용 홈페이지 주소, 안내 문구 500자, 자주 묻는 질문 5개×60자, 부서 연락처 10개, IP 하루 상한, 기관 하루 상한). 기록은 `public_ask_logs`(기관·시각·IP 해시·질문 1,000자·답 8,000자·근거 제목 목록·결과·토큰). 하루 횟수는 이 표를 세서 정한다(조건부 — 기관마다 advisory lock 함수 하나로 '세고 넣기'를 원자적으로).
- **붙이는 코드**: `/ask/embed.js?org={slug}` — 단추·iframe만 그리는 작은 스크립트(외부 라이브러리 없음). **지금 `vercel.json`이 모든 주소에 `X-Frame-Options: DENY`를 건다** — `/ask/*`만 이 머리글에서 빼고, 대신 그 기관 설정의 **허용 홈페이지 주소**(https 도메인 5개까지, 비우면 붙이기 불가·별도 주소만)로 `Content-Security-Policy: frame-ancestors`를 화면 응답에 건다(구현자 판단: 아무 사이트나 끼우게 두지 않음). 직원 화면은 그대로 DENY.

## 검토에서 정한 것(구현자 판단 — 사용자가 고칠 수 있음)
- **확인 못 하면 닫힘**: 시민 길은 기관 한도·하루 횟수·금지어를 읽지 못하면 묻지 않고 '잠시 뒤 다시'로 답한다(직원 길의 '못 읽으면 허용'을 쓰지 않음 — 로그인 없는 창이라).
- **거절·마감 기록**: 개인정보로 거절한 질문과 마감으로 막힌 질문은 **질문 글을 남기지 않고** 결과·시각·IP 해시만. 모든 시도가 IP 하루 상한에 세어지고(남용 막기), 기관 하루 상한은 모델을 부른 질문만 센다.
- **기록 열람**: 시민 질문 기록은 설정과 같이 **기관 전체 관리자만** 본다(부서에 속하지 않는 기록).

## 만드는 사람에게 맡김
화면 세부 모양(직원 화면 청록 체계·기관 테마 색), 스트리밍 이벤트 이름, 관리자 화면 위치(기관 정보 아래 새 패널 또는 새 메뉴 '시민 상담'), 30일 정리를 5분 실행기의 어느 자리에 끼울지, 자주 묻는 질문 단추가 바로 보내는지 입력창에 넣는지.
