# S2 설계 — 한글 생성기와 양식 채우기

**작성일**: 2026-10-15
**선행**: S1(비서 단계·대화 실행기·편집 화면) 배포 완료
**상위 문서**: `docs/superpowers/specs/2026-10-14-workon-service-definition-design.md` (9절 S2 · 4.2 능력 · 6 데이터 흐름 · 7.5 실패 원칙)

S2는 비서가 **결과를 한글(HWPX) 파일로** 주게 한다. 두 가지가 같은 장치로 된다.

- 기관이 올린 양식에 내용을 채워 돌려준다 (① 공문·보고서·계획서)
- 양식이 없으면 WORKON 표준 서식으로 만든다 (① 공문 · ⑦ 회의록)

---

## 1. 결정

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| 1 | 양식 채우기의 결과물 | **기관 양식 원본에 채우기를 기본으로, 못 채우면 표준 서식으로 대신** | 공공기관은 서식을 지키는 것이 중요하고 경쟁 서비스와의 가장 큰 차이다. 옛 HWP(이진)는 직접 쓸 수 없으므로 대체 경로가 필요하다 |
| 2 | 작성 흐름 | **대화 안에서** — 양식 → 목차 확인 → 초안 → 파일 | 지금 대화 실행기·도구 구조를 그대로 쓴다. 최종 손질은 한글에서 한다. 별도 작성 화면은 쓰임을 본 뒤 정한다 |
| 3 | 채울 자리 찾기 | **`{{…}}` 표시가 있으면 따르고, 없으면 자동으로 찾는다** | 표시 강제는 도입을 번거롭게 한다. 자동 찾기의 오류는 목차 확인 단계에서 걸러진다 |
| 4 | 생성 파일 보관 | **대화와 함께 — 대화를 지우면 파일도 지운다** | 파일만 따로 사라지면 혼란스럽다. 보관 기간은 나중에 정하면 대화·파일에 같이 적용한다 |
| 5 | 구현 방식 | **채우기 엔진 하나.** 표준 서식 = WORKON에 들어 있는 기본 양식 | 엔진이 하나라 고칠 곳도 하나다. 코드로 HWPX를 처음부터 조립하면 한글에서 깨질 위험이 크다. 외부 변환기는 새 바이너리·새 처리 경로라 제외 |

## 2. 구조

```
대화 실행기 (S1-b)
 └─ 능력 '문서 만들기' (document)
     ├─ list_templates   쓸 수 있는 양식 목록 (비서 양식 + 기본 양식)
     ├─ read_template    양식 하나의 채울 자리(목차)
     └─ fill_template    자리별 내용 → 파일 → 내려받기 링크
             │
             ▼
     src/lib/doc-fill/
       ├─ slots.ts   자리 찾기 규칙 (표시 · 항목 · 표 칸 · 자리 표시 글자)
       ├─ hwpx.ts    HWPX 읽기·쓰기
       ├─ docx.ts    DOCX 읽기·쓰기          (S2-b)
       ├─ fallback.ts 못 채우는 양식 → 기본 보고서   (S2-b)
       └─ index.ts   형식 고르기 · 상한 · 결과 정리
             │
             ▼
     src/lib/generated-files.ts  보관·조회·삭제
     GET /api/files/[id]         내려받기 (주인만, 서명 주소로 넘김)
```

| 파일 | 책임 |
|---|---|
| `src/lib/capabilities/document.ts` (새) | 능력 정의 · 도구 셋 · 흐름 안내 프롬프트 |
| `src/lib/doc-fill/*` (새) | 채우기 엔진. DB·저장소를 모른다 — 바이트를 받아 바이트를 돌려준다 |
| `src/lib/generated-files.ts` (새) | `generated_files` 행과 저장소 파일 |
| `src/lib/builtin-templates.ts` (새) | 기본 양식 목록(키·이름·파일 경로) |
| `assets/templates/*.hwpx` (새) | 기본 양식 파일 — 사용자가 한글로 만든다(7절) |
| `src/app/api/files/[id]/route.ts` (새) | 내려받기 |
| `supabase/migrations/0029_generated_files.sql` (새) | 표 · 트리거 |

엔진이 DB와 저장소를 모르게 두는 이유는 시험 때문이다. 양식 바이트 → 자리 목록, 양식 바이트 + 내용 → 결과 바이트가 전부라 실제 파일로 시험할 수 있다.

## 3. 능력과 도구

### 3.1 능력 `document`

- 표시 이름: **문서 만들기** — "양식을 채우거나 표준 서식으로 한글 파일을 만듭니다"
- `capabilities/settings.ts`의 `CAPABILITY_IDS`에 더한다. 설정값은 없다(`{}`)
- 서비스 정의서는 "양식 채우기"와 "한글로 내보내기"를 따로 적었지만, 이 설계에서 내보내기는 기본 양식 채우기이므로 하나로 묶는다. 엑셀 내보내기는 S3
- 기관 범위 제한 대상이 아니다(`public_data`만 기관 범위를 따른다). 나만의 비서도 켤 수 있다
- `isAvailable()`은 항상 참 — 외부 키가 필요 없다

### 3.2 도구

모든 도구의 입력 스키마에 기관·부서·사용자·대화 id를 넣지 않는다. 서버의 `TurnContext`에서만 꺼낸다(S1 설계 4.2, `tests/capabilities.test.ts`가 확인).

**`list_templates`** — 입력 없음.
돌려주는 것: `[{ ref, name, kind: 'agent' | 'builtin', format: 'hwpx' | 'docx' | 'hwp' }]`.
비서 양식은 `agent_templates`에서 이 비서의 쓰는 중인 것(`retired_at IS NULL`), `ref`는 그 id.
기본 양식은 `builtin:official_letter` · `builtin:report` · `builtin:minutes`.

**`read_template`** — 입력 `{ ref }`.
돌려주는 것: `{ ref, name, mode: 'fill' | 'fallback', reason?, slots: [{ id, label, kind, path, hint }] }`
- `kind`: `marker` | `section` | `cell`
- `path`: 상위 제목 경로 (예: `["2. 추진 계획", "가. 일정"]`)
- `hint`: 지금 들어 있는 자리 표시 글자(있으면)
- `mode='fallback'`이면 `reason`에 이유(옛 HWP, 자리 없음)

**`fill_template`** — 입력 `{ ref, title, values: [{ slot_id, text }] }`.
- `title`은 파일 이름에 쓴다(`{title}.hwpx`, 쓸 수 없는 글자는 바꾼다)
- 돌려주는 것(AI에게): 만든 파일 이름, 채운 자리 수, **채우지 않은 자리 목록**, 대체 경로였으면 그 사실
- 화면에는 `ToolOutcome.files`로 파일 링크를 보낸다(6절)

`ref`가 이 비서의 양식도 기본 양식도 아니면 거절한다 — 다른 비서·기관의 양식 id를 넣어도 읽히지 않는다.

### 3.3 흐름 안내 (시스템 프롬프트)

`document` 능력의 `prepare`가 `systemAddendum`으로 붙인다. 프리셋마다 적지 않는다 — 직원이 만든 비서에도 똑같이 필요하다(S1의 자료 인용 규칙과 같은 판단).

담는 것:
1. 문서를 만들어 달라는 요청이면 `list_templates`로 양식을 고른다. 사용자가 이름을 말하지 않았고 후보가 여럿이면 묻는다
2. `read_template`로 자리를 읽어 **목차를 먼저 보여 주고 확인을 받는다.** 확인 전에는 채우지 않는다
3. 확인되면 항목별 초안을 대화에 쓰고, 같은 내용으로 `fill_template`을 부른다
4. **모르는 칸(일시·장소·참석자·문서번호 등)은 지어내지 않는다.** 묻거나 비워 두고, 비워 둔 칸을 알린다
5. `mode='fallback'`이면 그 이유와 "HWPX로 다시 저장해 올리면 양식 그대로 채운다"를 사용자에게 알린다

### 3.4 `TurnContext`에 대화 id

생성 파일은 대화에 묶인다. `TurnContext`에 `conversationId`를 더한다. 새 대화는 `prepareTurn`이 도구 루프 전에 만들므로 이 값은 항상 있다.

## 4. 채우기 엔진

### 4.1 채울 자리

| 종류 | 찾는 법 | 이름 | 채우는 법 |
|---|---|---|---|
| `marker` | 본문·표 칸 글자 속 `{{이름}}` | 괄호 안 | 표시를 지우고 그 자리에 넣는다 |
| `section` | 번호 붙은 제목 문단, 그 아래 다음 같은 급 이상 제목 전까지 | 제목 글자 | 제목은 두고 아래 영역의 빈 문단·자리 표시 문단을 내용으로 바꾼다 |
| `cell` | 표에서 비었거나 자리 표시만 든 칸, 왼쪽(없으면 위)에 항목명 칸 | 항목명 칸 글자 | 그 칸을 채운다 |

- **표시가 하나라도 있으면 자동 찾기(`section`·`cell`)를 하지 않는다.** 표시는 기관의 의도다. 섞으면 엉뚱한 칸까지 채운다
- 번호 체계: 공문서 항목 기호 `1.` → `가.` → `1)` → `가)` → `(1)` → `(가)` → `①` → `㉮`, 보고서식 `Ⅰ.` · `□` · `○` · `-`. 기호 종류로 급을 정한다
- 자리 표시 글자: `○○○`, `OOO`, `(내용)`, `(작성)`, `(기재)` 등. 목록은 `slots.ts` 한 곳
- 같은 이름의 표시가 여러 번 나오면 자리 하나로 묶고 모든 위치에 같은 글을 넣는다 (예: 머리글과 본문의 `{{제목}}`)

S2-a는 `marker`만 한다. `section`·`cell`은 S2-b.

### 4.2 채우기 규칙

- 글은 평문이다. **줄바꿈 하나 = 문단 하나.** 새 문단은 그 자리에 원래 있던 문단을 복제해 글만 바꾼다 — 글꼴·들여쓰기·줄 간격 등 서식 참조(`paraPrIDRef`·`charPrIDRef`)가 그대로 남는다
- 표 칸 안에서도 같다 — 칸 안 문단을 복제한다
- 안 채운 자리는 원래대로 둔다. `marker`는 표시 글자가 남는다(사람이 찾기 쉽게)
- 자리 안에 새 표를 만들거나 표 행을 늘리지 않는다 (12절 '나중')
- 상한: 자리 100곳, 자리 하나 6,000자, 양식 파일은 S1 상한 그대로. 넘으면 이유를 돌려준다

### 4.3 HWPX 다루기

HWPX는 zip 안의 XML 묶음이다(`Contents/section*.xml`이 본문, `Contents/header.xml`이 서식 정의).

- **본문 XML(`section*.xml`)만 고친다.** 서식 정의·그림·설정 파일은 바이트 그대로 다시 넣는다
- 원본 XML의 순서·속성·네임스페이스를 지키는 방식으로 읽고 쓴다. 이미 들어와 있는 `fast-xml-parser`의 순서 보존 모드와, 바꿀 곳만 손대는 문자열 치환 중 한글에서 안전한 쪽을 **S2-a 첫 작업(확인 작업)**에서 정한다
- 고친 문단의 줄 배치 캐시(`hp:linesegarray`)는 지운다. 글이 바뀌었는데 옛 줄 배치가 남으면 한글이 겹쳐 그릴 수 있다. 없으면 한글이 열 때 다시 계산한다(확인 작업에서 실제로 확인한다)
- 미리보기 글(`Preview/PrvText.txt`)이 있으면 채운 본문으로 갈아 끼운다 — 파일 탐색기 미리보기에 자리 표시가 보이면 안 된다
- `mimetype` 항목은 zip 맨 앞에 압축 없이 둔다(형식 규칙)

### 4.4 못 채울 때 (S2-b)

옛 HWP이거나 자리를 하나도 못 찾으면 `read_template`이 `mode='fallback'`을 돌려준다.
기존 파서(`hwp.ts`)로 본문을 읽어 번호 제목만 뽑아 자리 목록으로 삼고, `fill_template`은 기본 보고서 양식에 "제목 + 내용" 쌍으로 채운다.
결과와 프롬프트(3.3-5)로 그 사실을 밝힌다.

### 4.5 DOCX (S2-b)

`word/document.xml`의 `w:p`·`w:r`·`w:t`. 한 낱말이 여러 `w:r`로 쪼개져 있어 `{{제목}}`이 세 조각일 수 있다 — 문단 안 글을 이어 붙여 찾은 뒤 위치를 조각으로 되짚는다. 나머지 규칙은 HWPX와 같다.

## 5. 생성 파일

### 5.1 표 `generated_files` (0029)

| 칸 | 뜻 |
|---|---|
| `id` uuid | |
| `conversation_id` → `conversations(id) ON DELETE CASCADE` | 대화와 수명을 같이 한다 |
| `user_id` → `users(id)` | 주인. 내려받기 권한의 근거 |
| `department_id` NOT NULL · `organization_id` | 기관은 트리거가 채운다(기존 표와 같은 방식) |
| `agent_id` → `agents(id) ON DELETE SET NULL` | |
| `template_ref` text · `template_name` text | `agent_templates.id` 또는 `builtin:…` |
| `file_name` · `mime_type` · `size_bytes` · `storage_path` | |
| `created_at` | |

색인: `(conversation_id)`, `(user_id, created_at DESC)`.

**배포 순서: 0029 적용 → S2-a 코드 배포.** 코드가 이 표에 쓰기 때문이다(0013의 교훈).

### 5.2 저장소

- 비공개 `documents` 버킷, 경로 `generated/{organization_id}/{conversation_id}/{file_id}/{file_name}`
- 저장소 접근은 `generated-files.ts` 한 곳에서만 — 서비스 정의서 7.4의 "저장소 연결부" 자리다

### 5.3 내려받기 `GET /api/files/[id]`

1. 로그인 확인
2. 행을 읽어 `user_id === session.user.id`인지 확인. 아니면 404 (있다는 사실도 알리지 않는다)
3. 60초짜리 서명 주소로 넘긴다(302)

함수가 파일을 직접 보내지 않는 이유: **Vercel 서버리스 함수는 응답 본문도 4.5MB로 제한된다.** 그림이 든 HWPX는 넘을 수 있다.

**관리자는 내려받지 못한다.** 감사 화면에는 생성 사실과 파일 이름만 남는다 — 질문 원문을 가린 것과 같은 원칙.

### 5.4 지우기

대화 삭제 라우트(`DELETE /api/conversations/[id]`)가 그 대화의 생성 파일을 저장소에서 먼저 지우고 대화를 지운다. 저장소 삭제가 실패해도 대화는 지우되, 남은 경로를 `system_logs`에 남긴다 — DB 연쇄 삭제는 저장소 파일을 지우지 않는다.

### 5.5 기록

생성마다 `usage_logs`에 `action='document_generated'`, `details: { agent_id, template_ref, template_name, file_name, size_bytes, mode }`.
토큰을 쓰지 않으므로 과금 규약 대상(`db-check`의 `TOKEN_ACTIONS`)이 아니다. 감사·통계 화면 한글 이름은 **문서 파일 생성**.

## 6. 대화로 전달

- `ToolOutcome`에 `files?: GeneratedFileRef[]`를 더한다 — `{ id, file_name, size_bytes }` (S1에서 미뤄 둔 칸)
- SSE `tool_end` 페이로드에 `files`를 더한다. **이벤트 이름과 기존 칸은 그대로**
- `messages.source_references`에 `files: GeneratedFileRef[]`를 더한다 — 새로고침해도 링크가 남는다. 두 메시지 행의 키 집합 규칙(PostgREST 배치)을 지킨다
- 대화 화면(`MessageBubble`)은 `files`를 내려받기 카드로 그린다: 파일 이름 · 크기 · [내려받기] → `/api/files/{id}`

## 7. 기본 양식과 프리셋

### 7.1 기본 양식 3종

**사용자가 한글로 만들어 `assets/templates/`에 둔다.** 한글이 저장한 HWPX라야 호환성이 확실하다. 각 양식에 아래 표시를 넣는다.

| 파일 | 이름 | 넣을 표시 |
|---|---|---|
| `official_letter.hwpx` | 공문 기안문 | `{{행정기관명}}` `{{수신}}` `{{경유}}` `{{제목}}` `{{본문}}` `{{붙임}}` `{{발신명의}}` `{{공개구분}}` |

- 공문 기안문은 행정업무운영규정 시행규칙의 기안문 서식을 바탕으로 한다. 결재란·시행 번호·주소 같은 칸은 표시 없이 비워 둔다 — 실제 기안은 전자문서시스템(온나라 등)에서 하므로 이 파일은 **초안**이다
- 일반 보고서는 `fallback`(4.4)에도 쓴다. 이때는 `{{제목}}`에 문서 제목을, `{{주요 내용}}`에 "항목 제목 줄 + 내용 줄"을 차례로 넣고 나머지 표시는 비운다(표시 글자가 남지 않게 빈 글로 채운다). 반복 자리를 따로 두지 않는다
- Vercel 배포 묶음에 이 파일이 들어가도록 `next.config.mjs`에 `outputFileTracingIncludes`(`/api/chat` → `./assets/templates/**`)를 둔다

### 7.2 프리셋 (S2-c)

- '회의록 정리 비서' · '공문 작성 비서' · 보고서 계열 프리셋에 `document` 능력을 켜고 프롬프트를 흐름에 맞게 고친다
- 기존 기관은 `npm run seed:agents -- --update` — `updated_by`가 빈 비서만 갱신(관리자가 고친 것은 건드리지 않는다)
- 회의록: 메모·녹취록을 붙여 넣거나 사진(손글씨 메모·화이트보드)을 첨부하면 정리해 회의록 파일로 준다. 녹취록 파일 첨부는 S3(대화 중 파일 첨부)
- 기관이 자기 양식을 그 비서에 올리면 그것을 쓴다

## 8. 보안 · 과금 · 데이터 흐름

- **격리**: 도구는 이 비서의 양식과 기본 양식만 읽는다. 생성 파일은 주인만 받는다. 기관 값은 서버 문맥에서만
- **과금**: 초안 글은 모델이 도구 입력으로 쓰므로 그 토큰은 이미 `chat_message` 기록(모델·금액)에 잡힌다. 새 과금 경로가 없다
- **바깥으로 나가는 것**: 양식의 자리 이름·상위 제목·자리 표시 글자(목차)가 Claude로 간다. 양식 파일 전체와 만든 파일은 나가지 않는다. 서비스 정의서 6절 표에 이 줄을 더한다
- **권한 검사 전수**: `/api/files/[id]`를 `tests/route-auth.test.ts`에 직원 라우트로 올린다

## 10. 나누어 짓기

| | 내용 | 끝나면 되는 것 |
|---|---|---|
| **S2-a** | 확인 작업(한글에서 열리는가) · HWPX 엔진(`marker`) · 0029 · `generated-files.ts` · 내려받기 · `ToolOutcome.files`·`tool_end.files`·`source_references.files`·파일 카드 · `document` 능력·도구·흐름 안내 · 기본 양식 연결 · 대화 삭제 시 파일 삭제 | 표준 서식 공문·보고서·회의록을 한글 파일로 받는다 |
| **S2-b** | 자동 자리 찾기(`section`·`cell`) · DOCX · 옛 HWP·자리 없음 대체 · 양식 탭 안내(표시 넣는 법) | 기관이 올린 양식을 그대로 채운다 |
| **S2-c** | 프리셋 3종 · 흐름 다듬기 · 실측 | 회의록·공문·보고서 비서가 첫날부터 파일을 준다 |

각각 계획 하나. S2-a의 **첫 작업은 확인 작업**이다 — 기본 양식(또는 사용자가 한글로 저장한 빈 HWPX)에 엔진으로 글을 넣은 파일을 만들어 **사용자가 한글에서 열어 본다.** 열리지 않으면 4.3의 방식을 바꾼 뒤에야 다음 작업으로 간다.

**사용자가 할 일**: 기본 양식 3종을 한글로 만들어 두기(7.1) · 0029 적용 · 확인 작업과 각 단계 끝의 파일 열어 보기 · 푸시.
