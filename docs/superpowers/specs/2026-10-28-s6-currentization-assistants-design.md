# S6 — 현행화 비서 10개 설계 (업무 도우미를 '입력 → 파일'에서 '작년 문서 → 올해 문서'로)

**날짜**: 2026-10-28
**근거**: 벤치마킹 분석(`docs/BENCHMARK_PLAN_2026-10-27.md`), 업무 개편 장부(`docs/workon-rebuild/IMPLEMENTATION_STATUS.md`), 업무 엔진 코드(`src/lib/work/`, `src/lib/doc-fill/`), 2026-10-28 대화
**결정 방식**: 사용자가 질문을 멈추고 진행을 지시("일단 그냥 진행해줘"). 사용자가 말한 것은 **[사용자]**, 설계자 판단은 **[설계자]**로 표시한다
**앞선 과제**: 업무 개편(0034, 업무 10개 구현 — 운영 미반영), S4·S5(NODA·공통 자료실)

## 1. 왜 만드는가

**[사용자]** 지금까지의 업무 비서는 직원이 내용을 입력하면 HWPX·XLSX로 만들어 준다. 그런데 내용을 입력하는 일이 곧 업무라서 줄어드는 부담이 적다. 공공기관 문서의 대부분은 **작년에 쓴 것을 올해 사정에 맞게 다시 쓰는 일**이고, 그중 가장 손이 많이 가는 것은 **바뀐 규정·지침을 찾아 맞추는 일**, 그다음이 바뀐 내용 반영이다. 원하는 것은 기관의 지난 문서를 파악해 제목(또는 작년 파일 하나)만 넣어도 올해 판을 만들어 주는 서비스다.

**[사용자]** 주 고객은 지방공기업. 지난 문서의 최종본은 전자문서시스템에 있지만, 작성과 수정은 담당자 PC에서 한다. 전자문서시스템에 등록된 문서의 **제목 목록**은 받을 수 있다.

**[사용자]** 꼭 필요한 비서 10개를 확정해 만들고, 그 뒤 하나씩 더하거나 사용자가 직접 더한다.

그래서 이 과제는 비서를 새로 열 개 만드는 일이 아니다. **모든 비서가 공유하는 '현행화 엔진'** 하나를 만들고, 기존 업무 엔진(양식 채우기·항목 뽑기·표 계산·근거 찾기)을 그 위에 다시 겨냥하는 일이다.

## 2. 목표 · 비목표 · 실패 기준

### 목표
1. 직원의 입력은 **작년 파일 + 올해 바뀐 자료(첨부) + 몇 줄 메모**다. 내용을 처음부터 적지 않는다. 이것이 모든 비서의 공통 입력 모델이다
2. 비서는 작년 파일을 읽어 **바꿔야 할 자리**(연도·기간·수치·근거 규정 인용·담당자·일정·사실 서술)를 찾고, 올해 자료·규정·법령으로 메운 뒤, **서식을 그대로 둔 올해 파일**과 **변경 내역표**(무엇을·왜·어떤 근거로 바꿨나, 못 바꾼 곳)를 낸다
3. 근거 규정은 세 곳에서 본다 — 기관 자료실의 내부 규정(NODA), 기관 유형 공통 자료실의 정부 기준(현재 판), 법제처 법령·자치법규. 바뀐 근거는 **옛 판과 새 판을 나란히** 보이고, 못 찾은 근거는 '확인 필요'로 남긴다
4. 전자문서 제목 목록으로 **문서 달력**을 만들어 "작년 이맘때 낸 문서"를 먼저 꺼내고, 시작할 때 관련 문서(작년 판·근거 공문)를 제목으로 짚어 준다
5. 직원이 **자기 반복 문서를 비서로 등록**할 수 있다(작년 파일 + 양식 + 지시 + 원자료 갈래)
6. 숫자·날짜·사람·조문 위치는 프로그램이 원자료에서 확인한 것만 남긴다(업무 개편의 원칙 그대로). 모델은 문장만 쓴다
7. 웹에서 끝까지 된다. 한글 PC 도우미는 다음 판(5절)

### 비목표 (S6에서 안 함)
- 전자문서시스템(EDMS) 연동 — 기관마다 제품이 다르고 보안성 검토 대상이 늘어난다. **제목 목록 파일(엑셀·CSV)** 만 받는다 **[설계자, 대화에서 합의]**
- 담당자 PC 설치형 도우미(작업 폴더 읽기·한글 COM 제어) — 설계는 5절에 적어 두되 이번에 만들지 않는다. 담당자 PC의 인터넷·설치 가능 여부를 아직 못 들었다 **[설계자]**
- 회의 녹음 STT, 보고 슬라이드(PPTX), 이미지 생성, 멀티 프로바이더, 노코드 워크플로우 빌더 — 벤치마킹 문서 7절
- 기관 문서 전체를 비서가 자동으로 '파악'하는 일 — 자료실에 올린 문서(NODA)만 안다. 관리자가 전자문서에서 묶음으로 내려받아 올리는 길은 지금 문서 관리로 된다

### 실패 기준 (하나라도 나면 '제공' 표시를 못 한다)
- 작년 파일의 서식(표·글상자·머리말)이 깨진 올해 파일
- 작년 숫자가 올해 숫자로 바뀌지 않은 채 '완료'로 보임(바꾸지 못한 자리는 반드시 변경 내역표의 '확인 필요'에 있어야 한다)
- 지난 판 규정이 근거로 쓰임(S5 실패 기준 그대로)
- 모델이 지어낸 수치·조문 번호·담당자가 파일에 들어감

## 3. 현행화 엔진 (모든 비서의 바탕)

### 3-1. 입력

| 갈래(`work_sources.purpose`) | 무엇 | 필수 |
|---|---|---|
| `prior`(신설) | 작년 파일 — HWPX·HWP·DOCX·XLSX. 여러 개면 가장 최근 것이 기준, 나머지는 참고 | 비서마다 다름(4절) |
| `data` | 올해 수치 자료 — 엑셀·CSV·표가 있는 한글 | 선택 |
| `reference` | 올해 근거 — 상급기관 지침 공문·편람·내부 규정(없으면 자료실·공통 자료실·법제처에서 찾는다) | 선택 |
| `template` | 기관 양식(작년 파일과 다른 양식으로 내야 할 때만) | 선택 |
| 메모 | 몇 줄 — "올해는 사업 B를 뺀다", "기준일 2026-03-01" | 선택 |

`prior`가 HWP(5.0)면 서식을 지킨 채 고칠 수 없다 — 글만 읽어 기관 양식 또는 표준 양식에 다시 담고 변경 내역표에 '서식 재현 불가'를 적는다(대체 경로, `doc-fill/fallback.ts`와 같은 꼴).

### 3-2. 단계 (실행기 `runs/executor.ts`에 `kind: 'currentize'`로 더한다 — 체크포인트는 단계마다)

1. **읽기** — 작년 파일을 문단·표 칸 단위 **조각**으로 읽는다. HWPX는 `hwpx-core.scanParagraphs`가 이미 문단·조각·오프셋을 주므로 그대로 쓴다(조각 id = 섹션·문단 시작 위치). 각 조각에 글·위치(제목 사슬·표 좌표)를 붙인다
2. **자리 찾기(프로그램)** — 조각마다 바꿔야 할 후보를 규칙으로 찾는다
   - 연도·기간: `2025년`·`'25`·`2025. 1. 1. ~ 12. 31.`·`전년도`·`금년도`
   - 수치: 표 칸의 숫자·본문의 금액·명·건·%(표 엔진 `parseNumber`로 읽히는 것)
   - 근거 인용: `「○○법」 제N조`, `○○규정 제N조`, `○○지침(2025)`, `예산편성기준`(이름 사전은 공통 자료실·자료실 문서 이름 + 법제처 검색)
   - 사람·조직: 담당자·부서명(기관 조직도와 대조)
   - 일정: 날짜·요일
   - 나머지 문장: '서술'로 분류 — 바꿀지 여부는 3단계에서 모델이 판단하되 **바꾼 문장은 반드시 근거(올해 자료 조각 번호·메모)를 달아야** 한다
3. **근거 모으기(프로그램)** — 인용된 규정마다 현재 판을 찾는다: 기관 자료실(NODA `/context`, 비서 보관함) → 공통 자료실(현재 판) → 법제처(현재 판, 시행일). 옛 인용과 새 판의 **해당 조문 글**을 나란히 둔다. 올해 수치 자료는 표 엔진으로 읽어 항목 이름으로 작년 표와 맞춘다(`lookupColumn` 재사용)
4. **바꾸기(모델 + 프로그램)**
   - 연도·기간·날짜: 프로그램이 규칙으로(기준일에서 계산)
   - 수치: 프로그램이 올해 자료에서 찾은 값만. 못 찾으면 **그대로 두고 '확인 필요'** — 지어내지 않는다
   - 근거 인용: 조문 번호·이름은 프로그램이 새 판에서 확인한 것만. 조문 내용이 바뀌어 **서술까지 바꿔야 하면** 모델이 새 조문을 근거로 문장을 다시 쓰고 근거 번호를 단다
   - 서술: 모델이 올해 자료·메모를 근거로 고친다. 근거 없는 수정은 프로그램이 되돌리고 '제안'으로만 남긴다(규정 확인 업무의 '유보'와 같은 규칙)
5. **쓰기** — HWPX 조각에 `Edit`를 만들어 `applyEdits`·`writeHwpx`(서식 유지). 표 칸은 `ancestorLineSegDeletes` 규칙 그대로. DOCX는 `docx.ts`의 조각 치환으로. 결과 = 올해 파일 + **변경 내역표 XLSX**(조각 위치 · 작년 글 · 올해 글 · 종류 · 근거 · 상태 `바꿈|확인 필요|제안`)
6. **검수** — 업무 개편의 `review.ts`(숫자 대조)·`items/verify.ts`(날짜·사람 대조)를 그대로 돌린다. '확인 필요'와 '제안'은 검토 항목이 된다

### 3-3. 화면 (작업실 `TaskWorkbench`에 보기 하나 추가)

- **대조 보기**: 왼쪽 작년 조각, 오른쪽 올해 조각, 가운데 종류·근거·상태. 조각을 눌러 올해 글을 고치면 새 판(기존 '칸 직접 수정'과 같은 경로)
- 근거 인용이 바뀐 조각은 옛 조문·새 조문을 접어 보인다(근거 창 `SourcePanel` 재사용)
- '확인 필요'만 모아 보기. 모두 처리돼야 '검토 완료'

### 3-4. 지키는 것

- 작년 파일의 바이트는 원자료로 보존(`work_sources` origin에 해시). 조각 id는 같은 바이트에서 결정적
- 모델에는 조각 글·올해 자료 조각·근거 조문만 준다. 파일 전체를 한 번에 주지 않는다(긴 문서는 조각 묶음으로 나눠 부르고 체크포인트)
- `usage_logs` `work_generate`·`work_revise` 규약 그대로(모델·토큰·원가·run_id·stage)

- 3의 신구조문대비표는 지방공기업·협회 공통의 표준 서식(현행 | 개정안 | 개정 이유 3열). `assets/templates/`에 한글로 만든 HWPX를 더한다(`build-standard-templates.ps1`·검증 기록 절차 그대로)
- **'제공' 표시는 평가 사례가 통과한 비서만**(02 문서 원칙). 1·2·3은 실제 지방공기업 샘플 없이는 통과를 주장할 수 없다 — 가상 사례로 '준비 중(시험)'까지만 **[설계자]**

## 5. 전달 방식 — 웹 먼저, PC 도우미는 다음 판 **[설계자]**

| | 웹(S6) | PC 도우미(S7 후보) |
|---|---|---|
| 작년 파일 | 직원이 올린다 | 작업 폴더에서 비서가 고른다 |
| 올해 파일 | 내려받아 작업 폴더에 둔다 | 작업 폴더에 바로 쓴다 |
| 한글 서식 | 서버가 XML 수준에서 고친다(이미 검증된 엔진) | 한글 프로그램(COM)이 직접 고친다 — 미리보기·인쇄 보장 |
| 전제 | 브라우저 | 담당자 PC 인터넷 + 설치 권한 + 서명된 설치 파일 |

PC 도우미를 만들 때도 엔진은 서버 것을 쓰고 PC 쪽은 입출력과 한글 COM만 맡는다. 이 저장소의 `scripts/hancom-verify.ps1`·`work-hancom-renderer.mjs`가 그 출발점이다. **담당자 PC 환경(인터넷·설치)을 확인한 뒤 결정한다.**

## 6. 문서 달력 (제목 목록 활용)

- 입력: 관리자가 전자문서에서 내려받은 제목 목록 파일(엑셀·CSV). 칸은 최소 **제목·날짜**, 있으면 **부서·담당자·문서번호**. 칸 대응은 올릴 때 화면에서 고른다(첨부 읽기의 머리글 판정 `header.ts` 재사용) **[설계자 — 실제 칸은 미확인]**
- 처리(프로그램): 제목에서 연도·시기 낱말을 떼고 묶어 **되풀이 문서**를 찾는다(같은 줄기 제목이 2개 연도 이상). 부서·담당자별로 '올해 이맘때(±4주)' 문서를 홈에 띄운다
- 시작할 때: 새 작업 제목을 치면 목록에서 작년 판·관련 공문 제목을 보여 주고 "전자문서에서 이 파일을 내려받아 올리세요"라고 짚는다. 자료실에 같은 제목의 문서가 이미 있으면 바로 `prior`로 건다
- 인수인계 비서의 원자료로 담당자별 제목 목록을 그대로 쓴다
- 표: `work_document_index`(신설, 기관 단위) — 제목·날짜·부서·담당자·문서번호·줄기 키·원본 행. 개인정보는 담당자 이름뿐이고 기관 안에서만 보인다

## 7. 사용자 추가 비서

- '내 비서 만들기' = **작년 파일 + (선택) 양식 + 몇 줄 지시 + 원자료 갈래**를 저장한 것. 엔진은 currentize 고정. 카탈로그에 넣지 않고 `work_user_assistants`(신설, 기관·주인·공개 범위·`prior` 원자료 id·지시·갈래)에 둔다
- 공개 범위는 비서 권한 규칙(`personal`·`department`·`official`)을 따르고, 공식 승격은 기존 승인 흐름
- 홈에는 공식 비서 10개 다음에 '내 비서'가 보인다

## 8. 측정 (출시 뒤 월 1회 장부에)

업무별: `prior` 조각 수 대비 **자동으로 바뀐 비율**, '확인 필요' 수, 직원이 다시 고친 조각 수(재작업), 검토 완료까지 시간, 모델 원가. 플랫폼: 비서별 완료 수, 사용자 추가 비서 수, 문서 달력에서 시작한 작업 비율.

## 9. 빌더 점검 뒤 정한 것 (2026-10-28, 설계자 판단 — 틀렸다면 사용자가 뒤집는다)

검토용 에이전트가 설계를 읽고 "추측하면 계획이 달라지는 것" 아홉 가지를 물었다. 답은 다음과 같다.

| # | 물음 | 결정 |
|---|---|---|
| 1 | 엔진이 구조 변경(절·표 행 넣고 빼기)까지 하는가, 글 바꿔 넣기까지인가 | **S6는 글 수준**이다. 문단·표 칸의 글을 제자리에서 바꾸고, 글만 있는 문단을 뒤에 덧붙이는 것까지(지금 엔진이 하는 범위). 절 삭제·표 행 삽입·삭제는 **'확인 필요'로 남기고 직원이 한글에서** 한다. 이유: HWPX 문단·행 복제는 컨트롤이 함께 복제돼 파일이 깨진다(hwpx-core 결정). 구조 변경은 S7(PC 도우미 — 한글이 직접 행을 넣는다)로 보낸다. "제목만 넣어도 올해 판"의 약속은 S6에서 '글은 다 바뀌고 구조 변경 자리는 표시된 올해 판'이다 |
| 2 | `전년도 | 당해 | 증감` 표의 열 밀기와 증감 재계산 | **한다.** 머리글에 연도꼴 둘 이상이 있고(`header.ts`의 연도 판정) 올해 기준일로 '한 해 전·당해'를 가릴 수 있는 표는 ① 작년 '당해' 값을 올해 '전년도' 칸으로 옮기고 ② '당해'는 올해 자료에서 찾은 값, 없으면 비우고 확인 필요 ③ 증감·증감률은 `table-engine`으로 다시 계산한다. 연도 뜻을 가릴 수 없는 표는 통째로 확인 필요 |
| 3 | 옛 판 조문은 어디서 오는가 | **법제처 연혁 API는 붙이지 않는다**(장부 결정 유지). '옛 판' = 작년 파일에 적힌 인용 글, '새 판' = 법제처 현재 판·공통 자료실 현재 판·자료실 문서. 나란히 보기는 '작년 문서의 인용 ↔ 현재 조문'이다. 비서 3(규정 제·개정)은 **기관 현행 규정 ↔ 현재 상위 법령**을 맞대면 되므로 법령의 옛 판이 필요 없다. 자치법규·판례처럼 자체 `LAW_API_OC`가 필요한 조회는 키가 있을 때만 켠다 |
| 4 | 기존 카탈로그 항목을 바꿔도 되는가 | **추가만 한다.** 기존 키의 필수 입력은 바꾸지 않는다. `official-letter`·`audit-response`·`report`·`meeting`·`reply`·`handover`에 선택 입력 `prior`(file-set)를 더한다. `intake`는 키·구현 그대로 두고 **홈에서 비서 4 카드 아래 묶어 보일 뿐**이다(계약·옛 작업 불변). `collection`·`settlement`도 홈 카드만 합친다. 새 키 세 개(`business-plan`·`evaluation-report`·`regulation-amend`)만 추가 |
| 5 | 사용자 추가 비서를 어디에 두는가 | **S6는 '내 작업 틀'(개인 전용)까지만.** 새 표 `work_task_presets`(기관·주인·이름·업무 키·`prior` 원자료 사본·양식·지시·갈래). 부서 공유·공식 승격은 하지 않는다(승인·판 기록은 `agents`에 묶여 있어 한 벌 더 만들지 않는다). 공유가 필요해지면 `agents` 행으로 옮기는 것을 그때 설계한다 |
| 6 | 공통 자료실 유형에서 지방공기업을 뗄 것인가 | **뗀다.** `local_enterprise`(지방공기업)를 일곱째 유형으로 더한다 — `ORG_TYPES`·0033 CHECK(마이그레이션 0035)·열쇠 표·운영자 화면 탭. 기존 기관은 `public`에 남고 운영자가 지방공기업만 옮긴다. 비서 1·2의 근거(예산편성기준·경영평가 편람)가 공공기관 것과 섞이지 않게 하는 선행 작업이다 |
| 7 | 작년 파일 크기·분량 | 실측이 없다. **가정**: HWPX 50MB·500쪽·조각 5,000개까지. `prior` 원자료 상한을 50MB로 올리고, 조각 목록은 DB가 아니라 저장소(`extract_path`)에 두며, 모델 호출은 조각 50개 묶음·업무당 원가 상한(기본 2,000원, 기관 설정)을 둔다. 실제 샘플을 받으면 숫자를 고친다 |
| 8 | 문서 달력의 담당자 ↔ 계정, 누가 보는가 | 담당자 이름이 같은 기관 `users`에 **정확히 하나** 있을 때만 잇는다(동명이인·없음은 미연결). 미연결 문서는 부서 단위로 보인다. 보이는 범위는 **자기 부서 + 상위 부서**(`getVisibleDepartmentIds`)와 관리 범위 관리자. 감사·인사 문서 제목을 전 직원에게 보이지 않는다 |
| 9 | 실제 지방공기업 샘플 확보 시점 | **사용자 몫.** 샘플이 오기 전에는 한글로 만든 가상 사업계획·실적보고서로 엔진을 만들고 '제공' 판정은 보류한다. 계획은 **엔진 먼저**로 짠다 |
