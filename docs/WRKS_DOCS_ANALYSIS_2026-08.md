## 1. 지금 웍스AI에 벌어지고 있는 일 — 강제 마이그레이션

**가장 중요한 발견입니다.**

### 비서(Assistants) 기능이 2026-08-10자로 종료됐습니다

- 상단 메뉴에서 비서 항목이 사라지고 **대화 이력도 확인 불가**
- 관리 화면만 8/19까지 유지 후 제거
- **기존 비서는 에이전트로 자동 이전되지 않음** — 사용자가 직접 재생성
- **대화 이력과 업로드한 지식 파일은 옮길 수 없음**

사유가 문서에 명시돼 있습니다:

> 비서 기능의 기반인 **OpenAI Assistants API가 8월 26일 공식 종료**되고,
> 데이터를 옮겨주는 자동 마이그레이션 도구가 제공되지 않아 함께 정리하게 됐어요.

### 이것이 의미하는 것

웍스AI의 RAG 비서는 **OpenAI Assistants API 위에 얹혀 있었습니다.** 벡터 저장·검색·
파일 파싱을 전부 OpenAI에 위임한 구조입니다. 그 API가 폐기되자 **고객 데이터를
가져올 방법이 없어 고객에게 직접 다시 만들라고 안내**하고 있습니다.

같은 종속성이 다른 문서에도 드러납니다:

> (비서-폴더 연동) OpenAI가 읽어들이지 못하는 파일은 동기화에 실패할 수 있고
> 이는 웍스AI 문제가 아니라 **전적으로 OpenAI 문제**입니다. …
> **해결해 드릴 수 있는 방법은 안타깝지만 없습니다.**

> (정부/공공 버전) 고객 데이터를 **저장하지 않고**(모든 데이터는 OpenAI에 저장)

**→ WORKON은 Supabase + pgvector로 직접 저장·검색합니다. 이 종속성이 없습니다.**
공급자 API 폐기로 고객 데이터가 증발하는 사고가 구조적으로 발생하지 않습니다.

## 2. 정부/공공 특화 버전 — 우리와 직결

기업 계정 개설 시 **'조직 유형'에서 '정부/공공'을 선택**하면 비서 세트가 자동 설치됩니다.

| 웍스AI 공공 비서 | WORKON seed |
|---|---|
| 음슴체 변환기 | ✅ 동일 |
| 개조식 내용정리 | ✅ 동일 |
| 정책 홍보문 작성 | ✅ 동일 |
| 공문 초안 작성 | ✅ 동일 |
| 보고서 초안 작성 | ✅ 동일 |
| 민원인 답변 작성 | ✅ 동일 |
| 연설문 작성 | ✅ 동일 |
| 회의록 작성 | ✅ 동일 |

**WORKON의 공공 비서 8종은 이 목록을 그대로 복제한 것입니다.**
즉 이 부분은 차별점이 아니라 **동등 수준(parity)**이며, 여기서 우위를 주장할 수 없습니다.

그 외 웍스 공식 비서 40여종(파워포인트 기획, 엑셀 함수 추천, 요약/확장, 번역 등)이
별도로 제공됩니다. 학교 특화 버전도 별도 존재하며, 서울시교육청은 `senGPT`라는
별도 브랜드로 운영 중입니다.

## 3. 지원 파일 유형 — HWP는 이미 표준

비서 제작 시 **두 능력을 토글로 분리**합니다.

| 능력 | 지원 형식 |
|---|---|
| 텍스트 문서 읽기 | PDF, DOCX, PPTX, **HWP, HWPX**, TXT, HTML, PY, PHP, JSON, MD, JAVA, C, CPP, RB, TEX |
| 숫자 문서 읽기 | XLSX, CSV, PDF, DOCX, PPTX, TXT, HTML, CSS, PY, XML, MD, JS, TS, JAVA, C, CPP, RB, TEX, ZIP, TAR, JPEG, PNG, GIF |

**HWP/HWPX는 이미 시장 표준입니다.** WORKON의 HWP 지원은 "차별화"가 아니라
"없으면 검토 대상에서 탈락하는 요건"으로 봐야 합니다.

다만 **구현 방식이 다릅니다.** 웍스AI는 파싱을 OpenAI에 위임해 실패 시 대응 수단이
없다고 문서에 명시합니다. WORKON은 자체 파서라 표 복원·장식 문자 제거 등을 직접
제어합니다. 이건 실질적 품질 차이로 이어질 수 있습니다.

## 4. 도입·구축 프로세스 (실제 운영 방식)

### 4-1. 규모별 분기

| 규모 | 방식 |
|---|---|
| **100인 이하** | 셀프서빙 — 계정 개설 → 법인카드 등록 → 직원 초대 → 즉시 이용. 계약서 불필요 |
| **100인 이상** | 별도 계약(서면/전자) → 매월 세금계산서 발행 → 계좌이체 |

과금 시작일은 **계정 생성일로부터 매 30일**(월말 아님), 첫 달에 가입비 합산.

### 4-2. 계약 시 고객이 결정할 4가지

1. **전사 오픈 희망 시점**
2. **로그인 방식** (아래 4택 1)
3. **조직도 연동 여부** — 연동 시 고객사 개발 필요, 오픈 2~3주 지연
4. **사내 교육 필요 여부와 횟수** — 유료

### 4-3. 로그인 방식 4가지

| 방식 | 특징 |
|---|---|
| MS Entra ID SSO | 별도 개발 불필요. 도메인만 등록. 특정 URL로 MS 로그인 강제 가능 |
| 그룹웨어 SSO | 암호화 코드 기반 인증. 고객사 개발 필요. 최초 1회 개인정보 제공 동의 |
| **회사 이메일 직접 가입** | **가장 많이 쓰는 방식.** 개발 불필요. 도메인 등록 후 직원이 각자 가입 |
| CSV 일괄 초대 | 100명 미만 소규모에 적합. 이름·이메일·권한 3열 |

> 세 방식 모두 퇴사 시 회사 이메일이 막히면 자연스럽게 접근이 끊기는 구조를
> 의도적으로 택했습니다.

### 4-4. 조직도 연동 — 유료 부가서비스

- **최초 1회 200만원**(VAT 별도)
- 고객사가 부서 관리 API로 직접 개발
- 문서가 명시적으로 권고: **"필수가 아니고 사후 연동 가능. 빠른 도입을 위해
  우선 연동 없이 도입하고, 직원들이 충분히 쓰게 되었을 때 사후 연동 권장"**
- 조직도는 **하나의 워크스페이스에만** 연동 가능

### 4-5. 사내 교육 — 전면 유료

- 저가 정책 유지를 위해 교육은 유상 제공
- 전문 강사 6명이 전국 사업장·공공기관 출강, 기본 3시간
- **도입 이후 교육 권장** (도입 전 교육은 바로 써볼 수 없어 효과 낮음)
- 도입 담당자용 30분 비대면 솔루션 소개 미팅은 별도 제공
- 서비스 내 '무료 교육 신청' 버튼 → 1:1 비대면 온보딩 콜

## 5. 수익 구조 — 핵심 기능이 부가서비스로 분리돼 있음

| 부가서비스 | 요금(VAT 별도) | 과금 기준 |
|---|---|---|
| 이용 기록(감사 로그) | 일 8,000원 | 켜 둔 날짜 |
| 접속 통제 | 일 3,000원 | 켜 둔 날짜 |
| 주기적 대화/파일 자동 삭제 | 일 5,000원 | 켜 둔 날짜 |
| AI 슈퍼 가드레일 4종 | 일 10,000원~ | 날짜 × 사용자 수 |
| 한국형 통합 문서 파서(자동 OCR) | 일 4,000원~ | 날짜 × 사용자 수 |

**감사 로그·접속 통제가 본체가 아니라 별도 과금 항목입니다.**
1,000명 규모 기준 가드레일만 월 약 30만원, 파서 월 약 12만원이 추가됩니다.

→ WORKON은 접속 로그·시스템 로그·보안 로그·대리접근 로그를 **기본 기능으로**
이미 구현해 뒀습니다. 포지셔닝 재료가 됩니다.

## 6. 요금 체계

- **순수 종량제.** 모델·도구별로 원화 단가를 공시
- 환산 기준을 명시: **1천 토큰 = 한글 약 1,600자**
- 예: GPT-5.6 Sol 입력 1천 토큰 19.5원 / 출력 117원
- 입력이 27만 2천 토큰을 넘으면 입력 2배·출력 1.5배 할증
- 2025-11-24부터 OpenAI 외 Anthropic·Google·xAI·Perplexity 등 **54종 모델 추가**
  (그 전에는 OpenAI 7종만 제공)
- 개인 계정은 2026-08-10부터 정액 구독제 폐지 → **적립금 차감 방식**

→ WORKON `models.ts`가 USD 단가 + 환율 방식인데, 웍스AI처럼 **원화 직접 단가**로
가는 것도 방법입니다. 고객이 이해하기 쉽고 환율 변동을 흡수할 수 있습니다.

## 7. RAG 운영 노하우 (그대로 쓸 수 있는 내용)

`admin-guide/advanced/rag-techniques`에 실제 고객 문의와 답변이 정리돼 있습니다.
WORKON 관리자 가이드에 거의 그대로 적용 가능합니다.

1. **파일에만 의존하면 답이 흔들린다**
   RAG는 전체 파일이 아니라 일부 문단만 발췌하므로 불명확한 답이 나온다.
   원하는 정답 사례를 **비서 프롬프트에 직접 넣어야** 확실히 제어된다.

2. **일관성이 필요하면 FAQ 형식 파일로 올려라**
   `Q. 출장 여비 규정 / A. 임원 100만원 …` 형식이 청크 선택 실패에 강하다.

3. **날짜·공휴일 인식은 포기하고 직접 나열하라**
   20개 미만이면 프롬프트에 날짜와 내용을 직접 적는 편이 정확하다.

4. **같은 질문에 다른 답이 나오는 것은 RAG 엔진의 청크 선택 편차** 때문이며
   구조적으로 불안정하다고 인정하고 있다.

## 9. WORKON 전략에 대한 시사점

### 차별점이 아닌 것 (동등 수준)

- 공공 특화 비서 8종 — **완전히 동일**
- HWP 지원 — 시장 표준
- 요술봉, 부서별 공유, 사용량 통계

### 실제 우위 가능성이 있는 것

1. **데이터 주권**
   웍스AI는 "고객 데이터를 저장하지 않는다 = 모두 OpenAI에 저장"입니다.
   공공기관 보안성 검토에서 이건 설명하기 까다로운 지점입니다.
   WORKON은 Supabase에 자체 저장하므로 국내 리전·자체 통제를 주장할 수 있습니다.

2. **공급자 종속 없음**
   OpenAI Assistants API 폐기로 웍스AI 고객은 지금 비서를 손으로 다시 만들고
   있습니다. 대화 이력과 지식 파일은 복구 불가입니다.
   WORKON은 pgvector 자체 구현이라 같은 사고가 구조적으로 없습니다.

3. **감사·통제 기능 기본 제공**
   웍스AI는 감사 로그·접속 통제를 일 단위 유료 부가서비스로 팝니다.
   WORKON은 기본 포함입니다.

4. **문서 파싱 품질 제어**
   웍스AI는 파싱 실패 시 "OpenAI 문제라 해결 불가"라고 안내합니다.
   WORKON은 자체 파서라 표 복원·장식 문자 제거를 직접 고칠 수 있습니다.

### 따라잡아야 하는 격차

- 멀티 모델 (54종+ vs 1종)
- 내부 도구 (웹검색·코드실행·이미지생성·차트·문서요약) — WORKON은 전무
- SSO 4종 (WORKON은 Credentials만)
