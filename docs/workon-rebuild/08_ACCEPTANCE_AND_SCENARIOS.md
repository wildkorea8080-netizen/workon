# 08. 완료 기준과 검증 시나리오

기능 완료는 구현·자동 검증·실제 파일·브라우저 검증 증거로 판단한다. 아래의 실제 한글·운영 환경 검사는 자동 실행할 수 없는 경우 담당자·필요 파일·미완료 이유를 명시한다. 검증 도구가 없다는 이유로 통과로 바꾸지 않는다.

## 분기 실적 통합 과제

`fixtures/quarterly-report.json`은 전부 가상 자료다. 실제 소속·개인정보가 아니다. 테스트에서 해당 원자료를 XLSX·요청 문서로 준비한다. JSON fixture만 읽고 UI 통과했다고 주장하지 않는다.

1. 가상 요청 문서에서 제출 기간·기한·항목 추출.
2. 네 부서 중 세 부서만 제출한 상태를 표시.
3. 두 부서의 천원과 한 부서의 원 단위를 통일.
4. 동일 제출의 중복 사본은 자동 이중 합산하지 않고 후보로 표시.
5. 소계·합계 행을 제외하고 예산·집행·참여자 집계.
6. 미제출 부서를 제외한 잠정 집계임을 표시하고 직원이 이 상태를 확인.
7. 같은 집계로 결과보고 HWPX와 제출 공문 HWPX 생성.
8. 직원이 향후 계획만 수정하고 다시 생성. 집계 금액은 유지.
9. XLSX·HWPX·미리보기의 금액·단위·기간·파일 버전 일치.
10. 다음 세션에서 열어도 자료·검토·최종본 유지.

## 업무별 실제 파일 관문

10개 비서 모두 catalog에 지정한 기본 파일을 최소 한 가지 검증된 업무 유형에서 생성해야 한다. 파일의 확장자·시그니처·패키지 구조·필수 내용·편집성을 확인한다. HWPX에는 문서 전체 이미지 대신 편집 가능한 글·표가 있어야 한다. XLSX는 숫자 타입·반올림·문자 보호·원본 대응을 확인한다.

기본 양식 3종이 없어서 건너뛴 검사가 남아 있으면 출시 양식 관문을 실패시킨다. 테스트 fixture는 단위 검증으로 표시하며 한글에서 검증한 실양식과 폴더·표시를 구분한다.

## 업무 성과 실증

초기 3개 업무는 같은 난이도의 과제로 기존 전체 투입시간과 새 전체 투입시간을 비교한다. 업로드·질문·검토·직접 수정·다운로드·한글 재편집·실패 재시도를 포함한다. 실제로 다른 일을 할 수 있는 대기시간과 직원 투입시간은 따로 기록한다.

초기 목표 가안은 검토 가능한 결과 도달률 85% 이상과 핵심 업무 순투입시간 중앙값 30% 이상 감소다. 성능 보증이나 이번 구현의 달성 결과가 아니다. 중요 수치·권한·파일 실패는 평균 만족도와 별도로 보고한다.

## 최종 제출할 검증 기록

- 실행한 명령·환경·결과, 실행하지 못한 검사의 이유.
- 대표 사용자 흐름 화면과 해당 결과 파일·해시·버전.
- 한글 열기·수정·저장을 검증한 제품 버전·글꼴·파일·일자.
- DB 기관 격리·멱등·worker 복구·파일 수명 시험 결과.
- 남은 외부 의존성, 실제 운영 전 해야 할 작업, 롤백 경로.
