# 04. 결과 파일 생성·수정·검증

## 1. 첫 관문: 진짜 HWPX 결과

기존 `readTemplate`·`fillTemplate`을 감싸는 새 문서 서비스를 먼저 만든다. 첫 과제는 공문·보고서·회의록의 실제 한글 양식으로 생성 → 다운로드 → 한글에서 열기·편집·다시 저장이다. 실제 한글 호환 시험은 XML 검사나 테스트 fixture로 대체할 수 없다.

현재 체크아웃에는 기본 양식 3종의 바이너리가 없다. 허용된 개발 자료나 한글에서 검증된 양식을 확보한다. 기본 양식을 임의로 위조하거나 테스트 fixture를 검증된 기관 양식으로 표시하지 않는다. 사용자가 이미 보유한 양식과 사용 가능한 검증 환경이 없으면 그 의존성을 구체적으로 기록하고, 엔진·화면·계약·로컬 테스트 등 독립 작업을 계속한다. 보유하지 않은 양식·렌더러·라이선스 때문에 실제로 못 끝낸 검증은 남겨 둔다.

## 2. 양식의 세 등급

- `draft`: 업로드만 됨. 원본 보관과 읽기 결과 확인 가능.
- `mapped`: 채울 항목·반복 표·이미지 위치 등 지원 구조가 대응됨. 시험 생성 가능.
- `verified`: 지정한 환경에서 생성·편집·렌더링 시험을 통과한 특정 양식 버전. 직원에게 공식 제공 가능.
- 별도 `retired` 상태: 새 작업에 쓰지 않지만 기존 작업 재현을 위해 보존.

양식마다 파일 SHA-256, 버전, 필수 항목, 필드 타입·길이, 수정 가능 범위, 고정 문구, 지원 기능, 검증 환경·일자·결과를 저장한다. 수정된 양식을 기존 버전으로 덮지 않는다. 신규 작업은 최신 승인 버전을 추천하되 진행 중 작업의 양식을 자동 교체하지 않는다.

원본 기관 양식과 표준 양식은 구분한다. HWP 이진 파일은 읽기와 HWPX 대체 결과의 차이를 설명한다. 원본 유지가 불가능한 파일을 표준 보고서로 바꿀 때는 사용자에게 차이를 보여 주고 선택 기록을 남긴다.

## 3. 내용 모델

양식 원본·필드 대응표·업무 내용·실제 생성 파일을 분리한다. 내용 모델은 **지원하는 편집 영역**을 표현하며 임의의 HWPX 전체를 완벽하게 복원하는 범용 편집기라고 가정하지 않는다.

필드에는 안정적인 ID, 양식 위치, 타입(text/paragraph/table/image), 현재 값, 근거 ID, 직원 직접 수정 여부, 잠금 여부를 둔다. 필드 ID는 현재 원본 해시와 양식 버전에 속하며 재읽기 결과의 순번만으로 버전 간 대응하지 않는다. 기존 `s1` 등 순번은 해당 양식 버전 안에서만 어댑터가 사용한다.

문서 버전에는 기준 양식 버전, 부모 버전, 입력 자료 버전, 비서·워크플로 버전, 필드 값, 계산 결과 해시, 생성 요청, 수정 출처를 고정한다. 파일은 그 버전에서 만든 불변 결과다.

## 4. HWPX 생성 단계

1. 접근 권한·기관·필수 입력·양식 지원 상태 확인.
2. 양식과 원자료 버전을 고정하고 스냅샷 저장.
3. 근거와 사실·계산 결과를 구조화. AI가 없는 숫자·이름·문서번호를 채우지 않도록 검증.
4. 필드별 내용 생성. 서버에서 출력 스키마·길이·필수 항목 검사.
5. 기존 채우기 엔진 또는 확장 어댑터로 실제 HWPX 생성.
6. 압축·XML·리소스·필드·수치·지원 양식 조건 검사.
7. Storage 업로드 → 해시·크기·형식·소유권·버전 메타데이터 확정.
8. 렌더러가 실제 저장 파일을 열어 페이지 미리보기·필요 시 PDF 생성.
9. 결과·검토 항목·미리보기 상태를 작업에 연결. 최종 완료는 필요한 산출물이 모두 준비됐을 때만 표시.

생성 실패는 내용 모델과 입력을 남기고 복구한다. ‘채팅 글을 복사하세요’를 기본 성공 경로로 두지 않는다. 복구 안내로 텍스트 열람은 제공할 수 있으나 파일 실패 사실을 숨기지 않는다.

## 5. 단계별 지원 범위

| 수준 | 지원 | 관문 |
|---|---|---|
| D1 | 기존 자리·문단·표 셀의 텍스트, 기존 표·그림·문서 구조 보존 | 실제 양식 3종에서 한글 열기·편집·저장 |
| D2 | 문단별 재생성·직접 수정·잠금·버전 복구 | 다른 영역과 직접 수정이 유지됨 |
| D3 | 검증된 반복 표의 행 추가·합계·글머리, 지정 위치 이미지·차트 | XML 관계·표 주소·ID·리소스와 실제 페이지 검사 |
| D4 | 양식 종류 확대·복잡한 반복 구역·첨부 묶음 | 양식별 지원 행렬과 회귀 검증 |

기존 문서의 그림을 보존하는 것과 새로운 그림을 삽입하는 것을 구분한다. D3를 제공하려면 이미지 크기·캡션·참조·리소스·내용 목록을 처리하고 실제 렌더링을 확인해야 한다. LLM이 만든 XML을 그대로 파일에 붙이지 않는다. 파일 전체를 이미지로 만드는 방식은 편집 가능 조건에 맞지 않는다.

## 6. 수정과 동시성

직접 수정: 클라이언트는 `baseVersion`과 field patch를 보낸다. 서버에서 권한·필드 타입·잠금·현재 버전을 검사하고 트랜잭션으로 새 문서 버전을 만든다. 기준 버전이 바뀌었으면 409와 최신 버전·충돌 필드를 제공한다.

AI 수정: 지정 field ID와 요청을 저장 → 변경 후보 생성 → diff 표시 → 사용자 적용 → 새 버전 생성. 직원이 잠근 필드는 바꾸지 않는다. 문서 전체가 아니라 선택 영역만 처리한다. 후보 생성 중 다른 버전이 생기면 자동 적용하지 않는다.

매번 원본 양식 + 해당 버전의 필드 값으로 재생성하여 누적 XML 손상을 피한다. 이전 생성 파일을 반복적인 문자열 치환의 기준으로 삼지 않는다. 복구는 과거 버전을 삭제하거나 덮는 것이 아니라 과거 내용에서 새 버전을 만드는 행위다.

동시 작업이 늦게 끝나도 현재 버전을 덮지 않는다. 서버는 완료 시 버전·run ID·lease를 비교해 해당 결과를 역사로 보존하거나 `superseded`로 표시한다. 미리보기는 artifact hash에 연결하고, 현재 버전과 다르면 다운로드 버튼 옆에 구버전임을 표시한다.

## 7. 미리보기와 렌더러

`DocumentRenderer`를 별도 인터페이스로 분리한다. 제공 기능은 HWPX 입력, PDF·페이지 이미지 출력, 페이지 수, 렌더링 엔진·버전, 사용 글꼴·누락 글꼴 경고, 원본 해시다. 한컴 공식 문서 필터 모델과 DVC는 구조·서식 검증의 참고이며 웹 페이지 렌더러라고 가정하지 않는다.

실제 사용 가능한 렌더러·배포 환경·라이선스·데이터 경로를 검증한 뒤 연결한다. SDK 없이 완전한 HWPX 웹 편집이 가능하다고 약속하거나 지원되지 않는 변환기를 만들었다고 표시하지 않는다. 외부 변환 서비스를 몰래 호출하지 않는다.

렌더러가 없을 때 구조화 내용의 편집은 가능하지만 ‘실제 파일 미리보기’와 구분한다. 이 상태를 최종 상용 관문 통과로 처리하지 않는다. 서비스 내부의 문단·셀 편집을 먼저 완성하고, 정밀한 시각 편집은 검증된 편집기 통합의 별도 범위로 둔다.

## 8. XLSX

기존 계산 엔진과 `buildResultWorkbook`을 재사용한다. 기본은 고정 계산 값 + 계산 근거. 작업용 수식 모드가 필요하면 별도 명시하고 신뢰 가능한 내부 계산식만 쓴다. AI·업로드 문자열을 수식으로 실행하지 않는다. 계산 결과의 정확한 값과 화면 반올림은 구분하고, 금액·비율은 단위·반올림 규칙을 고정한다.

취합 산출물에는 결과·제출 현황·오류·원본 대응·계산 근거 시트를 필요에 따라 제공한다. 원본 셀을 알 수 없는 추출 경로는 추정 셀 주소를 만들지 말고 파일·표·추출 좌표 수준으로 명시한다. 원본 시트 인덱스와 추출 표의 행 인덱스를 혼동하지 않는다.

읽기 상한으로 잘린 파일을 전체 취합 완료로 표시하지 않는다. 상한 확대가 필요하면 분할 처리·메모리·시간·원본 추적 시험을 함께 한다. 빈값·읽기 실패를 0으로 바꾸지 않는다. 중복·합계행·음수·혼합 단위·숨김 시트 처리 규칙은 기존 회귀를 보존한다.

## 9. 파일 검증·자원 제한

확장자·헤더·실제 패키지 형식을 함께 확인한다. ZIP 경로 탈출·과도한 압축 해제·XML 외부 엔티티·외부 리소스·매크로·암호화·서명 문서 정책을 정한다. 원본·추출·생성·렌더링의 크기·시간 상한을 분리한다. 실패 코드는 `TEMPLATE_MISSING`, `TEMPLATE_UNSUPPORTED`, `OUTPUT_INVALID`, `OUTPUT_TOO_LARGE`, `PREVIEW_UNAVAILABLE`, `VERSION_CONFLICT` 등으로 일관되게 제공한다.

기술 참고: [한컴 OWPML 모델](https://github.com/hancom-io/hwpx-owpml-model), [한컴 DVC](https://github.com/hancom-io/dvc). 이 공개 모델의 존재는 별도 편집·변환 제품의 사용 권한을 의미하지 않는다.
