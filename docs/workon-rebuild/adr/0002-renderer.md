# ADR 0002 — 실제 파일 미리보기 렌더러

- 날짜: 2026-10-27 · 상태: 채택(운영 렌더러는 미정) · 관련: 04_DOCUMENT_ENGINE.md 7절

## 결정

1. `DocumentRenderer` 경계(`src/lib/work/documents/renderer.ts`)를 둔다. 입력은 저장한 파일 바이트와 sha256, 출력은 쪽 수·PDF·렌더러 이름·판.
2. **운영(Vercel)에는 HWPX 렌더러가 없다** — 기본 구현 `unavailableRenderer`. 파일의 미리보기 상태는 `unsupported`이고 화면은 "실제 파일 미리보기 없음(이 서버에 렌더러 없음)"과 '문서 구조(편집용) — 실제 쪽 배치와 다를 수 있음'을 구분해 보인다. 구조 보기를 실제 미리보기처럼 꾸미지 않는다.
3. **로컬 Windows 작업자**는 설치된 한글(COM, `scripts/work-hancom-renderer.mjs`)로 그 파일을 열어 PDF를 만든다(`npm run work:worker -- --hancom`). 미리보기 기록에 렌더러 `hancom-com-local`과 한글 판이 남는다. 2026-10-27 실측: 공문 초안 HWPX → 1쪽 PDF, sha256 일치.
4. 한글 COM은 **운영 렌더러로 쓰지 않는다** — 한글 사용권(서버·자동화 용도)·Windows 데스크톱 세션·동시 처리 한계가 확인되지 않았다. 보안 모듈(FilePathCheckerModule)·레지스트리를 바꾸지 않으므로 한글이 접근 확인을 띄우는 폴더에서는 멈춘다 — 임시 폴더에서 열고 저장한다.
5. 외부 변환 서비스를 몰래 부르지 않는다.

## 남은 결정(사용자·운영)

- 운영 렌더러 후보: (a) 한컴 공식 서버 제품(문서 변환·뷰어) 계약, (b) 기관 내부 Windows 렌더링 서버 + 한글 사용권, (c) 렌더러 없이 내려받아 한글에서 확인. 데이터 경로·보존·사용권을 함께 정해야 한다. 정할 때까지 상용 관문의 '실제 파일 미리보기'는 미통과로 둔다.
