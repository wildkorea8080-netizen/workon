# 03. 화면·정보 구조·디자인

## 화면 방향

브랜드는 WORKON, 현재의 Pretendard와 짙은 청색 계열을 계승한다. 큰 채팅 입력창 대신 ‘처리할 업무’와 ‘검토할 결과물’을 중심에 둔다. 공공기관 직원에게 모델명·토큰·프롬프트·내부 처리 경로를 필수 선택으로 보여 주지 않는다. 별도 사용자에게 필요한 오류·처리 상태·자료 외부 전송 안내는 명확히 표시한다.

### 디자인 기준

- 배경 `#F5F7FA`, 본문 `#152238`, 주색 `#003087`, 카드 흰색, 구분선 `#DCE3EC`를 초기 토큰으로 둔다. 기존 기관 브랜딩은 주색·로고로 덮어쓸 수 있어야 한다.
- 본문 15~16px, 제목 24~28px, 보조 글 13px 이상을 기본으로 한다. 8px 간격 체계, 모서리 10~12px, 그림자는 최소화한다.
- 색만으로 상태를 구분하지 않는다. ‘자료 확인 중’, ‘검토 필요 3건’, ‘파일 준비 완료’처럼 글과 아이콘을 함께 제공한다.
- 1440px·1280px 데스크톱 작업을 우선하고 1024px에서 패널 접기, 768px 이하에서는 탭 전환으로 제공한다. 작은 화면에서 넓은 표를 억지로 줄이지 않는다.
- 키보드 이동, 명시된 입력 라벨, 오류와 포커스 연결, 작업 상태의 접근성 알림, 대비를 검증한다. 파일 드래그 외에 ‘파일 선택’ 버튼을 항상 제공한다.

## 직원 경로

| 경로 제안 | 화면 | 주요 내용 |
|---|---|---|
| `/` | 로그인 전 소개 / 로그인 후 업무 홈 | 인증 상태에 따른 현재 진입 유지. 로그인 후 업무 대시보드 |
| `/assistants` | 업무 비서 10개 | 필요한 자료·결과 파일·지원 양식이 보이는 카드 |
| `/tasks` | 내 작업함 | 상태·기한·비서·담당·결과물 필터, 검색·정렬 |
| `/tasks/new?workflow=...` | 작업 시작 | 양식 선택, 원자료, 필수 정보, 결과 파일 구성 |
| `/tasks/[id]` | 업무 작업실 | 결과 미리보기, 검토 사항, 근거, 수정·재생성 |
| `/tasks/[id]/history` | 변경 기록 | 생성·직접 수정·AI 제안·복구·확정 기록 |
| `/templates` | 사용 가능한 양식 | 기관 양식·표준 양식, 버전·지원 상태 |
| `/files` | 결과물 모음 | 작업·버전·파일 형식별 목록, 권한 확인 후 다운로드 |
| `/chat` | 기존 AI 대화 | 기존 비서·대화 기능 보존, 보조 기능으로 배치 |
| `/my/stats` | 내 업무 현황 | 실제 작업 성과 + 기존 사용량 |

기존 `/?conv=ID`는 `/chat?conv=ID`로 호환한다. `/shared/[token]`의 기존 권한과 동작은 유지한다. 공유 대화 링크가 업무 파일·근거 원문에 대한 접근 권한을 새로 부여하지 않도록 한다. `/dashboard` 기존 리다이렉트와 충돌하는 경로를 만들지 않는다.

## 홈

왼쪽: WORKON·기관명, 업무 홈/업무 비서/내 작업함/결과물/양식/AI 대화. 관리자 메뉴는 해당 권한에만 표시한다.

위쪽: ‘오늘 어떤 업무를 처리하시겠어요?’ + ‘새 업무 시작’. 바로 아래 ‘검토할 작업’, ‘진행 중’, ‘최근 결과물’. 실제 값이 없을 때 가짜 업무·절감시간을 넣지 않는다.

가운데: 자주 쓰는 비서 3개와 전체 보기. 카드에는 이름, 한 문장 용도, 필요한 자료, ‘HWPX’·‘XLSX’ 형식 표시, 시작 버튼. 모델명은 표시하지 않는다.

아래: 최근 작업 표. 제목, 비서, 상태, 수정일, ‘이어서 작업’ 버튼. 처음 사용하는 기관에는 실제 기능으로 연결되는 시작 안내를 제공한다.

## 작업 시작 화면

1. 업무와 결과물 선택. 업무마다 기본 결과 파일을 미리 고른다.
2. ‘우리 기관 양식’·‘표준 양식’에서 선택, 또는 양식 등록. 기관 로고·부서 등 이미 아는 정보는 자동 채운다.
3. 원자료 업로드와 자료 용도 선택. 자료 읽기 상태·실패 이유·파일별 제외를 표시한다.
4. 제목·대상 기간·수신자 등 필수 정보. 문서에서 추출한 값은 근거와 함께 채운다. 직원이 확인하거나 수정할 수 있다.
5. ‘HWPX 만들기’ 또는 ‘취합 엑셀 만들기’. 제출·발송을 뜻하지 않는다.

매 단계 저장한다. 뒤로 이동·새로고침·탭 종료 뒤에도 서버에 보존된 작업을 이어갈 수 있어야 한다. 파일 선택의 브라우저 임시 상태를 보존된 업로드로 오해시키지 않는다.

## 업무 작업실

상단: 제목, 상태, 저장 상태, 현재 버전, ‘HWPX 내려받기’, ‘검토 완료’.

왼쪽 폭 약 220px: 목차·생성 파일·원자료 탭. 선택한 항목은 문서 위치와 연결한다.

가운데: **현재 결과 파일을 렌더링한 실제 페이지 미리보기**. 준비되지 않으면 ‘실제 파일 미리보기 준비 중/실패’ 상태를 표시한다. 문서 구조 미리보기는 별도로 표시하고 실제 쪽 배치를 보장하는 화면처럼 꾸미지 않는다.

오른쪽 폭 약 320~380px: ‘확인할 사항’, ‘근거’, ‘수정’ 탭. 확인 사항 클릭 → 해당 문단·표와 근거로 이동. ‘확인할 사항 없음’은 검사 범위까지 표시하고 사실 무오류 인증으로 표현하지 않는다.

수정 방식은 두 가지다.

- 해당 문단·표의 값을 직접 고치고 저장.
- 범위를 선택해 ‘핵심만 3줄로’, ‘표 마지막에 합계 행 추가’처럼 요청. 변경 전후 미리보기 → 적용 → 새 버전과 파일 생성.

‘요약해 줘’처럼 범위가 모호하면 선택 문단에 적용한다. 문서 전체 변경은 명시적으로 고르게 한다. 다른 사용자가 수정했으면 덮어쓰기 대신 버전 충돌을 표시한다. 오래된 렌더링·오래된 생성 결과가 현재 버전을 덮지 않도록 한다.

파일 생성은 끝났지만 검토 문제가 남으면 ‘검토 필요’로 표시하며 초안 다운로드는 허용할 수 있다. 해결하지 않은 필수 문제는 ‘검토 완료’를 막는다. 초안/최종 표시는 기관 정책에 따른다.

## 관리자 확장

기존 `/admin/*`, `/super/*`를 유지한다. 기관 관리자에게 양식 등록·필드 대응·시험 생성·승인, 비서별 지원 범위·공개 상태, 실패 작업·품질, 보존 정책을 추가한다. 슈퍼관리자는 기관별 활성화·서비스 장애·양식 공급·공통자료를 운영한다.

운영 관리자에게 원문 파일을 기본 공개하지 않는다. 지원이 필요하면 기존 감사·접근 통제에 맞는 명시적 지원 경로를 사용한다. 기관 관리자도 기존 생성 파일을 임의로 다운로드할 수 없다는 정책을 개편으로 약화시키지 않는다.

## 빈 화면·오류·비활성 상태

준비되지 않은 비서는 ‘준비 중’과 이유를 표시한다. 선택 양식 파일 없음, 지원하지 않는 표 구조, 근거 충돌, 업로드 만료, 모델 장애, Storage 실패, 미리보기 실패를 각각 복구 가능한 문구로 안내한다. 실패 뒤에도 입력·수정본은 보존한다. 작동하지 않는 버튼·가짜 진행률·가짜 다운로드를 만들지 않는다.
