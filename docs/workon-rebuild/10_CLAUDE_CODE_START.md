# Claude Code 시작 지시문

실제 WORKON 저장소 루트에서 아래 내용을 전달한다. 패키지는 먼저 `docs/workon-rebuild/`에 둔다.

---

현재 WORKON을 공공기관 직원이 실제 업무 파일을 완성하는 서비스로 전면 개편해 주세요. 단순한 비서 카드·채팅 화면 리디자인이 아니라 작업함, 양식, 문서 버전, HWPX·XLSX 생성, 검토·수정, 파일 보관과 기관별 권한이 연결된 제품으로 구현하는 요청입니다.

먼저 저장소의 `AGENTS.md`가 있으면 해당 범위의 지침, `CLAUDE.md`, 그리고 `docs/workon-rebuild/README.md`와 번호 01~09 문서, contracts·fixtures를 읽으세요. 현재 코드가 분석 기준 `702cc436b895c278ba1fc6eb13673e88d07c3091` 이후 바뀌었으면 실제 코드를 우선 확인하고 차이를 기록하세요. 기존의 사용자 미커밋 변경을 보존하세요.

사용자 요구로 바뀐 제품 결정은 다음과 같습니다.

1. 결과 문장은 직원이 한글로 옮기는 재료가 아니라 편집 가능한 HWPX 파일 자체로 제공해야 합니다. 취합·계산은 XLSX입니다.
2. 기관 양식과 필수 정보가 준비되면 ‘파일 만들기’ 한 번으로 초안을 생성합니다. 기존 목차 확인·초안 확인·파일 생성 확인을 반복하는 흐름은 주 경로에서 없앱니다.
3. 직원은 서비스 안에서 문단·셀을 직접 수정하거나 범위를 지정해 AI 수정 후보를 적용하고, 변경된 파일을 다시 받을 수 있어야 합니다. 기존 직접 수정·잠금·다른 영역을 보존하세요.
4. 새 작업의 결과 파일·원자료·버전은 대화 삭제와 독립적으로 보관해야 합니다.
5. 직원 홈은 업무 10개, 내 작업함, 검토할 결과물, 양식을 중심으로 개편합니다. 기존 AI 대화·관리자·슈퍼관리자·기관 브랜딩과 기존 데이터는 유지하세요.
6. 초기 비서 10개는 catalog를 따릅니다. 각 비서는 입력 폼·처리·검수·실제 파일·실패 복구가 있는 업무로 구현하세요. 프롬프트 10개를 추가하고 전체 완료라고 하지 마세요.

현재 Next.js·TypeScript·Supabase·NextAuth·NODA·LLM 연결·`doc-fill`·`table-engine`·`xlsx-export`·기존 과금·감사 경계를 가능한 한 재사용하세요. 프레임워크 전면 업그레이드·DB 교체·새 모델 제공사·새 요금제·외부 음성 서비스 도입은 이 요청에 포함되지 않습니다. 새 기능에 꼭 필요한 패키지는 현재 환경·유지 상태·라이선스를 확인해 최소한으로 선택하고 결정 기록을 남기세요.

`07_IMPLEMENTATION_BACKLOG.md`의 P0부터 순서대로 구현을 시작하세요. 처음에 현재 상태·재사용/교체 지점을 짧게 기록한 뒤 계획만 제시하고 끝내지 마세요. 한 응답에 10개 전체를 억지로 구현하기보다 각 단계를 실제 동작·검증 가능한 단위로 마무리하고 이어 가세요. `docs/workon-rebuild/IMPLEMENTATION_STATUS.md`에 현재 단계, 변경 파일, 테스트 결과, 실제 파일·브라우저 확인, 미완료 의존성, 다음 구체 작업을 기록하세요.

반드시 지킬 기술 기준:

- 기존 기관·부서·비서 권한 모듈을 존중하고 모든 새 API·worker·파일·미리보기 경로에서 서버 권한을 확인하세요. service role에서 RLS만으로 격리됐다고 간주하지 마세요.
- 환경변수는 기존 config 경계를, LLM 호출은 기존 `src/lib/llm/` 경계를 사용하고 호출별 모델·사용량·기록 시점 비용을 남기세요. 키·원문·서명 URL을 로그에 남기지 마세요.
- 긴 실행은 브라우저가 닫혀도 이어져야 합니다. 실제 실행자·큐·멱등·lease·재시도·상태 조회를 구현하세요. API 응답 뒤 비동기 함수를 방치하거나 가짜 진행률을 사용하지 마세요.
- 생성 파일은 실제 패키지 검사·내용·편집성까지 확인하세요. HTML·텍스트 파일의 확장자만 HWPX로 바꾸거나 문서 전체 이미지를 넣지 마세요.
- HWPX 구조 미리보기와 실제 파일 렌더링을 구분하세요. 렌더러가 없으면 없는 상태를 표시하고 정밀 미리보기 완료라고 하지 마세요.
- 저장소의 기본 양식 파일 유무를 먼저 확인하세요. 현재 분석 시 바이너리 3종이 없었습니다. 실제 한글 검증 양식·렌더러·키가 필요한 부분은 구체적으로 기록하고, 확보되지 않은 검증을 통과 처리하지 마세요. 독립적으로 할 수 있는 코드·화면·계약·테스트는 계속 구현하세요.
- 기존 HWPX 텍스트 채우기와 새 표 행·이미지 생성은 지원 범위가 다릅니다. 기능을 주장하는 양식은 해당 구조와 한글 화면을 검증하세요.
- 계산은 프로그램으로 하고 근거·단위·원본 대응을 보존하세요. 기존 감사용 XLSX의 고정 값 모드는 유지하며 수식이 필요하면 별도 모드로 명시하세요.
- 추가 마이그레이션으로 진행하고 운영 데이터 삭제·자동 덮어쓰기·기존 파일 CASCADE 확대를 하지 마세요. 레거시 링크와 기관별 단계 전환·롤백을 구현하세요.

테스트와 완료 기준은 `08_ACCEPTANCE_AND_SCENARIOS.md`를 따르세요. 현재 환경에서 타입 검사, 기존 테스트, 빌드와 변경 영역의 의미 있는 통합·브라우저 검증을 실행하세요. DB 검증은 로컬·승인된 스테이징에서 하며 운영 데이터를 시험 자료로 쓰지 마세요. 실제 한글 파일 열기·편집·다시 저장을 못 했으면 별도 미확인으로 보고하세요.

모의 구현은 명시된 개발·테스트 모드로만 제공하고 실제 기능으로 표시하지 마세요. 선택한 기관 양식·업무 입력에서 생성 → 검토 → 수정 → 새 파일 다운로드까지 연결되는 것이 첫 제품 완료 단위입니다.

로컬 구현·테스트·변경 문서·배포 계획까지 진행하세요. 운영 배포·본 DB 적용·기존 자료 영구 삭제·새 유료 서비스 계약은 자동 실행하지 말고, 필요한 단계까지 준비한 후 구체적으로 알려주세요. 그 외의 일반적인 구현 선택마다 확인을 요청하지 말고 명세와 현 코드에 맞게 판단해 진행하세요.

## 새 세션에서 이어 하기

현재 WORKON 전면 개편을 이어서 구현해 주세요. 저장소의 해당 지침과 `docs/workon-rebuild/README.md`, `07_IMPLEMENTATION_BACKLOG.md`, `08_ACCEPTANCE_AND_SCENARIOS.md`, `IMPLEMENTATION_STATUS.md`를 읽고 실제 git 변경·코드·검증 결과를 확인하세요. 완료한 단계를 다시 만들지 말고 다음 미완료 단계부터 구현하세요. HWPX·XLSX 실제 결과 파일, 작업실 수정, 기관 격리와 기존 데이터 보존 요구를 유지하고 계획 설명만으로 끝내지 마세요.

## 특정 단계가 끝난 뒤 다음 단계 요청

지금 완료했다고 기록한 단계의 실제 구현과 검증 증거를 먼저 확인한 뒤, 장부에 기록된 다음 단계까지 이어서 구현해 주세요. 단계별 산출물이 실제 파일·DB·화면과 연결되어 있는지 확인하고, 빠진 의존성·미확인 검증은 완료와 분리해 기록하세요.
