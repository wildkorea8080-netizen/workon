## 5-1. 발견한 기존 문제

- 표 엔진이 표 위 글 '(단위: 천원)'을 '참여자'처럼 차원 낱말이 없는 셈 열에도 붙인다 — 대화의 표 합치기가 참여자 합을 '천원'으로 표시할 수 있음. 취합 업무는 셈 항목에서 그 단위를 버리게 막았고, 엔진 수정은 별도 작업으로 제안함
- 운영 DB 드리프트(agents.icon·color·usage_guide·starter_prompts — 3절)
- 취합 항목 이름을 단위 괄호와 함께 적으면('참여자 수(명)') 셈 항목으로 못 알아보고 머리글에 단위가 두 번 붙을 수 있다 — 화면 예시는 단위 없이('예산액') 바꿈, 엔진 보완은 남음
- 취합 결과 표가 작업실 가운데 칸(1280px에서)에 좁게 들어가 부서 이름이 글자마다 줄바뀜 — 화면 배치 보완 남음
- `nextAuthOptions.ts`가 users 행이 없거나 부서가 빈 사용자에게 **가장 오래된 부서**(`getDefaultDepartmentId`)를 배정한다 — CLAUDE.md '부서를 추측해서 배정하지 말 것'(signup·chat·bulk-register에서 지웠던 것)과 같은 꼴이 로그인 경로에 남아 있음. 업무 개편과 별개 — 수정 필요(소속을 모르면 거부)

## 5-2. 규정 확인 결정(Ruling)

- 근거는 `work_evidence`(업로드 파일에 묶임)가 아니라 **판의 `content.regulations`**에 저장 — NODA·공통 자료실·법제처 근거는 업로드 파일이 아니고, 판마다 '그때 무엇을 보고 썼나'가 남아야 한다. 0034를 바꾸지 않음. 틀렸다면: 근거 검색 화면이 필요할 때 표를 따로 만들어 옮긴다
- 위치·시행일은 프로그램이 자료 정보에서만, 모델은 근거 번호만 — 카탈로그 '실제 확인한 원문 위치만'
- 법제처는 **현재 판**만 준다 → 시행일이 기준일 뒤면 근거에서 빼고 '기준일에 적용되던 판 확인'을 유보로. 연혁(옛 판) 조회는 하지 않음. 틀렸다면: 법령 연혁 API를 붙여 기준일 판을 가져온다
- 기관 문서는 대화와 같이 **이 직원이 쓸 수 있는 공식 비서**의 보관함만(최대 3곳). 개인·부서 비서 문서는 찾지 않음
- 근거 제공자 장애는 다시 시도(SOURCE_UNAVAILABLE) — 근거 일부만으로 메모를 만들지 않음. '설정 안 됨'은 검토 범위·확인 사항에 적고 이어 감
- 메모 양식은 새 표준 양식(보고서 머리가 메모와 맞지 않음). 기본 양식이 넷이 되어 **대화의 '문서 만들기' 목록에도 나온다**

## 5-3. 규정 확인의 알려진 한계

- 법령 이름 검색이라 관련 없는 법령이 섞일 수 있다(실측: '여비' → 법원공무원 여비 규칙). 기관 종류로 법령을 거르지 않음 — 모델 의견·사람 검토가 맡는다
- 조문 고르기는 핵심어 개수 — 긴 조문이 유리하다. 시험 모드(모델 없음)에서는 핵심어가 질문 낱말이라 엉뚱한 조문이 고를 수 있다
- 추가 자료는 읽은 글의 **앞 1,500자만** 근거로 싣는다(파일 안에서 관련 부분을 찾지 않음) — 긴 규정 파일은 뒤 조문이 근거에서 빠진다
- 기관 문서의 시행일은 읽지 않는다(항상 '시행일 확인 필요')
- 실제 모델로 화면에서 만든 메모는 아직 없다(흐름 시험은 가짜 모델, 화면은 시험 모드)

## 5-4. P4 결정(Ruling)

- 접수·회의·인수인계는 **항목 뽑기 공통 엔진**(workflows/items) 하나로 — 모델은 항목과 원문 인용만, 프로그램이 인용·날짜·사람을 원자료에 다시 맞춘다. '화자·담당·기한 추측 금지', '명시 없는 담당자·상대 기한은 확인 필요'를 업무마다 따로 짜지 않으려는 것
- 원문에서 못 찾은 인용은 버리지 않고 표시만 — 버리면 직원이 놓친 요청을 모른다
- 다른 작업의 결과 파일은 **복사**해 원자료로(해시 확인, origin에 작업·판·해시) — 원래 작업이 새 판을 만들어도 이 작업이 본 판은 그대로. 권한: 이 작업 편집 + 원래 작업 내려받기, 아니면 404
- 결과 파일이 여럿인 업무는 모두 지금 판일 때만 검토 완료. 머리의 '내려받기'는 주 결과
- 처리표(XLSX)는 화면에서 고치지 않는다 — 원자료를 고쳐 다시 만들거나 내려받아 고친다. 틀렸다면: 항목 편집 화면을 더한다
- 선택 산출물(접수 검토 메모·1쪽 요약)은 만들지 않음 — 화면 안내도 실제로 만드는 파일만 적는다(producedOutputs)

## 5-5. P4의 알려진 한계

- 시험 모드(모델 없음)의 항목은 원자료 줄을 그대로 '기타'로 옮긴 것 — 분류·칸 채우기는 실제 모델에서만. 실제 모델로 P4 업무를 화면에서 돌려 본 적은 아직 없다
- 날짜 대조는 원문에 적힌 꼴(2026. 10. 30.·10월 30일·11. 10.)만 — '이달 말'·'금주 금요일' 같은 말은 상대 기한으로 남는다
- 비밀값 지우기는 '비밀번호:'·'PW='·'ID/PW' 같은 꼴만 — 꼴 없이 적힌 비밀값은 못 찾는다(유의 사항에 별도 절차 안내)
- 회의 '조건 표현' 알림은 낱말 목록(조건으로·전제로·추후 결정 등) — 다른 표현은 놓칠 수 있다
- 업무분장표 부서 후보는 낱말 겹침 — '후보'로만 보이고 배부하지 않는다
- 이 PC에서 Docker(6.3GB)와 next dev를 함께 돌리면 커밋 메모리(24.5GB 한도)가 차 dev 서버가 죽는다 — 화면 확인 때 다른 Docker 프로젝트를 꺼 두면 낫다
