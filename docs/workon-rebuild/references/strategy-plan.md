# 공공기관 AI 비서: 벤치마킹과 서비스 실행 계획

조사 기준일: 2026년 10월 26일

## 1. 제안의 중심

**기관이 쓰던 양식과 근거 자료를 받아, 직원이 검토하고 제출할 수 있는 업무 결과물까지 만드는 서비스**를 권한다. 제품의 대표 경험은 ‘질문에 답하기’보다 ‘자료를 모으고, 빈칸을 채우고, 틀린 부분을 찾고, 다음 담당자에게 넘기기’에 두는 것이 좋다.

**확정된 제품 요구사항: 결과물 자체를 편집 가능한 파일로 생성한다.** 문서 업무의 기본 결과물은 기관 양식에 본문·표·붙임이 반영된 HWPX이며, 취합·계산 업무는 XLSX로 제공한다. 직원이 생성된 문장을 복사해 한글에 붙여넣고 서식을 다시 만드는 과정을 정상 사용 흐름으로 두지 않는다. 서비스 안에서 결과 파일의 미리보기·수정 요청·재생성·다운로드를 연결하고, 업무 완료 기준에 다운로드 후 필요한 추가 편집량까지 포함한다.

상용 첫 버전의 비서 구성은 10개로 설계하되, 개발·실증은 핵심 3개 → 7개 → 10개 순으로 진행한다. 비서의 개수를 늘리기 위해 요약·번역·맞춤법을 따로 포장하지 않는다. 이 기능들은 모든 비서가 공유하는 기본 도구로 제공한다.

가장 먼저 실증할 세 가지는 **자료 취합·엑셀 정리, 공문 기안·기관 양식 작성, 규정·지침 근거 확인**이다. 이는 현장 조사 이전의 제품 가설이다. 실제 사용 빈도와 절감 시간은 인터뷰와 업무 관찰을 통해 검증해야 한다.

- 실제 유료 계정으로 기능을 실행하거나, 기업 내부 설치 제품을 시험한 것은 아니다. ‘제공한다’는 설명은 공식 페이지·가이드에서 확인한 공급사 설명을 뜻한다. 품질·성능·보안 효과를 독립 검증한 결과가 아니다.
- 마케팅 페이지와 세부 가이드의 범위·버전이 다를 수 있다. 다른 메뉴·요금제·설치 형태의 지원 범위를 서로 동일한 것으로 간주하지 않았다.
- 초기 대상은 공기업·준정부기관·지방공기업·출자출연기관 등의 기획·경영지원·사업관리 부서로 가정했다. 중앙행정기관·지자체·교육기관은 공통점이 있지만 규정과 업무 시스템이 다르므로 별도 검증이 필요하다.
- 아래의 개발 일정, 목표치, 기능 우선순위, 수익모델은 제안이다. 경쟁사 실적이나 검증된 시장 평균이 아니다.

#### 반드시 참고할 세부 사항

**① 도구별 실제 실행 정책이 다르다.** 협업 도구 가이드에서 Gmail 발송은 확인 후 실행으로 설명하지만, M365 메일은 ‘보내줘’ 요청 시 별도 확인 없이 즉시 발송된다고 명시한다. 우리 서비스는 기관 정책으로 승인 지점을 통일하고, 확정된 수신자·본문·첨부파일을 사람이 확인한 뒤 실행하도록 설계한다. [협업 도구 16·21·35·44쪽](https://doc4.ai/v/9gHLLt#35)

**② 한글 지원은 읽기·편집·출력·서식 보존을 따로 확인해야 한다.** 문서작성 Pro는 HWP 계열 양식을 받으며 HWPX·DOCX·PDF 결과를 안내한다. 동시에 단락 이미지가 한글 출력에 포함되지 않는 조건과 변환 서버 상태에 따른 간이 서식 출력 가능성도 설명한다. ‘한글 지원’ 한 줄로 제출 품질을 판단해서는 안 된다. [심화 기능 103·109~111쪽](https://doc4.ai/v/Ai4PnF#110)

**③ 보안 기능의 적용 경로를 확인해야 한다.** 관리자 가이드의 일부 파일 필터와 업로드 제한은 ‘AI 대화’ 전용으로 기재되어 있다. 이 설명만으로 다른 비서·문서 도구에 통제가 없다고 단정할 수는 없지만, 전 기능에 동일하게 적용된다고 추정할 수도 없다. 우리 서비스는 문서·음성·검색·예약·결과 다운로드에 공통 통제를 적용하고, 예외 경로를 시험한다. [관리자 설정 31·34쪽](https://doc4.ai/v/BpSSBg#31)

**④ 데이터에 연결해도 오류는 남는다.** 공식 DB를 조회해도 잘못된 통계표 선택, 기준연도·지역 혼동, 잠정치 누락, 적용 시점 오류, 해석 오류가 생길 수 있다. 나라장터 가이드도 기관 자체 시스템의 공고 누락 가능성, 원문 확인, 예측치의 한계를 명시한다. ‘공식 출처가 있다’와 ‘업무에 적용한 결론이 맞다’를 별도로 평가해야 한다. [공공·법령·통계 33·48쪽](https://doc4.ai/v/5dhaYM#48)

**⑤ 운영·이전성도 상품의 일부다.** 업데이트 자료는 비서에서 에이전트로 전환할 때 대화 이력과 지식 파일이 자동 이전되지 않는 사례를 안내한다. 이 안내가 현재도 동일하게 적용된다는 뜻은 아니지만, 우리 제품은 비서의 설정·근거·문서·검수 결과를 특정 모델 제공사의 기능과 분리해 보관해야 한다. [업데이트 36쪽](https://doc4.ai/v/N8kZii#36)

### 2.3 두 서비스를 보고 내릴 판단

두 제품 모두 문서 검색·생성·자동화·기업 통제를 다룬다. ‘웍스AI는 생성만, 알리웍스는 검색만’이라는 구분은 부정확하다. 다만 공개자료의 강조점으로 보면 웍스AI는 다양한 실무 도구와 한국어 문서 경험을, 알리웍스는 내부 지식·앱 구성·기업 시스템 운영을 두드러지게 제시한다. 이는 공개자료에 근거한 해석이며 성능 우열 순위가 아니다.

우리의 경쟁 우위 후보는 다음 네 가지다.

1. **업무 단위 완결성:** 받은 요청에서 제출할 자료까지 여러 비서가 같은 자료·담당자·기한을 공유한다.
2. **검증 비용 절감:** 문장·셀·증빙마다 원문 위치를 보여 주고, 누락·충돌·계산 오류를 먼저 드러낸다.
3. **기관별 반복 업무의 축적:** 승인된 양식, 항목 대응표, 지표 정의, 과거 수정 기준을 재사용한다.
4. **측정 가능한 성과:** 채팅량 대신 완료한 업무, 직원 재작업, 실제 순절감 시간을 보고한다.

이 네 가지도 경쟁사가 구현할 수 있다. 지속적인 차이는 기관별 업무 데이터의 정리 수준, 반복 검수 경험, 도입·지원 비용을 줄이는 운영 방식에서 만들어야 한다.

## 3. 누구의 어떤 문제부터 해결할 것인가

### 첫 고객군

초기에는 한 기관의 기획·경영지원·사업관리 부서와 자료를 제출하는 3~5개 협업 부서를 묶어 실증한다. 공개·비민감 또는 기관이 승인한 자료로 시험을 시작할 수 있고, 정기 보고·자료 취합이 반복되며, 실제 문서 양식을 제공하고 검수할 담당자가 있는 기관을 우선한다.

사용자는 실무자와 검토자, 도입 담당자는 디지털혁신·정보화 부서, 운영 협력자는 보안·개인정보·기록관리 담당자로 구분한다. 실무자의 만족만으로 구매가 완료되지 않으므로 각 역할의 요구를 초기부터 받아야 한다.

| 대상 | 초기 적합 업무 | 초기 별도 검증이 필요한 업무 |
|---|---|---|
| 공기업·준정부기관 | 경영지원, 사업 실적 취합, 내부 규정, 감사 대응 자료 준비 | 산업별 사업 판단, 계약·지급의 확정 처리 |
| 지방공기업·출자출연기관 | 지자체 제출 보고, 예산·정산 대사, 이사회 자료, 인수인계 | 기관별 조례·정관·감독 규정 적용 |
| 중앙행정기관·지자체 | 공문, 의회·국회 요구자료, 회의, 민원 회신 지원 | 행정처분·인허가·급부 자격 판단과 기존 행정망 연계 |
| 교육기관 | 공문·보고·학교 행정 지침 확인 | 학생·아동 정보와 교육상 판단을 포함하는 기능 |

### 실제로 줄여야 할 일

‘작성 시간이 오래 걸린다’는 인터뷰 응답을 그대로 기능으로 옮기지 않는다. 검색, 파일 열기, 복사, 항목 맞추기, 누락 확인, 숫자 검산, 상사 수정 반영에 각각 시간이 얼마나 쓰이는지 나눠 관찰한다. 글 생성보다 자료 취합과 검산이 병목이면 그 부분에 먼저 투자한다.

초기 인터뷰는 15~20명을 대상으로 하고, 최소 5명은 최근 실제 업무를 처음부터 끝까지 보여 주도록 한다. 업무 종류·빈도·기존 소요시간·승인된 원본 자료·최종 제출본·반려 이유를 한 묶음으로 수집한다. 자료의 반출·활용 범위는 기관과 정한다.

우선순위 점수는 빈도 25%, 순절감 가능 시간 25%, 여러 부서의 공통성 15%, 결과 검증 가능성 15%, 자료·시스템 접근 가능성 10%, 오류·도입 위험의 낮음 10%로 계산할 수 있다. 각 항목을 1~5점으로 현장 평가한다. 점수를 매기기 전 업무 데이터와 권한을 확보할 수 없는 후보는 별도로 보류한다. 이 문서에서는 조사하지 않은 사용 빈도를 수치 점수로 꾸미지 않았다.

## 4. 초기 상용 구성: 비서 10개

| 번호 | 비서 | 대표 산출물 | 개발 묶음 |
|---|---|---|---|
| 1 | 접수공문·업무요청 처리 | 요청사항표, 담당·기한·제출물 목록 | B |
| 2 | 공문 기안·기관 양식 작성 | 검토 가능한 HWPX 공문 초안 | A |
| 3 | 보고서·사업계획 작성 | 근거가 연결된 보고서와 요약본 | B |
| 4 | 자료 취합·엑셀 정리 | 통합 엑셀, 미제출·오류 목록 | A |
| 5 | 예산·집행·정산 대사 | 거래별 대사표, 증빙 누락·불일치 목록 | C |
| 6 | 규정·지침·법령 근거 확인 | 시점·적용 범위가 명시된 근거 답변 | A |
| 7 | 회의·위원회 후속조치 | 회의록, 결정·미결 사항, 담당·기한표 | B |
| 8 | 민원·대내외 문의 회신 | 질문별 답변 초안과 확인할 사실 목록 | C |
| 9 | 감사·경영평가·의회 요구자료 | 질의별 답변표, 증빙목록, 수치 대조표 | C |
| 10 | 인수인계·반복업무 안내 | 업무별 절차, 일정, 미결 과제, 자료 지도 | B |

A는 가장 먼저 실증할 3개, B는 다음 4개, C는 데이터·검수 기준을 확보한 뒤 완성할 3개다. 숫자는 중요도 순위가 아니다. 상용 첫 패키지는 10개로 구성하되, 모든 비서를 동일한 범위의 자율 실행으로 제공하지 않는다.

### 1) 접수공문·업무요청 처리 비서

- **상황:** 본문과 여러 첨부파일을 읽고 무엇을 언제까지 제출해야 하는지 파악한다.
- **입력:** 받은 공문, 첨부 양식, 추가 안내, 기관 업무분장표. 초기에는 파일 업로드 방식.
- **처리:** 요청 항목·기한·제출 경로·대상 기간·첨부 목록 추출 → 본문과 붙임의 불일치 표시 → 업무분장표에 따른 담당 후보 제안 → 작업 목록 생성.
- **결과:** 원문 위치가 연결된 요청사항표. 담당·기한이 원문에 없으면 ‘확인 필요’로 남긴다.
- **초기 경계:** 자동 배부·대외 회신까지 하지 않고 담당자가 확정한다. ‘통보일로부터 7일’ 같은 기한은 기산일과 적용 기준을 확인하도록 표시한다.
- **검증:** 명시된 기한·필수 제출물을 빠짐없이 추출하는지, 본문·붙임 충돌을 감지하는지 시험한다.

### 2) 공문 기안·기관 양식 작성 비서

- **상황:** 짧은 메모나 요청 내용을 기관 양식에 맞춰 기안한다.
- **입력:** 기관이 승인한 양식, 사실관계, 수신자 후보, 관련 문서. 비슷한 과거 문서는 문체·구조 참고용으로 구분한다.
- **처리:** 필수 정보 확인 → 목적·근거·내용·붙임 작성 → 날짜·금액·문서번호·붙임 대조 → 기관 양식에 삽입.
- **결과:** 편집 가능한 HWPX 초안, 변경 부분, 확인할 항목 목록. 원본 양식과 미리보기를 함께 제공한다.
- **초기 경계:** 공문 유형 3종과 기관 양식 5~10개 정도부터 품질을 보장한다. 임의의 복잡한 한글 문서를 모두 완벽하게 복원한다고 약속하지 않는다. 전자결재 등록은 초기 범위에서 분리한다.
- **검증:** 한글에서 정상적으로 열리고 표·번호·쪽 나눔·붙임이 유지되는지, 이전 문서의 연도·금액·기관명이 섞이지 않는지 확인한다.

### 3) 보고서·사업계획 작성 비서

- **상황:** 사업별 원자료를 경과·성과·문제·후속계획으로 정리해 보고한다.
- **입력:** 승인된 실적표, 사업계획, 회의 결정, 기관 보고 양식. 필요한 경우 공식 통계.
- **처리:** 목차 제안 → 자료별 근거 배치 → 수치·기간 대사 → 설명 작성 → 본문과 1쪽 요약의 일치 확인.
- **결과:** 기관 양식의 보고서, 1쪽 요약, 지표·출처 목록. 해석·제안은 확인된 사실과 구분한다.
- **초기 경계:** 주간업무·사업추진 현황·결과보고 등 반복성이 높은 3종부터 제공한다. 자유 주제 정책 연구는 후속 확장으로 둔다.
- **검증:** 원자료의 없는 성과를 만들지 않는지, 실적 집계와 본문 수치가 같은지, 요약본이 본문의 판단을 왜곡하지 않는지 시험한다.

### 4) 자료 취합·엑셀 정리 비서

- **상황:** 부서별 양식을 나누고, 회신 파일을 열어 통합하고, 누락·오류 때문에 다시 요청한다.
- **입력:** 기준 양식, 회신 파일, 대상 부서 목록, 항목 정의·집계 규칙.
- **처리:** 열·항목 대응 → 기간·단위·코드 정규화 → 미제출·중복·빈칸 표시 → 수식·합계·원본 대사 → 통합본 생성.
- **결과:** 통합 엑셀, 제출 현황, 수정 요청 후보, 값별 원본 파일·시트·셀 추적. 자동 전송은 별도 승인 절차.
- **초기 경계:** 동일 양식과 작은 양식 변형부터 처리한다. 의미가 다른 지표를 AI가 임의로 같은 열에 합치지 않는다. 금액·비율은 명시된 규칙으로 계산한다.
- **검증:** 누락된 부서·시트·숨김 행, 천원·원 혼재, 전년 양식, 수식 오류, 중복 제출을 포함한 시험 자료로 확인한다.
- **사업 가치:** 한 담당자의 취합 시간뿐 아니라 여러 부서의 재제출과 문의를 줄일 가능성이 있어 대표 상품 후보로 적합하다.

### 5) 예산·집행·정산 대사 비서

- **상황:** 예산표, 집행내역, 영수증·증빙이 서로 맞는지 확인한다.
- **입력:** 승인된 예산·집행 엑셀, 증빙, 적용 기준과 사업별 정산 규칙.
- **처리:** 항목·사업코드 연결 → 증빙 정보 추출 → 금액·기간·중복 대사 → 누락·불일치 표시 → 정산 초안.
- **결과:** 거래별 대사표, 미확인 금액, 증빙 부족 목록, 집행률·잔액 표. 규칙과 계산 근거를 함께 제공한다.
- **초기 경계:** 한두 가지 정산 유형의 사전 점검부터 제공한다. 지출 적정성·비용 인정 여부의 확정이나 회계 전표 입력·지급은 담당자에게 남긴다.
- **검증:** 취소 거래, 부가세 포함 여부, 원 단위 차이, 분할 집행, 같은 증빙 재사용, OCR 불확실성을 확인한다. 현금·계좌정보 등 필요한 범위를 최소화한다.

### 6) 규정·지침·법령 근거 확인 비서

- **상황:** 현재 업무에 어떤 기준이 적용되는지 찾고 원문을 확인한다.
- **입력:** 적용 기관·업무·기준일, 승인된 규정·지침·매뉴얼, 허용된 공식 법령 소스.
- **처리:** 적용 범위 확인 → 문서·버전·시행일 검색 → 관련 조항·별표·예외 제시 → 상충·근거 부족 표시.
- **결과:** 답변, 조문·쪽·표 위치, 시행일, 확인할 예외, 필요한 추가 사실. 문서 우선순위와 적용 관계는 기관이 승인한 기준을 따른다.
- **초기 경계:** 모든 법률 문제를 답하지 않는다. 내부 규정 질문과 제한된 업무 분야부터 시작한다. 과거 사건은 당시 유효한 규정을 확인한다.
- **검증:** 폐지·개정 문서, 비슷한 제목의 타 기관 규정, 본문과 별표, 예외 조항, 답이 없는 질문을 평가한다. 근거가 없는 답변의 유보도 정상 결과로 인정한다.

### 7) 회의·위원회 후속조치 비서

- **상황:** 녹음·메모를 회의록으로 만들고 결정사항을 실제 할 일로 옮긴다.
- **입력:** 기관의 녹음·보관 기준에 맞는 음성 또는 전사문, 안건·참석자·회의 양식.
- **처리:** 발언·안건 연결 → 결정·제안·미결 구분 → 담당·기한 추출 → 회의록과 후속조치표 작성.
- **결과:** 기관 회의록, 발언·시간 근거, 확정할 이름·담당·기한, 후속조치 목록.
- **초기 경계:** 메모·전사문 기반도 지원해 음성 처리가 허용되지 않는 환경을 수용한다. 위원회의 의결·의견을 추정하지 않는다. 공식 회의록 확정은 사람이 한다.
- **검증:** ‘검토하자’를 ‘확정했다’로 바꾸지 않는지, 조건부·반대 의견이 빠지지 않는지, 화자가 불확실할 때 이를 표시하는지 확인한다.

### 8) 민원·대내외 문의 회신 비서

- **상황:** 문의의 여러 질문을 빠짐없이 이해하고 관련 사실·규정으로 답한다.
- **입력:** 문의 내용, 담당자가 확인한 사실, 적용 규정, 검수된 답변 사례.
- **처리:** 질문 분해 → 사실관계 부족 표시 → 근거 확인 → 질문별 회신 → 표현·개인정보 점검.
- **결과:** 회신 초안, 질문별 답변 대응표, 담당자 확인 사항. 과거 답변은 현재도 유효한지 확인한다.
- **초기 경계:** 처음에는 일반 문의와 정형 회신에 한정한다. 행정처분·급부·자격·분쟁에 대한 결정, 정보공개의 최종 판단, 자동 대외 발송은 포함하지 않는다.
- **검증:** 답변 누락, 약속하지 않은 조치·기한의 생성, 민원인 간 정보 혼입, 부적절한 단정·표현을 평가한다.
- **기관별 조정:** 대국민 접점이 적은 기관에서는 대내외 질의·협조 회신 중심으로 구성한다.

### 9) 감사·경영평가·의회 요구자료 비서

- **상황:** 요구 항목별로 여러 해의 자료와 증빙을 찾고, 과거 제출본과 수치를 맞춘다.
- **입력:** 요구서, 지표 정의, 승인된 실적·회계 자료, 과거 제출본, 관련 증빙.
- **처리:** 요구 항목 분해 → 근거·증빙 연결 → 대상 기간·집계 기준 대사 → 과거 수치와 차이 설명 → 초안·색인 작성.
- **결과:** 요구 항목별 답변표, 증빙목록, 자료 부족 목록, 수치 변경 사유표.
- **초기 경계:** 하나의 반복 자료요청 유형부터 지원한다. 지표가 달라 직접 비교할 수 없는 수치는 구분한다. 증빙의 존재가 주장 전체를 입증하는지는 별도 확인한다.
- **검증:** 서로 다른 연도·사업·집계 기준을 혼합하지 않는지, 증빙 링크가 실제 답변 내용을 뒷받침하는지, 없는 근거를 만든 흔적이 없는지 확인한다.

### 10) 인수인계·반복업무 안내 비서

- **상황:** 담당자가 바뀔 때 반복 일정, 업무 절차, 미결 과제와 자료 위치를 전달한다.
- **입력:** 검수된 업무 결과물, 일정, 매뉴얼, 담당자가 확정한 진행 상태. 인수인계 대상자 권한에 맞는 자료만 포함한다.
- **처리:** 업무별 절차 → 주·월·분기·연간 일정 → 진행·미결 사항 → 자주 발생하는 오류 → 확인할 자료·연락 창구 정리.
- **결과:** 인수인계서, 첫 달 체크리스트, 자료 지도, 담당자 확인 질문.
- **초기 경계:** 개인 채팅이나 메일 전체를 무차별적으로 모으지 않는다. 확인된 업무 자료만 사용하고 비밀번호·계정 비밀은 저장하지 않는다. 인사이동 시 기존 권한이 자동으로 이어지지 않도록 한다.
- **검증:** 종료된 업무를 진행 중으로 쓰지 않는지, 최신 담당·기한을 반영했는지, 권한 밖 자료가 목록·제목·요약에도 드러나지 않는지 확인한다.

## 5. 10개 비서가 공유할 기본 기능

### 결과 파일 생성은 초기 제품의 필수 조건

기관이 기존에 사용하던 양식이나 검증된 공식 양식을 선택하고, 원자료를 넣으면 편집 가능한 결과 파일을 생성한다. HWPX 문서의 글과 표는 한글에서 직접 수정할 수 있어야 한다. 문서 전체를 이미지로 넣거나 확장자만 바꾼 파일은 합격 결과로 인정하지 않는다. PDF는 검토·공유용 보조 형식으로 제공하고, 편집 원본을 함께 보존한다.

| 업무 | 기본 결과 파일 | 함께 생성할 자료 |
|---|---|---|
| 접수공문 처리 | 업무처리표 XLSX, 필요 시 검토 메모 HWPX | 요청사항·기한·원문 근거 |
| 공문 기안 | 기관 양식 HWPX | 붙임 문서·붙임 목록 |
| 보고서·사업계획 | 보고서 HWPX | 요약본 HWPX, 수치 근거 XLSX |
| 자료 취합 | 통합 XLSX | 미제출·오류·원본 대응 시트 |
| 예산·정산 | 대사표 XLSX, 정산보고 HWPX | 증빙목록·미확인 항목 |
| 규정·지침 확인 | 근거·적용 시점이 담긴 검토 메모 HWPX | 원문 위치·확인할 예외 |
| 회의·위원회 | 기관 회의록 HWPX | 후속조치표 XLSX |
| 민원·문의 회신 | 회신 문서 HWPX | 질문별 답변·검토 사항 |
| 감사·평가 요구자료 | 지정 양식의 HWPX 또는 XLSX | 증빙목록과 첨부파일 묶음 |
| 인수인계 | 인수인계서 HWPX | 연간 일정·미결 과제 XLSX |

기관이 지정한 제출 형식이 있으면 그 형식을 우선한다. 사용하지 않을 보조 파일을 매번 모두 만들지는 않는다. 업무별 기본 파일과 필요한 첨부를 함께 내려받을 수 있도록 한다.

사용 흐름은 **양식 선택 또는 등록 → 원자료 입력 → 실제 결과 파일 생성 → 파일 미리보기에서 확인 → 필요한 부분 수정 → 같은 파일에 반영 → 다운로드**로 설계한다. 예를 들어 ‘추진 배경을 절반으로 줄여줘’, ‘예산표에 합계 행을 추가해줘’라는 요청은 해당 문단·표를 수정하며, 다른 영역의 확정된 내용과 서식을 유지해야 한다. 직원의 직접 수정 내용도 다음 재생성에서 보존하고, 충돌 시 변경 후보를 확인하게 한다.

처음에는 기관별 핵심 양식 5~10개를 검증된 양식으로 등록한다. 양식별로 글꼴·문단 간격·번호 체계·표 너비·병합 셀·머리말·꼬리말·쪽 번호·이미지·붙임을 시험한다. 내용이 길어질 때 표와 문장이 잘리는지, 쪽이 넘어갈 때 읽을 수 있는지 확인한다. 모든 임의 양식을 즉시 지원한다고 약속하기보다 지원 양식을 단계적으로 늘린다.

미리보기는 최종 생성 파일의 렌더링을 기준으로 한다. 채팅 화면의 예쁜 표나 별도 HTML 화면만 보고 파일 품질을 합격시키지 않는다. 필수 정보가 빠지면 파일과 서비스 화면에 미완료 상태를 표시하고, 확인할 항목을 모아 제공한다. 한글에서 파일 열기·본문과 셀 편집·다시 저장하기까지 확인해야 한다.

### 업무별 작업함

채팅마다 파일을 다시 올리는 구조를 피한다. 하나의 업무에 요청서, 관련 자료, 양식 버전, 담당자, 기한, 검토 상태, 결과물을 연결한다. 업무 상태는 ‘접수 → 자료 준비 → 작성 → 검토 → 완료’처럼 직원이 이해하는 말로 표현한다.

완료한 보고서의 같은 사실이 기안·감사 대응·인수인계에 재사용되도록 한다. 다만 초안과 승인된 결과물을 구분하고, 잘못된 초안이 다음 업무의 근거로 자동 편입되지 않도록 한다.

### 모든 비서에 필요한 검수

- 사실과 제안 구분, 근거 없는 내용 표시.
- 문서·셀·음성 구간 단위의 근거 연결과 원문 열람.
- 날짜, 대상 기간, 단위, 합계, 비율, 본문·표의 수치 일치 확인.
- 원본 대비 변경 내용과 버전 복구.
- 개인정보·기관 비공개 정보 처리, 문서·사용자 권한 적용.
- 출력 파일의 열림·표·줄바꿈·문서 구성 점검.
- 누락·충돌·판단 불가 항목을 모은 ‘확인할 사항’ 화면.

공통 검수 기능을 ‘11번째 비서’처럼 추가 과업으로 떠넘기지 않는다. 직원은 작업 결과에서 바로 확인하고 고칠 수 있어야 한다.

### 초기 사용자 화면

첫 화면에는 ‘할 일을 선택하세요’와 기관에서 쓰는 업무 카드 10개를 둔다. 파일을 먼저 올리면 적합한 비서를 추천한다. 기관·부서·양식·참조 문서 범위는 가능한 한 미리 설정해 둔다.

입력은 파일·대상 기간·용도·양식 등 최소 항목으로 구성하고, 빠진 사실만 추가로 묻는다. 진행 화면에는 완료한 단계와 막힌 항목을 표시한다. 결과 화면은 편집할 문서, 원본 근거, 확인할 사항을 가까이 배치한다. 모델명이나 프롬프트 작성법을 직원의 필수 선택으로 만들지 않는다.

### 대표 시연: 분기 실적 제출

1. 직원이 실적 제출 공문과 붙임을 올린다.
2. 접수공문 비서가 요청 항목·대상 기간·제출일을 추출한다.
3. 취합 비서가 담당 부서별 양식과 제출 현황을 준비한다. 실제 배포는 승인 후 진행한다.
4. 회신된 엑셀을 취합하고 미제출·단위·합계 오류를 보여 준다.
5. 규정 비서가 확인된 집계 기준과 근거를 제시한다.
6. 보고서 비서가 승인된 수치로 결과보고와 요약을 만든다.
7. 공문 비서가 제출 공문을 작성한다.
8. 담당자가 원본·검수 결과·산출물을 확인하고 기존 제출 절차로 전달한다.

이 하나의 시연에서 파일 정리·누락 확인·숫자 대조·작성·서식 보정에 들던 시간이 얼마나 줄었는지를 측정한다.

## 6. 구현·배포 전략

### 공통 처리 기반과 업무별 설정을 분리

공통으로 필요한 것은 문서 읽기, 근거 검색, 항목 추출, 표·계산, 문서 출력, 권한·이력 관리다. 각 비서는 입력 항목, 처리 순서, 승인된 규칙, 사용할 자료, 출력 양식, 평가 사례로 구분한다. 비서마다 같은 처리 기능을 따로 개발하면 수정과 검증 비용이 커진다.

개발의 첫 기술 관문은 실제 기관 양식으로 편집 가능한 HWPX를 만들고, 표·이미지·쪽 구성을 검증하는 것이다. 양식의 고정 부분과 AI가 채울 문단·표를 구분하고, 문서 구조와 내용을 별도로 관리한다. 양식 채우기·일부 수정·버전 복구를 공통 문서 생성 기능으로 제공한 뒤 10개 비서에 연결한다. 파일 생성이 불완전한 상태에서 채팅 기능만 먼저 확장하지 않는다.

AI는 문서 의미 파악·항목 대응·서술 초안을 맡고, 합계·비율·중복·필수 항목·파일 형식 검증은 명시된 규칙과 계산 도구로 처리한다. 애매한 항목 대응은 사람에게 후보와 근거를 보여 준다.

### 자체 개발할 것과 활용할 것

| 직접 경쟁력을 쌓을 영역 | 기존 기술·제품 활용을 검토할 영역 |
|---|---|
| 기관별 업무 절차, 양식·지표 정의, 검수 기준 | 언어모델과 기본 추론 기반 |
| 업무별 작업함과 비서 간 자료 재사용 | OCR·음성 전사·문서 변환 |
| 원본 대사·누락 탐지·검토 화면 | SSO·저장·암호화·모니터링 기반 |
| 현장 평가셋, 오류 개선, 도입·교육 방식 | 범정부 AI 공통기반·승인된 모델 서비스 |

문서 변환·한글 출력은 서버 환경과 라이선스·유지 비용까지 비교해 조달한다. 읽기 기능이 있다고 편집·출력 라이선스가 해결되는 것은 아니다. 모든 모델·OCR·변환·로그 처리의 실제 데이터 경로를 배포 형태별로 문서화한다.

### 연계는 세 단계

1. **파일 기반:** 직원이 허용된 파일을 올리고 검토 후 결과를 내려받는다. 최초 가치 검증에 적합하다.
2. **읽기 연계:** 공유폴더·규정관리·전자결재 이력 등 승인된 소스에서 필요한 자료를 가져온다. 원본 권한·버전·삭제를 반영한다.
3. **승인 후 쓰기:** 검토된 결과만 업무 시스템에 등록·회신·배포한다. 중복 등록 방지, 실패 시 재개, 실행 이력을 갖춘다.

파일 기반 실증이라도 기관의 반출·업로드 허용 범위를 먼저 정해야 한다. 내부 시스템을 여러 개 연결하기 전, 파일 기반만으로도 직원의 순업무시간이 줄어드는지 입증한다.

### 공공기관의 도입 환경

NIA의 [2026년 공공부문 AI 도입·활용 가이드 안내](https://www.nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=29526&cbIdx=37989)는 범정부 AI 공통기반의 활용 검토와 기획·예산·계약·구축·운영 절차를 설명한다. 따라서 자체 모델·서버 판매에만 의존하지 않고, 기관이 사용하는 공통기반이나 승인된 AI 환경에 업무 비서를 올리는 방식도 검토하는 것이 합리적이다. 실제 이용 대상·연계 허용·계약 조건은 기관별 확인 사항이다.

배포 방식은 기관의 정보 분류·망·운영 환경에 따라 선택한다. 공공 클라우드형, 기관 전용형, 폐쇄망형을 상품 구상 단계에서 구분하되 첫 실증을 세 방식으로 동시에 개발하지 않는다. 첫 고객의 승인된 환경 하나에서 공통 제품을 완성한 뒤 확장한다.

‘국내 서버’, ‘온프레미스’, ‘모델 학습에 미사용’이라는 표현만으로 외부 전송·보관·접근 문제가 모두 해결되는 것은 아니다. 외부 모델·OCR·전사·오류 로그·지원 인력 접근까지 확인해야 한다. 개인정보보호위원회는 생성형 AI의 생애주기별 개인정보 처리 고려사항을 안내한다. [개인정보 처리 안내서 공개](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11410)

클라우드 인증·보안성 검토·조달 방식은 실제 배포 형태와 당시 제도를 기준으로 적용 범위를 확인한다. 특정 회사의 인증이나 인증된 기반 시설 사용을 우리 서비스 전체의 인증으로 표시하지 않는다. 실증 단계에서 보안·개인정보·기록관리 담당자와 요구사항을 정리하고, 정식 제공 전에 필요한 검증·계약 절차를 완료한다.

## 7. 품질을 상품으로 만드는 방법

### 평가 자료를 먼저 만든다

비서별로 승인된 입력과 기대 결과를 한 쌍으로 확보한다. 정상 사례만 모으지 않고, 과거 양식·개정 규정·표의 병합 셀·틀린 합계·누락 파일·상충하는 기한·답이 없는 질문·권한 없는 자료·악성 문서 지시가 섞인 사례를 넣는다.

초기 핵심 비서별 50건 정도로 빠르게 개선하고, 출시 전에는 업무의 변형을 포괄하는 100~200건 수준으로 확대하는 안을 권한다. 건수 자체보다 실제 예외 상황의 범위가 중요하다. 개발에 사용한 사례와 최종 평가용 사례를 분리하고, 직원·검토자가 정답과 오류의 심각도를 확정한다.

| 평가 대상 | 확인할 내용 |
|---|---|
| 문서 읽기 | 본문·표·각주·별표·수식·숫자를 정확히 읽었는가 |
| 근거 찾기 | 맞는 기관·버전·시점·적용 범위의 자료인가 |
| 결과 내용 | 인용이 주장을 뒷받침하고 누락·과장이 없는가 |
| 계산 | 집계 규칙과 단위가 맞고 원자료와 대사되는가 |
| 출력 | 실제 사용하는 프로그램에서 열리고 수정·제출할 수 있는가 |
| 통제 | 권한 변경·삭제·예약 실행에도 같은 정책이 적용되는가 |
| 업무 성과 | 검토·수정까지 포함해 완료 시간이 줄었는가 |

### 제안하는 출시 관문

아래는 초기 협의용 목표이며 현재 달성한 수치가 아니다. 업무의 위험도에 따라 기관과 확정한다.

- 실증 중 실제 과제의 85% 이상이 수작업 전면 재작성 없이 검토 가능한 결과까지 도달.
- 핵심 업무의 검토·수정·서식 보정·재시도까지 포함한 순처리시간 중앙값 30% 이상 감소.
- 명시된 중요 필드의 추출과 인용 근거의 타당성은 각각 별도 평가하며, 우선 98% 이상을 목표로 설정. 기한·금액·대상 혼동 등 중대 오류가 나오면 원인 수정과 재검증 전 해당 경로 출시 보류.
- 검증용 권한 시험에서 비인가 정보 노출, 승인 없는 대외 실행 0건. 시험의 0건은 운영상 무사고 보증이 아니다.
- 승인된 양식 시험군의 결과 파일이 모두 정상적으로 열리고, 필수 항목·표 구조가 유지됨. 지원하지 않는 양식은 명시적으로 안내.
- 문서 업무는 실제 HWPX 파일 생성까지 도달해야 완료로 집계한다. 한글에서 본문·표가 편집 가능하고, 서비스 안에서 요청한 수정이 파일에도 반영되어야 한다. 문장 복사·붙여넣기, 표 재작성, 서식 재구성에 필요한 시간을 따로 측정한다.

평균 점수 하나로 합격시키지 않는다. 정보 노출이나 중요한 숫자 오류가 일반 문장 품질 점수에 가려져서는 안 된다. 근거가 없거나 모호한 경우 실행을 멈추고 직원에게 필요한 확인 항목을 알려주는 기능을 포함한다.

### 운영 중 개선

문서·양식·모델·검색 방식·권한 정책이 바뀔 때 평가를 다시 한다. 오류는 ‘읽기·검색·기준 선택·계산·서술·출력·권한·실행’으로 나눠 기록하고 발생 빈도와 영향으로 개선 순서를 정한다. 사용자 수정본을 무조건 학습하거나 다른 기관에 공유하지 않는다. 원인을 검토하고 권한·동의·자료 사용 범위 안에서 개선 자료로 편입한다.

규정은 소관 부서가 최신성·효력일·승인 상태를 관리한다. 제품 운영팀은 모델·도구·오류를 관리하고, 기관 업무 담당자는 결과의 사실과 업무 기준을 검수한다. 책임 주체가 없는 지식 자료는 자동으로 최신 자료처럼 취급하지 않는다.

기간은 시작일 기준의 제품 개발·실증 가안이다. 기관 예산·조달·보안 검토·서버 반입·연계 승인 기간은 별도로 관리한다. 기관 자료 접근과 검수 담당자 확보가 선행 조건이다.

|---|---|---|---|
| 0. 현장 문제 확정 | 1~2주 | 15~20명 인터뷰, 실제 업무 관찰, 요청서·원본·완성본·반려 이유 확보, 정보·권한·구매 환경 조사 | 반복 업무 3개와 검수 담당자 확정, 허용된 시험 자료 확보 |

## 9. 성과 측정과 사업 모델

### 실제 시간 절감

순절감 시간 = 기존 업무의 전체 시간 - AI 사용 시 전체 시간.

AI 사용 시 전체 시간에는 자료 준비·업로드·프롬프트 입력·결과 대기 때문에 실제로 막힌 시간·직원 검토·수정·서식 보정·재시도·제출 준비를 포함한다. 시스템이 처리하는 동안 다른 일을 할 수 있는 대기시간과 직원의 실제 투입시간은 구분해 기록한다. 유사 난이도의 업무를 비교하고 처음 배우는 기간도 별도로 표시한다.

예시로 기존 120분인 취합 업무가 자료 준비 10분, 검토·수정 30분, 제출 준비 5분으로 바뀌면 직원 투입 기준 75분 절감이다. 이는 설명용 계산이며 실증 결과가 아니다. 업무 난이도·빈도가 다른 과제를 섞어 평균만 내지 않는다.

핵심 대시보드는 완료 과제 수, 실제 순절감 시간, 검토 후 채택률, 재작업률, 중요 오류, 반복 사용, 과제당 비용을 표시한다. 비서 간 연결로 같은 시간을 두 번 절감했다고 집계하지 않는다. 사용량·추정 절감·실측 절감을 구분한다.

절감된 시간을 임금으로 환산한 잠재 가치를 실제 인건비 예산 절감으로 표현하지 않는다. 성과에는 초과근무 부담·반려·누락·응답 지연의 변화도 함께 기록한다.

### 권하는 판매 구성

- **실증 계약:** 대상 업무 3개, 기간, 기관이 제공할 자료·검수 인력, 완료 기준, 후속 도입 판단을 명확히 한다.
- **초기 10개 패키지:** 기관 양식·규정 설정, 사용자·관리자 기능, 교육, 지원 범위, 포함 사용량·비용 한도를 묶는다.
- **별도 비용 항목:** 업무 시스템 연결, 대규모 데이터 정리, 별도 배포 환경, 특수 양식·보안 연계. 첫 계약부터 지원·변경 범위를 명시한다.

가격은 모델 호출 원가만으로 정하지 않는다. OCR·음성·변환·저장·모니터링·기관별 지원·업데이트와 보안 운영 비용을 포함해 계산한다. 직원에게는 토큰보다 완료한 업무와 잔여 사용 한도를 보여 주는 편이 이해하기 쉽다.

기관별 변경은 가능한 한 양식·필드·규칙 설정으로 수용하고, 별도 코드 분기를 최소화한다. 두 번째 기관에서 설정·검증·교육 시간이 얼마나 줄어드는지가 확장 가능한 사업인지 판단하는 지표다.

## 10. 처음에는 뒤로 미룰 기능과 확장 순서

초기에는 이미지·동영상 제작, 범용 번역, 투자 리포트, 모든 직원용 노코드 빌더, 광범위한 PC 자동조작을 중심 상품으로 두지 않는다. 필요할 때 기본 도구나 외부 연계로 제공할 수 있지만 공공기관 직원의 반복 행정 업무를 줄이는 첫 성과와는 분리한다.

채용·평가·복지 자격·인허가·행정처분의 자동 결정, 자동 지급·계약 확정, 근거 없는 법률 판단도 초기 범위에서 제외한다. 관련 자료 정리·검토 보조는 지원하되 최종 판단과 실행은 별도로 둔다.

‘AI가 쓴 글 판별’은 행정 업무 부담 절감과의 연결이 약하므로 초기 10개에 포함하지 않는다. 이 문서에서 해당 기능의 판별 정확도를 시험하거나 평가한 것은 아니다.

| 출장·행사 운영 | 승인·일정·정산 연계가 반복되고 개인정보 처리가 정리됨 |
| 정책·법령 변경 영향 알림 | 변경된 조문을 연결된 업무·양식과 매핑하고 오탐을 검수할 담당자 확보 |
| 경영공시 자료 점검 | 공시 항목·기준일·지표 정의와 승인된 원자료 확보 |
| 홍보·보도자료 | 근거 사실·승인 표현·개인정보 확인과 대외 배포 절차 확보 |
| 산업별 특화 | 금융·기업지원·시설·교육 등 특정 기관군에서 반복 수요가 확인됨 |

신규 비서마다 실제 업무 사례 20건 이상, 현업 책임자, 허용된 자료, 기존 기능과의 차이, 순절감 목표, 평가셋을 확보하는 절차를 권한다. 처음에는 한 번에 하나씩 추가하고, 한 달 이상 운영에서 가치가 확인된 뒤 다음 후보를 연다. 기존 비서의 품질·장애 대응에 필요한 자원을 먼저 확보한다.

## 11. 바로 실행할 첫 2주 체크리스트

1. 첫 기관군을 하나로 정하고 실무·검토·정보화·보안 담당자의 참여를 확보한다.
2. 취합·기안·규정 확인의 실제 업무 묶음을 각각 확보한다. 자료 사용 허용 범위를 기록한다.
3. 직원이 기존 방식으로 한 과제를 처리하는 과정을 관찰하고 단계별 투입시간을 잰다.
4. 기관 대표 양식 5~10개, 빈번한 질문과 정답, 취합 오류 사례를 고른다.
5. 같은 자료로 경쟁사·기존 기관 도구·우리 시제품을 비교할 평가표를 만든다.
6. ‘분기 실적 제출’ 흐름을 시연으로 만들고 직원이 고쳐야 한 부분을 기록한다.
7. 성과가 가장 큰 업무부터 개발 범위와 출시 조건을 확정한다.

첫 제품 의사결정은 ‘어떤 모델을 쓸까’보다 **‘어떤 반복 업무를 어떤 완성본까지 책임질까’**로 시작하는 것이 좋다.
