## 1. 확인 범위

브라우저에서 `/`, `/login`, `/login?role=admin`의 공개 화면을 확인했다. 직원·관리자 로그인 이후 화면은 실행 검증하지 않았다. 내부 기능은 내려받은 저장소의 실제 파일·스키마·테스트 정의로 확인했다. 공급사나 기존 README의 ‘완료’ 표기만으로 운영 동작을 보증하지 않는다.

## 3. 실제 코드에서 발견한 핵심 차이

### A. 현재 제품의 주 흐름은 대화

`src/app/page.tsx`의 `ViewMode = 'welcome' | 'chat'`, `ChatInterface`, `AgentSelector`가 중심이다. 파일이 생겨도 `MessageBubble.tsx`에서 말풍선 아래 다운로드 카드로 제시한다. 새 제품은 업무와 결과 파일이 중심이고, 대화는 해당 업무에 연결된 보조 패널이 된다.

### B. 파일 생성 전 반복 확인

`src/lib/capabilities/document.ts`의 `DOCUMENT_ADDENDUM`은 목차 확인 후 초안을 채팅에 쓰고 다시 파일 생성을 묻도록 한다. 실패 시 복사 사용을 권하기도 한다. 새 작업 화면에서 직원이 ‘파일 만들기’를 누른 것은 초안 파일 생성 요청이다. 정해진 양식과 필수 자료가 있으면 별도 반복 질문 없이 생성한다. 미확인 사실을 지어내지 않는 원칙과 대외 전송의 승인 절차는 유지한다.

### C. 양식 바이너리의 준비 상태

`assets/templates/README.md`와 `builtin-templates.ts`는 공문·보고서·회의록 3종 HWPX를 정의하지만 분석한 체크아웃의 해당 폴더에는 README만 있다. `tests/builtin-templates.test.ts`는 파일이 없으면 실제 양식 검사 3건을 건너뛴다. **저장소에 기본 파일이 없다는 확인이며, 운영 Storage에 기관 양식이 없다는 뜻은 아니다.** 출시 전 기본 양식의 실제 공급·배포 포함·한글 검증을 필수 관문으로 변경한다.

### D. 현재 HWPX 채우기는 텍스트 중심

`doc-fill/index.ts`의 값 입력은 `{slot_id,text}` 목록이다. 자리 100개·자리당 6,000자 상한을 가진다. 기존 S2 설계는 새 표 삽입·행 증식 등을 후속으로 남겼다. 원본 표의 글을 채우는 것과 새로운 행·그림·차트를 만드는 것은 다른 지원 항목이다. 기존 엔진을 ‘완전한 한글 편집기’로 표시하면 안 된다.

### E. 결과 파일이 대화 삭제에 종속

`supabase/migrations/0029_generated_files.sql`의 `conversation_id`는 NOT NULL이며 ON DELETE CASCADE다. `generated-files.ts`도 대화의 저장소 파일 정리를 담당한다. 새 업무 결과물을 여기에만 저장하면 대화 정리로 업무 자료가 사라진다. 새 업무 파일은 별도 테이블·경로에 영속 보관하고, 옛 파일은 선택적으로 복사 가져오기 한다.

### F. 엑셀은 현재 계산 값 중심

`xlsx-export.ts`는 계산된 값과 계산 근거를 쓰고 수식은 쓰지 않도록 명시한다. 이 감사용 결과의 의미를 보존한다. 재계산 가능한 작업용 엑셀이 필요하면 별도 출력 모드로 추가하고 서버 계산 값과 수식을 함께 검증한다. 모든 엑셀에 수식을 넣도록 기존 기능을 바꾸지 않는다.

### G. 권한은 화면 숨김으로 해결되지 않음

현재 서버의 `supabaseAdmin`은 service role이다. RLS만 추가해 서버 권한 검사가 해결됐다고 주장하지 않는다. 업무 조회·자료 재사용·미리보기·다운로드·백그라운드 실행마다 현재 사용자·기관·작업 접근 범위를 검증해야 한다. 원본 자료 권한과 결과물 공유 범위를 독립적으로 넓히지 않는다.

## 4. 유지·교체·추가

- 유지: 사용자·기관·부서 ID, 인증, 관리자 운영, 과거 대화, 비서 버전, 과금 이력, 자료·NODA 연결, 문서·표 엔진.
- 교체: 직원 메인 구조, 비서 진입 방식, 생성 전 확인 단계, 결과 제시·수정 경험, 사용 성과 지표.
- 추가: 작업함, 버전별 문서 내용, 양식 검증·버전, 내구성 있는 작업 실행, 실제 파일 미리보기, 검토 항목, 새 업무 파일 보관, 원본 대응, 완료·절감 측정.
- 보류: 프레임워크 전면 업그레이드, 새 AI 제공사, 외부 음성 서비스, 임의 HWPX 완전 편집, 자동 발송·지급.

## 5. 구현 전 재확인

현재 HEAD, 작업 중 변경, 마이그레이션 적용 상태, 실제 양식 파일, NODA 계약, 로컬·스테이징의 키 준비, 문서 렌더러, 한글 검증 가능한 환경을 확인한다. 키 값·사용자 원문은 보고서에 출력하지 않는다. 기존 문서에 적힌 테스트 건수는 기록이며 이번 분석에서 재실행한 결과가 아니다.
