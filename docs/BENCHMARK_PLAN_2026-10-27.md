## 0. 결론 먼저

1. **방향은 맞다.** 두 회사 모두 "대화 + 도구 + 미니앱" 플랫폼이고, 결과물은 직원이 다시 옮겨 적는다. WORKON은 기관 양식에 맞는 **실제 HWPX·XLSX 파일**을 만들고 검토·수정·새 판까지 한 흐름에 둔다. 웍스AI가 2026-07에 낸 '문서 작성 Pro'(양식 올리면 단락마다 자동 작성, 별도 로그인·브라우저 저장·HWP는 본문만)가 가장 가까운데, 우리는 숫자 대조·근거 번호·판 기록·권한을 안에 두고 있다. 이 자리는 지킨다.
2. **10개 업무는 그대로 둔다.** 웍스AI 정부/공공 비서 8종(음슴체·개조식·홍보문·공문·보고서·민원·연설문·회의록)은 전부 '글 변환'이고, 그중 파일이 되는 건 우리 10개에 이미 있다(공문·보고서·민원·회의). 우리에만 있는 취합·정산·규정·접수·인수인계·감사는 두 회사 어디에도 없다. 다만 **열 개 모두 실제 모델로 화면에서 돌려 본 적이 없다**(장부 5절) — 비서를 늘리기 전에 이것부터다.
3. **다음에 더할 비서는 두 회사의 '웍스+' 미니앱에서 고른다.** 공공기관 서무·기획이 매일 하는 일이면서 새 업체가 필요 없는 것 다섯: ① 증빙 서류 → 엑셀(사업자등록증·통장사본·영수증) ② 제출 전 문서 점검(맞춤법·숫자·표현·공문 형식) ③ 양식 분배(취합의 반대) ④ 정기 모니터링(법령 개정·입찰공고·보도, 예약 실행 + 메일) ⑤ 보도자료·홍보문 + 부적절 표현 검사. 순서와 근거는 6절.
4. **보안·관리 소품은 기능이 아니라 보안성 검토 체크리스트다.** 2FA, 대화·파일 보존·삭제 정책, 신규 가입 수동 승인, 개인정보 **마스킹**(지금은 차단만), 문서 워터마크. 두 회사 다 있고 공공기관 심사에서 실제로 묻는다. 작고, 1단계에 넣는다.
5. **하지 않을 것도 정한다.** 멀티 프로바이더, 이미지·영상 생성, 코딩 에이전트, 데스크톱 앱, 노코드 워크플로우 빌더, 브랜드 모니터링. 이유는 7절.

### 1-2. 에이전트 구조 (가이드 1편)

| 층 | 누가 만드나 | 공유 | 특징 |
|---|---|---|---|
| 나만의 에이전트 | 직원 | 본인 | 모델 선택 → 이름·프롬프트 → 요술봉 → 파일(100MB/개, 여러 개) → 도구 최대 5개 → 만들기 |
| **팀 에이전트** | 부서원 누구나 | 같은 부서, **승인 없이 즉시** | 부서원 누구나 수정. 에이전트당 파일 1만 개 |
| 워크스페이스 에이전트 | 관리자 | 워크스페이스 | 카테고리 공개 범위(전체/일부/비공개)·노출 순서 |
| 전사 에이전트 | 관리자 | 회사 전체 | 직원 신청은 워크스페이스까지만 |

- 공식 등록 신청은 **신청 시점 스냅샷**(이후 수정 미반영). 공유되는 것: 이름·아이콘·설명·지시문·도구 연결 설정·업로드 파일(답변 참조만, 원본 다운로드 차단). 공유 안 되는 것: 대화·OAuth 토큰.
- 가이드가 거듭 말하는 것: **"파일은 꼭 필요할 때만 올려라 — 많을수록 성능이 떨어진다"**, "도구는 꼭 필요한 것만 — 토큰도 아끼고 응답도 좋아진다".
- 대화 시작 가이드(예상 질문 버튼 최대 6개), 제작자 표시, 월 이용 횟수.

→ WORKON 대조: 세 단계(`personal`·`department`·`official`)와 판 기록(`agent_history`)은 이미 같은 꼴이다. **다른 점 하나** — 저쪽 팀 에이전트는 승인 없이 즉시 부서 공유이고 부서원 누구나 수정한다. 우리는 부서 비서도 판을 남기고 권한 판정을 거친다. 공공기관은 '누가 고쳤나'가 남아야 하므로 우리 쪽이 맞다.

### 1-4. 공공·법령·통계 도구 (가이드 3편) — 같은 데이터, 다른 완성도

우리 커넥터 4종(법제처·KOSIS·나라장터·DART)과 데이터 원천이 **같다.** 차이는 결과를 다듬는 깊이다.

| 도구 | 웍스AI가 더 하는 것 | 우리 |
|---|---|---|
| 국가법령정보 | 조문·항·호 단위 설명, 가지조문, 자치법규(지역 필수), 시행령 검색, 다른 도구 연계(Notion·메일) | 검색·본문 조회. **규정 확인 업무**가 기준일·시행일·유보 판정까지 하므로 '판단'은 우리가 깊다 |
| 나라장터 | 발주예정 → 사전규격 → 진행중 3단계 파이프라인, 공고 상세 분석, **RFP 자동 분석**(목적·과업·배점·제출물·일정·리스크), 적격심사 예측, 투찰 시뮬레이션, 낙찰 이력·담합 시그널, 결과 시각화 | 공고 검색만. 투찰·적격심사는 **민간 공급자 기능**이라 공공기관(발주처) 직원에게는 필요 없다. 발주처가 쓰는 건 '유사 사업 낙찰 결과·추정가격 참고'·'RFP 작성'이다 |
| KOSIS | 일상어 → 통계 용어 변환, 항목·분류 탐색, 시계열 추출, 차트 자동, 2차 분석(YoY·이동평균), **출처·기준 시점 명시**, 종합 보고서 | 표 검색·데이터 조회. 보고서 업무에 '통계 근거 표' 넣기는 아직 없다 |

### 1-6. 3.0 업데이트에서 읽히는 전략 (2025-10 ~ 2026-07, 48건)

- 순서: 멀티 LLM(2025-11) → 허용 모델 통제(12월) → 에이전트(2026-03~07) → 공공·금융 도구 16종(05~07) → MCP 허브·워크플로우·코딩 에이전트(07). **모델·도구·연결**이 세 축이고, "문서를 실제로 만든다"는 문서 작성 Pro·슬라이드·회의록 Pro로 2026-04~07에야 붙었다.
- 비서 → 에이전트 강제 전환(2026-08-10): 자동 이전 없음, 대화 이력·지식 파일 못 옮김. 문서 작성(기존) → Pro도 2026-07-29 종료. **기반 API를 남의 것에 두면 고객이 다시 만든다**는 사례가 두 번째다.
- 관리자 장치는 "보안성 검토와 내부 감사에서 실제로 물어보는 항목"을 하나씩 채웠다고 스스로 적는다: AI 기본법 대응(민감정보 경고·AI 창작물 표시·영향평가서), API 키, 보존 정책, 워터마크, 감사 다운로드 사유, 민감정보 처리 라벨, 파일 형식 제한. → **우리 보안성 검토 자료의 체크리스트로 그대로 쓸 수 있다.**

### 1-7. 웍스AI의 약한 자리 (우리 관점)

1. **"서버에 남기는 고객 데이터 0건"의 뒷면** — 기관 자료가 축적되지 않는다. 지난달 보고서를 근거로 올해 보고서를 쓰는 일, 감사에서 "그때 무엇을 보고 썼나"를 답하는 일은 저장이 있어야 된다. 우리는 판·근거·사용 기록을 기관 DB에 남긴다.
2. **기능 69종의 피로** — 공공기관 직원은 "뭘 써야 하지"에서 멈춘다. 우리 업무 홈은 10개다. 적은 게 장점이 되려면 10개가 각각 끝까지 가야 한다.
3. **유료 부가서비스** — 감사 로그·접속 통제·삭제 정책·가드레일·파서가 일 단위 과금. 1,000명 기관이면 월 90만원 추가. 우리는 기본.
4. **문서 작성 Pro가 별개 서비스** — 이메일 로그인, 로그인 정보는 브라우저 저장, HWP는 이미지 미포함, "숫자·날짜·고유명사는 제출 전에 꼭 직접 확인하세요". 우리는 숫자를 원자료와 대조하고 틀린 곳을 검토 항목으로 띄운다.
5. 나라장터 도구의 절반(투찰·적격심사·담합)은 **입찰 참여 기업용**이다. 발주하는 공공기관에는 쓸모가 없다.

## 2. 알리웍스(Allganize Alli Works) — 구조와 운영 루프

### 2-1. 제품 구성

- 알리 웍스(에이전트 실행 환경) · 알리 웍스 데스크톱(폐쇄망, 엑셀·PDF·PPT 로컬) · 딥리서치 · Documents 2.0(문서 이해·추출) · Alli Coworker(Slack·Teams).
- **SaaS·온프레미스 단일 코드베이스**, 고객별 SSO·OCR·암호화는 플러그인. 공공·금융 규제 환경은 온프레미스. 300곳+(한·미·일), 1인 주당 11시간 절약 주장.
- Alli RAG: 권한 기반 검색, 답변 근거 추적, **스스로 검증·재탐색하는 Agentic RAG**, 원본 레이아웃 위에 인용 하이라이트, 맵리듀스로 100만 행 엑셀·500MB Word.

### 2-2. 앱 세 가지 (우리 설계와 맞대 볼 지점)

| 앱 | 무엇 | WORKON에 대응하는 것 |
|---|---|---|
| **답변형 앱**(싱글턴) | 입력 폼 6종(문서 업로드·문단 텍스트·단일 선택 …) + 모델 + 시스템/유저 프롬프트 + 긴 입력 처리(그대로·맵·맵리듀스) → 결과 복사·문서 다운로드 | **업무 작업**의 입력 폼 + 생성. 우리는 결과가 실제 파일이고 검토 항목이 붙는다 |
| 대화형 앱 | 노드 빌더(문서에서 답변·Q&A·LLM·조건·입력 폼·담당 멤버 연결·이메일·연동·MCP·딥 리서치) | 없음 — **의도적으로 안 만든다**(7절) |
| 에이전트형 앱 | 인스트럭션 + 변수 + MCP 도구, 버전 관리(저장·공개 이력, 과거 판 공개) | 비서 + 능력 + 판 기록(`save_agent`) |

- 앱 마켓: 기본 앱 100+, 카테고리 8(일반·세일즈·고객 지원·마케팅·IT·인사·법률·기타), 대화형/답변형 아이콘, '앱 테스트'·'앱 관리에 추가', **앱 요청**.
- **앱 공개 결재**: 승인자 지정 → 상신(사유) → 승인/반려 → 공개. 승인 대기 중 수정 불가, 승인 뒤 수정하면 다시 결재. → 우리 '공식 등록 승인'과 같은 자리. 우리는 승인 판 도장(`approval_version`)으로 "승인한 그 판"을 고정한다.

| 장치 | 내용 |

### 2-4. 알리웍스의 약한 자리 (우리 관점)

- 앱을 **관리자가 노드로 조립**해야 한다. 공공기관 담당자가 '조건 추가 노드'와 '변수 내보내기 노드'를 만질 가능성은 낮고, 결국 구축 용역이 붙는다(온프레미스 전제가 그걸 말한다).
- HWP는 "일부 형식과 DRM은 별도 구성". 한글 양식에 맞춰 **파일을 만드는** 앱은 보이지 않는다.
- 가격이 공개돼 있지 않다(도입 상담). 소규모 기관이 바로 쓸 수 없다.

## 4. 무엇이 "정말 도움이 되는" 서비스인가

벤치마크 두 회사와 우리 장부를 놓고 판단한 기준 세 가지.

1. **직원이 옮겨 적지 않아야 한다.** 답을 화면에서 읽고 한글에 다시 치면 절감이 반으로 준다. 웍스AI가 뒤늦게 문서 작성 Pro·hwpx 내보내기를 붙인 이유다. 우리는 처음부터 파일이다.
2. **틀린 숫자가 그럴듯하게 나가지 않아야 한다.** 두 회사 가이드 모두 "숫자·날짜는 직접 확인하세요"로 끝난다. 우리는 취합·정산에서 모델을 아예 안 부르고, 문서 업무에서 숫자를 원자료와 대조한다. 이 원칙이 공공기관에서 가장 비싼 오류(보고서 숫자)를 막는다.
3. **기관에 남아야 한다.** 판·근거·사용 기록이 기관 DB에 있어야 감사 대응과 다음 해 보고서가 된다. "데이터를 저장하지 않는다"는 민간 보안 문구이지 공공기관 요건이 아니다.

이 기준으로 보면 **업무 10개는 적중한 선택**이다. 다만 벤치마크가 보여 주는 '진짜 반복 부담' 중 우리에게 없는 것이 있다. 공공기관 서무·기획·사업 부서가 매주 하는 일로 좁히면:

| 반복 업무 | 지금 어떻게 하나 | 벤치마크 | 우리 후보 |
|---|---|---|---|
| 보조금·지급·계약 서류에서 사업자번호·계좌·금액을 엑셀로 옮김 | 손으로 타이핑 | 웍스+ 텍스트 추출(20개 일괄) | **증빙 서류 정리** |
| 공문·보고서 제출 전 오탈자·숫자·표현 점검 | 동료가 봐 줌 | 웍스+ 문서 건강검진, 부적절 표현 | **제출 전 점검** |
| 부서별 양식 보내고 회신 모음 | 메일 20통 | 웍스+ 양식 분배·취합 | 취합 ✅ + **분배** |
| 우리 기관 관련 법령 개정·입찰 공고·보도 매주 확인 | 담당자가 사이트 순회 | 대화 예약 + 워크플로우 템플릿(법령 개정 모니터링·입찰 공고 알림) | **정기 모니터링** |

## 6. 단계별 계획

각 단계는 "앞 단계가 운영에서 돌고 있다"가 전제다. 기간은 한 사람 기준 대략치이고, 출시 뒤 실제 사용 데이터가 순서를 바꿀 수 있다.

### 0단계 — 개편 출시 마감 (지금 ~ 2주) · 코드보다 확인

1. 10개 업무를 **실제 모델로 화면에서** 한 번씩(지금은 서버 점검 8개뿐). 산출 파일을 한글에서 열어 사람의 시각 검토 기록(`verification.json` `human-visual`).

| 멀티 프로바이더(100종) | 공공기관 보안성 검토에서 사업자가 늘면 소명할 곳이 는다. 어댑터 계층(`src/lib/llm/`)은 준비돼 있으니 **요구가 생기면** 하나씩 |
| 노코드 워크플로우·대화형 앱 빌더 | 공공기관 담당자가 노드를 조립하지 않는다. 우리 방식은 '고정 업무 + 기관 양식'이고, 자유도는 양식·칸 대응·사업 정보로 준다 |
| 코딩 에이전트·사내 전용 배포 | 공공기관 PC·망 환경과 맞지 않고 우리 제품 범위 밖 |
| 데스크톱 앱(웍스AI Desk·알리 데스크톱) | 설치 권한·보안 프로그램·망분리. "파일이 안 나간다"가 필요한 기관일수록 못 깐다(2026-08 판단 그대로) |
| 이미지·영상 생성, 프로덕트 스튜디오 | 홍보 부서 한정, 새 업체 |
| 브랜드 모니터링 | 상시 수집 과금형. 기관 언론 모니터링은 ④ 정기 모니터링의 '보도' 갈래로 축소해 흡수 |
| 메모리 | 기관 문서·사업 정보가 기억이다. 개인 기억은 감사 대응을 어렵게 한다 |
| 감사 로그·접속 통제의 유료화 | 기본 제공이 우리 포지셔닝 |
| 나라장터 투찰·적격심사·담합 | 입찰 참여 기업용 |

## 9. 아직 모르는 것

- 두 회사 모두 **실제 답 품질·파일 품질**은 공개 자료로 알 수 없다. 1단계 평가 사례 묶음으로 우리 것부터 잰다.
- 웍스AI 가이드 2·4편(협업 도구·금융)은 머리만 읽었다. 공공기관 직원 업무와 멀어 생략했지만, 재단·공기업의 회계 부서는 DART·ECOS를 쓸 수 있다.
- 우리 **첫 기관 유형**(지방공기업·협회·재단)에서 ①~⑤ 중 무엇이 실제로 자주 일어나는지는 출시 뒤 사용 기록으로만 안다. 2단계 순서는 그때 바꾼다.
