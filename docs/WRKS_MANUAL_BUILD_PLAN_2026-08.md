# 웍스AI 매뉴얼 20편 전수 분석과 WORKON 구축 계획

**작성일**: 2026-08-19
**대상**: docs.wrks.ai 사용자 매뉴얼 5편 + 관리자 매뉴얼 15편 (전수)
**대조**: WORKON 실제 코드 확인 (추정 없음 — 확인한 파일을 각 항목에 표기)

> 경쟁 서비스 **공개 문서** 분석입니다. 화면 모방이 목적이 아니라,
> "공공기관 담당자가 당연하게 기대하는 기능선"을 잡고 우리 공백을 찾는 용도입니다.

# 1부. 문서별 분석

## 사용자 매뉴얼

### U1. 회원가입 (`user-guide/signup`)

**핵심**: 관리자 초대 메일 → 회사 이메일로 가입 → 이메일 인증 → 자동으로 해당 기업 계정 소속 → 파란 **튜토리얼** 오버레이.

**개인정보 동의 범위가 명시돼 있음**:
- 제공 항목: 이름 / 이메일 / 조직도
- 회사에 제공되는 것: **사용 통계 (대화 내용 제외)**

**WORKON 현황**: 초대 링크 + CSV 일괄 등록 있음. `signup/route.ts`가
`email.split('@')[1]`로 도메인을 조회해 기관을 특정 — 같은 모델.
**튜토리얼 없음. 동의 항목 화면 없음.**

**시사점**: '대화 내용 제외'가 계약 문구가 아니라 **제품 동작**으로 존재한다는
점이 중요합니다. WORKON은 여기서 어긋나 있습니다(→ 5부 D1).

---

### U2. AI 대화 (`user-guide/agents`)

**핵심**: 모델 드롭다운 40종+(웍스 대표 / OpenAI / Google / Anthropic / Perplexity / xAI),
새 대화, 대화 공유(링크 복사 · 공유 중단), 이미지 생성 및 저장.

**WORKON 현황**: 단일 모델 고정(`claude-sonnet-4-6`). 대화 공유·중단 있음.
이미지 생성 없음.

**시사점**: 모델 선택은 최대 격차지만 공공기관에서는 양날입니다 — 모델이 늘면
"어떤 데이터가 어느 사업자에게 갔는지"를 전부 소명해야 합니다. **기관 관리자가
허용 모델을 고르는 형태**가 아니면 오히려 보안성 검토에서 불리합니다.

---

### U3. 우리 회사 비서 (`user-guide/company-assistants`)

**핵심**: 비서가 **카테고리 탭**으로 분류(채팅/번역/그림/회사 전용). 첫 카테고리에
사내 데이터 참조 비서. 왼쪽 사이드바에 대화 목록.

**WORKON 현황**: 카테고리 탭 + 즐겨찾기 있음. 단, **관리자가 공식 비서의
카테고리를 지정할 수단이 없음**(`AgentsManager.tsx` 폼에 필드 없음). 컬럼은 존재
(`db.ts`의 `category`, `icon`).

---

### U4. 나만의 비서 (`user-guide/personal-assistants`)

**핵심**: 이름 / 역할 프롬프트 / 아이콘 / **프롬프트 요술봉** / 파일 첨부.
**능력 토글 3종**:

1. 텍스트 위주 파일 읽기
2. 숫자 위주 파일 읽기
3. 실시간 검색 + 그림 그리기

1과 2는 **상호 배타**, 3은 둘 중 하나와 조합 가능.
공식 등록 신청 시 추가 입력: 비서 소개 / 사용 방법 / 다듬은 역할.

**WORKON 현황**: `CreateAgentModal.tsx`에 아이콘·카테고리·역할·파일 첨부·요술봉
모두 있음. 능력은 **파일 분석**만 활성, **실시간 검색은 "준비 중"으로 비활성**.

**시사점**: 커넥터 4종이 실동작(2026-08-19 실호출 10/10 통과)하는데 라벨이
뒤처져 있습니다. 다만 그냥 열면 안 됩니다 — 커넥터는 관리자가 켜는 설계입니다.

### U5. senGPT / 서울시교육청 (`user-guide/specific-organizations/sengpt`)

**대형 공공 테넌트의 실제 운영 방식이 드러나는 유일한 문서. 가장 참고할 것이 많음.**

| 항목 | 내용 |
|---|---|
| 접속 | 별도 도메인 `gov.wrks.ai` + **"공공기관 로그인"** 버튼 |
| 가입 | `@sen.go.kr` **전용**. `hs.kr`·`ms.kr` 등 타 도메인 거부 |
| 대상 | 2024-09부터 서울시교육청 전 직원 **무상** |
| 비서 | 공식 비서 + **기관 전용 비서**(서울 교육법규·생기부 지침 학습) |
| 고지 | 출처 표기 + **"AI가 거짓 정보를 만들 수 있음"** 명시 |
| 운영 이슈 | 웹메일 휴면 계정 → 인증 실패. 반송 후 24시간 재발송 제한 |

**WORKON 현황**: 도메인 기반 기관 특정은 이미 있음. **별도 접속 경로·기관 전용
브랜딩·AI 고지 문구는 없음.**

**시사점**: 공공기관 대형 계약은 "우리 기관 전용 시스템"으로 보여야 합니다.
`gov.wrks.ai`가 본체와 바이트 단위로 동일하다는 것은 이미 확인했습니다
(SHA-256 일치, `<title>`만 상이). 즉 **브랜딩만 갈아끼운 것**이고, 그 정도로
충분히 팔린다는 뜻이기도 합니다.

## 관리자 매뉴얼

### A1. 기업계정 개설 (`basic/create-enterprise-account`)

**핵심**: 개인 계정 로그인 → 우상단 **[기업용 버전 가입]** → 회사명 / **회사 유형** /
로고(선택) → [기업 계정 만들기] → 약 1분 프로비저닝.

**회사 유형 선택이 비서 세트 자동 설치를 결정합니다** (→ A14, A15).

**WORKON 현황**: 기관 생성은 **슈퍼관리자 전용**(`/super/organizations`).
셀프서빙 개설 경로 없음. 로고 없음.

**판단**: 공공기관은 셀프서빙으로 계약하지 않으므로 **셀프 개설은 불필요**.
다만 **기관 유형에 따른 비서 세트 자동 설치**는 도입 시간을 줄여 줍니다.

### A2. 회사 정보 (`step-by-step/company-info`)

**핵심**: 회사명 텍스트 + **로고 업로드(500KB 미만)** + [변경하기]. 그게 전부.

**WORKON 현황**: **없음.** 브랜딩이 `NEXT_PUBLIC_APP_NAME` 전역 단일값.

**시사점**: 화면은 단순하지만 멀티테넌트 제품에서 **기관별 브랜딩 수단이
아예 없다는 것**은 구조적 공백입니다. 공공기관은 CI 사용이 규정 사항입니다.

### A3. 직원 초대 (`basic/invite-members`)

**핵심**:
- [사용자 신규 초대] 개별 / **[일괄 대량 초대]** CSV (이름·이메일·권한 3열)
- **권한 3단계**: 최고 관리자 / 워크스페이스 관리자 / 일반 사용자
- 신규 계정 **2주간 1만원 한도** 테스트 크레딧

**WORKON 현황**: 초대 링크 + CSV 일괄 등록(`CsvRegisterTab.tsx`) 있음.
권한은 ADMIN / USER 2단계 + 슈퍼관리자 별도. 부서 계층으로 관리 범위가 갈리므로
'워크스페이스 관리자'에 해당하는 층이 **사실상 이미 있음**.

### A4. 회사 비서 제작·운영 (`basic/company-assistants`)

**핵심**:
- 비서 정보: 소개 / 역할 / **대화 시작 버튼** / 아이콘
- 프롬프트 요술봉
- **[노출 대기중] → [메인 노출] 스위치** — 공개 전 관리자만 보며 테스트
- **카테고리 추가·삭제·이름 변경**, **드래그로 카테고리 순서 조정**
- 카테고리 내 비서 순서 변경(☰)

**WORKON 현황**: 공식/승인대기/반려 3탭 + 승인 처리 있음.
**카테고리 관리·순서 조정·노출 스위치 없음.** 아이콘 입력 없음.
'대화 시작 버튼'(추천 질문) 없음.

**시사점**: 승인 플로우(직원 신청 → 관리자 승인)와 노출 스위치(관리자가 만들고
숨긴 채 테스트)는 **다른 기능**입니다. WORKON엔 전자만 있습니다.

### A5. 관리자 기능 (`basic/admin-features`)

**핵심 메뉴**: 이용통계 / 결제 관리 / 워크스페이스 관리 (그 안에 사용자 관리·공식 비서 관리)

- 이용통계: **비서별 · 직원별 · 부서별**, 매일 자정 갱신, 기간 선택, **Excel 내보내기**
- 토큰 상세: ⓘ 아이콘 → **모델별 토큰 · 이미지 생성 수 · 실시간 검색 사용량**과 요금
- 결제 관리: 당월 요금 / 결제 이력 / 카드 변경
- 좌하단 **[무료 교육 신청]** → 1:1 비대면 온보딩

**WORKON 현황**: 사용량 통계는 **부서별 축만**(`StatsDashboard.tsx`).
사용 내역 조회는 직원 필터 + CSV 있음(`audit-logs`). 모델·비용 열 있음.
결제 관리는 기관 관리자에게 **없음**(슈퍼관리자에만).

### A6. 로그인 연동 (`integrations/sso`)

4가지: MS Entra ID SSO / 그룹웨어 SSO(암호화 인사정보, 고객사 개발) /
**회사 이메일 직접 가입(가장 많이 씀, 개발 불필요)** / CSV 일괄 초대(100명 미만).

강제 로그인 URL: `wrks.ai/ko/signin/id/{기관코드}`

**WORKON 현황**: Credentials만. **도메인 기반 기관 자동 배정은 이미 있음** —
즉 3번 방식과 동등합니다.

**판단**: 문서 스스로 3번이 가장 많이 쓰인다고 밝힙니다. SSO는 후순위가 맞습니다.
다만 **기관별 로그인 URL**은 저렴하고 senGPT식 "전용 시스템" 인상에 직결됩니다.

### A7. 조직도 연동 (`integrations/org-integration`)

**핵심**:
- **최초 1회 200만원(VAT 별도)** 유료 부가서비스, 고객사가 부서 관리 API로 직접 개발
- 공유는 **비서 카테고리 단위** — 개별 비서 단위 공유 불가
- **상위 부서에 공유한 카테고리는 하위 부서 전원에게 자동 노출**
- 카테고리 기본값 **전체 공개**
- 조직도는 하나의 워크스페이스에만 연동 가능
- 문서가 스스로 권고: 필수 아님, **우선 연동 없이 도입 후 사후 연동**

**WORKON 현황**: 부서 계층(`parent_id`) + 상위→하위 cascade(`getVisibleDepartmentIds`)
**기본 제공**. 공개 범위 기본값도 `organization`(전체) — **동일한 결론에 먼저 도달**.
다만 공유 단위가 **비서 단위**(`agents.visibility`)이고 카테고리 단위가 아님.

**시사점**: 여기가 WORKON이 명확히 앞서는 지점입니다. 200만원 유료 + 2~3주 지연이
우리에겐 기본 기능입니다. 조달 제안서에 쓸 재료입니다.

### A8. 사내 데이터 연동 (`integrations/undefined`)

**핵심**: **아직 제공되지 않음.** 2025-11 예정으로 안내 후 미출시.
계획 범위: ERP / SCM / 사내 DB / 데이터 레이크.

**시사점**: 경쟁사도 못 한 영역입니다. WORKON의 커넥터 구조(MCP 표준 툴 정의 +
프로바이더 어댑터 분리)가 오히려 **같은 문제를 이미 푸는 틀**입니다.
공공기관 내부 시스템 연동은 커넥터 하나 추가로 대응 가능합니다.

### A9. 비서 응답 개선 / RAG 노하우 (`advanced/rag-techniques`)

실제 고객 문의와 답변 모음. **그대로 WORKON 관리자 가이드로 쓸 수 있습니다.**

1. **파일에만 의존하면 답이 흔들린다** — RAG는 문단 일부만 발췌하므로,
   원하는 정답 사례를 **비서 프롬프트에 직접** 넣어야 제어된다
2. **일관성이 필요하면 FAQ 형식 파일** — `Q. 출장 여비 / A. 임원 100만원`
   형식이 청크 선택 실패에 강하다
3. **날짜·공휴일은 포기하고 직접 나열** — 20개 미만이면 프롬프트에 직접
4. 같은 질문에 다른 답이 나오는 것은 **청크 선택 편차**이며 구조적으로 불안정하다고
   벤더가 인정

**WORKON 현황**: 관리자용 RAG 운영 가이드 문서 없음. `RAGSearchTester.tsx`는 있음.

### A10. M365 에이전트 (`advanced/m365`)

**핵심**: [기업관리자]-**[맞춤 설정]**에서 "이메일/캘린더 검색 기능 사용" 활성 →
비서 능력 선택에 "내 이메일 내용 및 캘린더 일정 검색 능력" 추가 → 직원이 최초 1회
MS 로그인. 1회 조회 **약 10개 내외**. Teams·OneDrive는 예정.

**WORKON 현황**: 없음.

**판단**: 공공기관은 M365보다 자체 메일·그룹웨어가 지배적입니다. **후순위.**
다만 **[맞춤 설정]이라는 기관 단위 기능 토글 메뉴**의 존재는 참고할 구조입니다.

### A11. 링크형 비서 (`advanced/link-assistants`)

**핵심**: 비서 유형에서 **'링크형 비서'** 선택 → 링크 주소 입력 → [메인 노출].
클릭하면 새 탭으로 외부 URL 연결. 용도는 **자체 보유 도구 등 웍스AI가 지원하지
않는 기능 연결**.

**WORKON 현황**: 없음.

**시사점**: **구현 비용 대비 효용이 가장 좋은 항목입니다.** 비서 목록에
기관 그룹웨어·문서24·업무포털 링크를 얹으면 "AI 도구 모음"이 아니라
**기관 업무 관문**으로 보입니다. 컬럼 2개(`type`, `link_url`)면 됩니다.

### A12. 비서-폴더 연동 (`advanced/auto-sync`)

**핵심**: OneDrive/SharePoint 폴더 연결 → **매일 1회 새벽 자동 동기화**.
**하위 폴더는 동기화 안 됨.** 20MB 이상 일부 파일 처리 불가.

벤더 입장이 문서에 그대로 적혀 있습니다: 동기화 실패는
**"해결해 드릴 수 있는 방법은 안타깝지만 없습니다"** — 파일 처리를 전부 OpenAI가
하기 때문.

**WORKON 현황**: 없음. 단 파서가 자체 구현이라 같은 무력함은 없습니다.

**판단**: 공공기관은 내부망·자체 EDMS가 많아 OneDrive 전제가 안 맞습니다. **후순위.**

### A13. 지원 파일 유형 (`advanced/undefined`)

| 능력 | 형식 |
|---|---|
| 텍스트 위주 | PDF, DOCX, PPTX, **HWP, HWPX**, TXT, HTML, PY, PHP, JSON, MD, JAVA, C, CPP, RB, TEX |
| 숫자 위주 | **XLSX, CSV**, PDF, DOCX, PPTX, TXT, HTML, CSS, PY, PHP, XML, MD, JS, TS, JAVA, C, CPP, RB, TEX, ZIP, TAR, JPEG, JPG, GIF, PNG |

**WORKON 현황**(`document-processor.ts` 확인): PDF / DOCX / TXT / HWP / HWPX.
**XLSX·CSV·PPTX 없음.**

**시사점**: HWP는 이미 시장 표준이라 차별점이 아니라 **탈락 방지 요건**입니다.
반대로 **XLSX/CSV 부재는 실질 격차**입니다 — 공공기관 업무의 상당량이 표입니다
(예산서, 집행내역, 통계표).

### A14. 정부/공공 특화 버전 (`sector-package/public`)

**핵심**: 계정 개설 시 조직 유형 **'정부/공공'** 선택 → 비서 8종 자동 설치
(음슴체 변환기 / 개조식 내용정리 / 정책 홍보문 / 공문 초안 / 보고서 초안 /
민원인 답변 / 연설문 / 회의록) + 웍스 공식 비서 40여종.

데이터 처리 주장: **"고객 데이터를 저장하지 않고"** = 전부 OpenAI에 저장.

**WORKON 현황**: 공공 비서 8종 seed **완전히 동일**. 자동 설치 트리거는 없음.

**시사점**: 비서 8종은 **동등 수준이지 차별점이 아닙니다.**
반면 데이터 저장 위치는 정반대입니다 — WORKON은 Supabase에 자체 저장하므로
보안성 검토에서 설명이 쉽습니다.

### A15. 학교 특화 버전 (`sector-package/school`)

**핵심**: 교사 5인 이상. 생기부 비서 세트(교과 평어 / 행발 / 과세특 / 창체 /
자율시간 운영계획). 구독제 **교사 1인당 월 25,000원**(GPT-5 무제한) 또는 종량제.
서울시교육청 관할 학교는 senGPT 계약 때문에 가입 불가.

**시사점**: **업종 패키지가 곧 영업 단위**라는 구조가 드러납니다.
WORKON도 '기관 유형 → 비서 세트' 구조를 갖추면 신규 기관 도입이 몇 분으로 줄어듭니다.
그리고 인당 정액(월 25,000원)이 공공 예산 편성과 잘 맞는 가격 형태입니다.

# 5부. 결정이 필요한 사항

## D1. 직원 질문 원문을 관리자가 볼 수 있는 문제

**현재 동작이 두 갈래로 갈려 있습니다.**

| 경로 | 질문 원문 | 관리자 열람 |
|---|---|---|
| `/api/chat` (비서 대화) | 저장 안 함 | 불가 |
| `/api/qna` (문서 질의응답) | `details.query`에 저장 | **감사 화면·CSV에 그대로 노출** |

웍스AI는 가입 동의에 **"회사에 제공되는 사용 통계 — 대화 내용 제외"**를
명시합니다. WORKON은 한 제품 안에서 같은 질문에 두 가지로 답하고 있습니다.

이건 기능 문제가 아니라 **정책 결정**입니다. 셋 중 하나를 골라야 합니다.

| 안 | 내용 | 장단 |
|---|---|---|
| **가** | `qna`도 질문 원문 저장 중단 | 웍스AI와 동일. 감사 시 "무엇을 물었는지" 제출 불가 |
| **나** | 저장하되 **감사 화면에서 마스킹**, 별도 권한에서만 열람 | 감사 대응과 프라이버시 양립. 구현 필요 |
| **다** | 현행 유지 + **가입 동의문에 명시** | 최소 비용. 단 동의 없이 수집 중인 현 상태를 그대로 두면 안 됨 |

공공기관은 근로자 감시·개인정보 이슈가 민감하고, 감사 CSV는 정보공개 청구로
외부에 나갈 수 있습니다. **'나'를 권합니다.**

## D2. 공유 단위 — 비서 vs 카테고리

웍스AI는 **카테고리 단위**로만 공유합니다(개별 비서 공유 불가).
WORKON은 **비서 단위** `visibility`입니다.

- 비서 단위: 세밀하지만 비서가 늘수록 관리 부담이 비례해 증가
- 카테고리 단위: 거칠지만 "인사자료 카테고리는 인사과만" 식으로 한 번에 정리

**P1-2(카테고리 도입) 시점에 함께 결정해야 합니다.** 둘을 다 지원하면
"카테고리는 공개인데 비서는 비공개" 같은 모순 상태가 생깁니다.

## D3. 모델 선택을 여는 순서

모델을 먼저 늘리고 정책을 나중에 붙이면, 그 사이 기간의 사용 내역을 보안성
검토에서 소명하기 어렵습니다. **허용 모델 정책 → 모델 확장** 순서를 권합니다.
`models.ts` 레지스트리와 `usage_logs.details.model` 규약은 이미 준비돼 있습니다.
