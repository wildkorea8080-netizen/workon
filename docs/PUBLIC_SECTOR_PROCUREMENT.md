# 공공기관 도입·조달 가이드 (초안)

**작성일**: 2026-08-18
**상태**: 초안 — 일반적인 공공기관 조달 절차 기준. 특정 기관과 협의 시 그 기관 규정으로 대체 필요
**용도**: WORKON을 공공기관에 공급하기 위해 갖춰야 할 것과 그 순서

> ⚠️ 이 문서의 제도 내용은 2026-08 시점 공개 자료 기준입니다. 클라우드 보안인증
> 체계가 전환 중이라(아래 2장) 실제 추진 전에 소관 기관 공고를 재확인해야 합니다.

---

## 요약 — 먼저 알아야 할 것

공공기관에 SaaS를 파는 길은 **기능 경쟁이 아니라 자격 요건**에서 갈립니다.

| 관문 | 없으면 | WORKON 현재 |
|---|---|---|
| **클라우드 보안인증** (CSAP → 국정원 보안검증) | 대부분의 공공기관이 도입 검토조차 못 함 | ❌ 없음 |
| **디지털서비스 등록** | 경쟁입찰을 거쳐야 함 (사실상 진입 곤란) | ❌ 없음 |
| 국내 리전·인프라 | 보안 검토 통과 불가 | ⚠️ **Vercel + Supabase (해외 SaaS 의존)** |

**가장 큰 문제는 마지막 줄입니다.** 3장에서 자세히 다룹니다.

## 1. 조달 경로 — 세 가지

### 1-1. 디지털서비스 전문계약제도 (권장 경로)

SaaS·클라우드를 공공기관이 **경쟁입찰 없이 수의계약**으로 살 수 있게 만든 제도입니다.

```
과기정통부 디지털서비스 심사위원회 심사
        ↓
NIA 디지털서비스 이용지원시스템(digitalmarket.kr) 등록
        ↓
조달청 디지털서비스몰 카탈로그 등재
        ↓
수요기관이 수의계약 체결
```

- 법적 근거: **국가계약법 시행령 제26조 제1항 제5호 아목**
- 실적: 시행 4년 누적 계약 5천억원 돌파, 579개 기관 1,504건

**이 경로가 사실상 유일한 현실적 진입로입니다.** 등록되지 않으면 일반 경쟁입찰을 거쳐야 하는데, 신생 SaaS가 대형 SI와 경쟁해 이기기 어렵습니다.

### 1-2. 나라장터 일반 입찰

- 종합쇼핑몰 등록 또는 공고 참여
- 실적·재무 요건이 붙는 경우가 많아 초기 기업에 불리
- SaaS보다 구축형 사업에 맞는 구조

### 1-3. 소액 수의계약

- 기관별 내부 규정에 따라 일정 금액 이하는 수의계약 가능
- **금액 기준은 기관마다 다르므로 반드시 해당 기관 계약 담당자에게 확인**
- 파일럿·시범 도입에는 쓸 수 있지만 전사 확산에는 부적합

## 2. 클라우드 보안인증 — 지금 전환기입니다

### 2-1. 현행 CSAP

공공기관이 민간 클라우드를 도입할 때 거치는 필수 검증입니다.

- **SaaS는 79개 검증 항목**
- 평가 영역: 관리적 보호조치(정책·인적 보안) / 물리적 보호조치(데이터센터 시설) / 기술적 보호조치(가상화 보안·네트워크 분리)
- 등급이 나뉘며, 취급 정보의 중요도에 따라 요구 등급이 달라집니다

### 2-2. 국정원 보안검증으로 전환 중

체계가 개편되고 있습니다.

- 공공 클라우드 인증을 **국정원 클라우드 보안검증으로 단일화**하는 방향
- 2026년 내 가이드라인 개정 → **2027년 7월 본격 시행**
- 그 사이 약 1년의 유예 기간

**의미**: 지금 CSAP를 새로 준비하기 시작하면 제도가 바뀌는 시점과 겹칩니다. 소관 기관(국정원·KISA·과기정통부) 공고를 추적하면서 준비 방향을 정해야 합니다.

### 2-3. GS인증과 혼동하지 말 것

경쟁사(웍스AI)는 **GS인증 1등급**을 전면에 내세웁니다. 하지만:

| | GS인증 | CSAP / 국정원 보안검증 |
|---|---|---|
| 성격 | 소프트웨어 **품질** 인증 | 클라우드 **보안** 검증 |
| 소관 | TTA 등 | KISA / 국정원 |
| 공공 클라우드 도입 요건 | 아님 | **관문** |

GS인증이 있어도 클라우드 보안인증을 대체하지 않습니다. 참고로 웍스AI의 공개 데이터 보안 정책 문서에는 CSAP·ISMS·국정원 보안검증·망분리에 대한 언급이 없습니다(2026-08 확인). 취득 여부는 공개 자료로 확인되지 않으므로 단정할 수 없습니다.

## 3. ⚠️ WORKON 아키텍처의 구조적 문제

**이 장이 이 문서에서 가장 중요합니다.**

현재 WORKON은 이렇게 구성돼 있습니다:

| 계층 | 사용 서비스 | 성격 |
|---|---|---|
| 호스팅 | **Vercel** | 미국 기업 SaaS |
| DB·스토리지·인증 | **Supabase** | 미국 기업 SaaS |
| LLM | Anthropic Claude | 미국 |
| 임베딩 | Voyage AI | 미국 |

클라우드 보안인증은 **물리적 보호조치(데이터센터 시설 심사)**를 포함합니다. Vercel·Supabase를 그대로 쓰는 구조로는 그 심사를 받을 주체가 없습니다. 리전을 서울로 두더라도, 인증 대상이 되는 것은 우리가 통제하지 못하는 남의 인프라입니다.

### 선택지

| 안 | 내용 | 비용·기간 |
|---|---|---|
| **A. 국내 CSAP 인증 IaaS로 이전** | NHN Cloud / 네이버 클라우드 / KT Cloud 등 CSAP 취득 IaaS 위에 재구축 | 크다. 인프라 재설계 + 인증 절차 |
| **B. 민간 시장 우선** | 공공은 보류하고 민간 기업 대상으로 먼저 검증 | 지금 구조 유지 가능 |
| **C. 파트너 경유** | 이미 인증을 갖춘 사업자의 플랫폼에 얹거나 리셀 | 마진·통제권 손실 |

**A안을 택하면 지금까지의 애플리케이션 코드는 대부분 재사용됩니다.** Next.js·PostgreSQL·pgvector 조합이라 Supabase 특화 기능(Auth, Storage)만 교체하면 됩니다. 다만 인증 절차 자체가 별도의 프로젝트 규모입니다.

**결론: 공공기관 조달을 목표로 한다면 인프라 결정이 기능 개발보다 먼저입니다.**

## 4. 예산·계약 실무

### 4-1. 예산 편성

공공기관 예산은 보통 전년도에 편성됩니다.

- **정보화사업 예산**으로 잡는 것이 일반적
- SaaS는 **자산 취득이 아니라 용역·임차** 성격이라 계정 과목 확인 필요
- 종량제는 예산 편성과 궁합이 나쁩니다 — 기관은 **연간 확정 금액**을 선호합니다

> **WORKON 시사점**: 현재 과금이 종량제 기반(`monthly_token_limit`)인데, 공공기관 대상으로는 **연간 정액 + 사용량 상한** 형태의 계약 옵션이 필요합니다. 한도 초과 시 차단하는 로직은 이미 있으므로(`usage-limit.ts`) 계약 형태만 추가하면 됩니다.

### 4-2. 계약 기간

- 통상 1년 단위, 회계연도(1~12월)에 맞춤
- 다년 계약은 별도 승인 절차가 필요한 경우가 많음
- 연말 예산 소진·연초 계약 공백에 대한 대응 필요

### 4-3. 대가 산정 근거

기관은 계약 심사에서 **단가 산출 근거**를 요구합니다.

> **WORKON 상태**: `models.ts`에 모델별 단가가 정리돼 있고 `usage_logs`에 `cost_usd`/`cost_krw`가 기록됩니다. 산출 근거 제시는 가능합니다.

## 5. 보안성 검토 대응

기관 정보보안 담당자가 요구하는 자료입니다.

| 항목 | WORKON 현재 |
|---|---|
| 데이터 흐름도 (수집·저장·전송·파기) | 작성 필요 |
| 개인정보 처리 위탁 관계도 | 작성 필요 (Anthropic·Voyage·Supabase 재위탁 구조) |
| 접근통제 정책 | 부분 — 부서 계층·공개 범위는 구현, 문서화 필요 |
| 암호화 방식 | API 키 AES-256 (`crypto.ts`), 전송 TLS |
| 로그 보존·제출 절차 | 로그 4종 구현(access/system/security/super_admin), 정책 문서 없음 |
| 계정 관리 (퇴사자 처리) | `is_active` 컬럼 있음, 절차 문서 없음 |
| 취약점 점검 결과 | 없음 |
| **망분리 환경 대응** | **불가** (SaaS 구조상) |

**망분리는 기관에 따라 절대 요건입니다.** 내부망에서만 업무를 처리하는 기관은 SaaS 자체를 쓸 수 없습니다. 이 경우 구축형(On-Premise) 공급이 필요하며, 현재 WORKON은 그 형태를 지원하지 않습니다.

## 6. 감사·정보공개 대응

공공기관 특유의 요구입니다. 민간 SaaS는 대체로 준비돼 있지 않고, **여기가 차별화 여지가 있는 영역**입니다.

### 6-1. 감사 대응

- 특정 기간·특정 직원의 AI 사용 내역 제출 요구가 들어올 수 있음
- **필요 기능**: 기간·사용자 지정 로그 추출(CSV/Excel)
- **WORKON 상태**: 슈퍼관리자 화면에 CSV 내보내기가 있으나 기관 관리자용은 미확인. 감사 목적의 추출 기능은 별도 정리 필요

### 6-2. 정보공개 청구

- AI와의 대화 이력이 공공기록물 또는 정보공개 대상인지에 대한 판단이 필요
- **법령해석례 조회 기능이 있으므로**, 이 질문 자체를 제품으로 답할 수 있음
- **필요 정책**: 대화 이력 보존 기간, 파기 절차, 공개 시 비식별 처리

### 6-3. 기록물 관리

- 공공기관은 공공기록물법 적용을 받음
- AI 생성 문서가 기록물로 등록되어야 하는지 기관 판단 필요
- **필요 기능**: 생성 문서의 원본성·이력 추적

> 이 영역은 **경쟁사도 답을 내놓지 않은 곳**입니다. 웍스AI 문서에도 감사·정보공개·기록물 관리에 대한 언급이 없습니다.
