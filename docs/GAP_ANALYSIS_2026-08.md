## 2-4. 실제로 남아 있는 결함 (신규 발견)

### 🔴 치명적 — 채팅이 멀티턴이 아님

`src/app/api/chat/route.ts:170`
```typescript
const claudeMessages: ClaudeMessage[] = [
  { role: 'user', content: message },   // ← 직전 대화 이력을 전혀 안 넣음
];
```
대화를 DB에 저장은 하지만 **다음 요청에 이전 메시지를 실어보내지 않습니다.** 사용자가 "그럼 그거 요약해줘"라고 하면 AI는 무슨 얘긴지 모릅니다. 챗봇 제품으로서 가장 기본이 깨져 있는 상태.

### 🟠 스트리밍 없음

`grep -rn "stream" src/` → **0건**. 응답이 완성될 때까지 사용자는 로딩만 봅니다. 4096 토큰 답변이면 체감 20초 이상. 웍스AI 대비 UX 격차가 가장 크게 느껴지는 지점.

### 🟠 리포지토리에 위험 파일 방치

```
disable-rls.js       ← 전 테이블 RLS를 끄는 스크립트 (.env.local 읽음)
drop-policies.js
test.exe / test.bat / test.php / test..dangerous.txt   ← 업로드 필터 테스트 잔여물
```
- 마이그레이션 어디에도 `ROW LEVEL SECURITY` 설정이 없음 → **RLS 미사용 상태**. 테넌트 격리가 전적으로 애플리케이션 코드의 `.eq('department_id', ...)`에만 의존합니다. 라우트 하나만 빠뜨려도 타 기관 데이터가 샙니다.
- 실행 파일들은 리포에서 제거해야 합니다.

### 🟡 API 응답 규약 불일치 잔존

`src/app/api/forbidden-words/route.ts:10,17` — 인증/권한 에러가 `{ success: false }`로 반환. 클라이언트(`SettingsManager.tsx`)는 `result.ok`를 검사 → 에러 메시지가 부정확하게 표시됩니다.

### 🟡 타입 안전성 사실상 해제

`next.config.mjs`에 `typescript: { ignoreBuildErrors: true }`. tsc 에러 61건 중 60건은 implicit any지만, 1건은 실제 널 참조 위험:
`src/app/api/super/accounts/users/route.ts:37` — `'deptFilter' is possibly 'null'`

### 🟡 초대 이메일 미발송

`package.json`에 메일 발송 의존성 없음(Resend 등). 초대는 **링크를 관리자가 수동 전달**하는 방식입니다. CSV로 500명 등록하면 링크 500개를 손으로 뿌려야 합니다.

## 전략적 판단

WORKON은 **웍스AI의 "관리 껍데기"는 거의 다 만들었지만 "AI 알맹이"는 초기 단계**입니다.
슈퍼관리자 포털·과금 테이블·감사 로그·기관 계층은 보통 스타트업이 1년차에 미루는 부분인데 이미 있습니다. 반대로 멀티 LLM·툴 실행·멀티모달은 웍스AI가 매일 쓰는 이유 그 자체인데 전부 없습니다.

두 가지 길이 있습니다.

**(A) 정면 승부** — P2 전부 수행. 멀티 LLM + 과금 + HWP까지 3~4주. 웍스AI와 같은 카테고리에서 경쟁하되, 이미 1,500개 기관·GS인증 1등급을 가진 상대와 붙는 것.

**(B) 틈새 집중** — 멀티 LLM은 포기하고 Claude 단일로 가되, **공공기관 특화 RAG + 국가 공공 DB 커넥터 + HWP**에 집중. P1 + P2-4 + P3-2만 수행(2주). 웍스AI가 "전 산업 범용"을 노리는 사이 "지자체·교육청 문서업무 전담"으로 좁게 파는 것.

현 코드베이스가 이미 부서 단위 RAG와 공공기관 디자인 시스템에 최적화되어 있으므로 **(B)가 투입 대비 승산이 높습니다.** 다만 어느 쪽이든 **P0과 P1은 무조건 선행**해야 합니다. 멀티턴이 깨진 챗봇은 어떤 전략으로도 팔 수 없습니다.
