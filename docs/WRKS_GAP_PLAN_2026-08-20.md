## 이 문서의 성격

경쟁 제품에 있는 것을 전부 따라가는 목록이 아닙니다.
**우리 제품이 이미 하고 있다고 믿는데 실제로는 안 하는 것**을 먼저 두고,
그다음에 공공기관 업무에 실제로 필요한 것을 둡니다.

기능을 추가·제거하면 이 문서를 함께 고치세요. 낡으면 이미 있는 것을 다시
만들거나 없는 줄 알고 우회하게 됩니다.

---

## 단계

### A. 통제가 있다고 믿는데 없는 것 (보안) — **먼저**

이 셋은 성격이 같습니다. **관리자나 사용자가 "막았다"고 믿는데 실제로는
안 막혀 있습니다.** 없는 기능보다 나쁩니다 — 없으면 조심이라도 하는데,
있다고 믿으면 조심하지 않습니다.

| # | 항목 | 현재 상태 |
|---|---|---|
| **A1** | 대화 공유 중단 | `POST`만 있음. **한 번 공유하면 영구히 열림** |
| **A2** | IP 접속 제한 | `/super/settings`에 "허용 IP 목록"이 있는데 **읽는 코드가 없음** |

A2는 고치거나 화면에서 빼거나 둘 중 하나입니다. 지금 상태가 가장 나쁩니다.

### B. 종량제를 팔기 위한 장치 (과금 통제)

네 자료가 **전부** 이걸 핵심 관리 기능으로 다룹니다 — 온보딩 콜, 관리자
매뉴얼(워크스페이스 관리), senGPT(1인당 월 25,000원 한도), 웍스AI Desk
("한 달 한도를 금액으로 — 회사 전체 / 부서 / 한 사람당").

종량제는 "얼마 나올지 모른다"는 불안을 주는데, 한도가 그 불안을 없앱니다.
**기능이 아니라 영업 논리의 일부입니다.**

| # | 항목 | 비고 |
|---|---|---|
| **B1** | 부서별·사용자별 **금액** 한도 | `usage_logs.details.cost_krw`와 `department_id`가 이미 쌓임. **판정 층만 없음** |
| **B2** | 통계에 모델별 세부 내역 | `details`에 model·입출력 토큰·원가가 다 있는데 화면에 안 냄 |

공공기관은 **부서별 예산 배정**이 기본 단위라 민간보다 더 필요합니다.

### C. 도입·확산 (작고 효과 큼)

| # | 항목 | 근거 |
|---|---|---|
| **C1** | 비서 **사용 방법** · **대화 시작 가이드** 필드 | 저쪽은 관리자가 직접 적는 필드로 둠. 기관마다 넣을 내용이 다름 |
| **C2** | 개인 비서 파일 상한 재검토 | 우리 10개 ↔ 저쪽 500개. 규정집 한 질이면 넘음 |
| **C3** | 문서 업로드에 **FAQ 형식 권장** 안내 | 청크 검색의 성질에서 나온 조언이라 우리에게도 유효 |

### D. 업무 도구 (새 기능, 큼)

저쪽은 비서와 **별개인 상단 메뉴**로 둡니다. 정해진 입출력을 가진
워크플로라 대화형 비서와 성격이 다릅니다.

| # | 항목 | 새 업체 |
|---|---|---|
| **D1** | 텍스트 추출 → 엑셀 (이미지 20장 일괄) | 불필요 (Anthropic 이미지 입력) |
| **D2** | 문서 작성 (양식 업로드 → 목차 자동 인식 → 항목별 초안) | 불필요 (HWP 파서 있음) |

D1은 통장사본·영수증·명함을 다루는 **서무 업무 직결**입니다.

## 보류 — 별도 결정이 선행

착수하지 않는 이유를 함께 적습니다. 적어 두지 않으면 다음에 또 검토합니다.

| 항목 | 보류 이유 |
|---|---|
| 멀티 프로바이더 (저쪽 6개사) | 공공기관 보안성 검토에서 **사업자가 늘면 소명할 곳이 늘어남**. "Anthropic 한 곳"이 오히려 강점일 수 있음 |
| 이미지 생성 | 새 업체 필요. 교육청 사례를 보면 수요는 실재하나 우선순위 아님 |
| 회의록 STT | 새 업체 필요 |
| **데스크톱 에이전트** (웍스AI Desk) | 기관 PC는 설치 권한이 잠겨 있고 보안 프로그램과 충돌하며 망분리 기관은 아예 못 씀. **"파일이 안 나간다"가 가장 필요한 기관이 가장 못 까는 앱** |
| 조직도 자동 연동 | 저쪽도 **유가 200만원**. 무료 기대 대상 아님 |
| M365 에이전트 / OneDrive 폴더 동기화 | 공공기관은 내부망·자체 EDMS라 전제가 안 맞음 |
| 그룹웨어 SSO | 공공기관에 잘 맞으나 기관별 개별 연동이라 고객이 특정된 뒤 |

## 우리가 앞선 것 (지키기)

경쟁 대조에서 **우리가 나은 자리**입니다. 리팩터링하다 잃지 않도록 적어 둡니다.

| 항목 | 차이 |
|---|---|
| **문서 저장 위치** | 저쪽은 *"데이터를 저장하지 않고 모두 OpenAI에 저장"*. 우리는 Supabase에 우리가 저장하고 임베딩도 우리가 만듦. 심사에서 "그럼 어디 있느냐"에 답할 수 있음 |
| **자료 인용 규칙** | 저쪽은 관리자에게 프롬프트로 해결하라고 안내. 우리는 `/api/chat`에 시스템 레벨로 주입 — 개인 비서에도 적용됨 |
| 문서 형식 | XLSX·CSV·PPTX·스캔 PDF 판독·HWP 표 복원 |
| 감사 대응 | 질문 원문 열람 통제(사유 필수), KST 표기, CSV BOM |
| 테넌트 격리 | `isolation:check`로 실측 |
| 부서 계층 | 워크스페이스와 조직도가 갈라져 충돌하는 저쪽 구조를 우리는 안 가짐 |
