## 1. 문서가 현실과 어긋남 (작지만 중요)

`CLAUDE.md`의 **🟠 기능 공백** 절이 낡았습니다.

| 문서 기재 | 실제 |
|---|---|
| 단일 모델 고정, 모델 선택 없음 | **4종 + 기관별 허용 정책** (0021) |

이 문서는 다음 작업 판단의 근거가 됩니다. 틀린 채로 두면 이미 있는 기능을
다시 만들거나, 없는 줄 알고 우회 설계를 하게 됩니다.

`docs/GAP_ANALYSIS_2026-08.md`도 같은 이유로 재검토가 필요합니다.

## 2. 테스트 공백 — 권한 검사

현재 59개 테스트는 **순수 함수 위주**입니다.

| 있음 | 없음 |
|---|---|
| 모델 정책·단가, 비서 카탈로그, 표 파싱, 스캔 판정, 파일 형식 | **API 라우트의 권한 검사** |

과거 이 프로젝트에서 실제로 났던 사고가 정확히 이 자리입니다 —
`POST /api/forbidden-words`에 `isAdminSession()`이 빠져 있었습니다.
핸들러마다 따로 검사하는 구조라 하나만 빠뜨려도 드러나지 않습니다.

**제안**: 소스를 읽어 관리자 전용 라우트의 모든 핸들러가 `isAdminSession`
또는 그에 준하는 검사를 거치는지 확인하는 테스트. DB 없이 가능하고,
`message-persistence.test.ts`가 이미 같은 방식(소스 검사)을 씁니다.

## 4. 기능 — Phase 4 잔여

우선순위 순입니다.

### 4-1. PPTX 파싱 (중간)

공공기관은 보고·발표 자료가 PPTX로 쌓입니다. 파서 계층이 이미 있어
`spreadsheet.ts`와 같은 자리에 붙이면 됩니다. 새 업체 불필요.

### 4-2. SSO (큼)

웍스AI 문서 스스로 **"회사 이메일 직접 가입이 가장 많이 쓰인다"**고 밝힙니다.
우리는 도메인 기반 기관 자동 배정이 이미 있어 그 방식과 동등합니다.
대형 기관 요구가 실제로 들어왔을 때 착수해도 늦지 않습니다.

### 4-3. 멀티 프로바이더 (큼)

`src/lib/llm/` 어댑터 계층이 먼저 필요합니다. 커넥터가 MCP 표준 형식으로
툴을 정의해 둔 이유가 이것입니다.

**다만 공공기관에서는 신중해야 합니다.** 프로바이더가 늘면 "어떤 데이터가
어느 사업자에게 갔는지"를 전부 소명해야 합니다. 실사용 데이터를 쌓아
필요성이 확인된 뒤가 낫습니다.

### 4-4. STT(회의록)·이미지 생성 (큼, 새 업체 필요)

Anthropic이 제공하지 않아 새 업체를 붙여야 합니다. 보안성 검토에서 설명할
곳이 하나 더 늘어납니다. 요구가 명확해지기 전에는 권하지 않습니다.

## 5. 공공조달 준비 (별도 트랙)

`docs/PUBLIC_SECTOR_PROCUREMENT.md`에 정리돼 있지만, 아직 만들지 않은
문서 자산이 있습니다. **코드가 아니라 제출 자료입니다.**

- 데이터 흐름도 (어떤 데이터가 어디로 나가는지)
- 개인정보 처리 위탁 관계도 (Anthropic·Voyage·Supabase)
- 대화 이력 보존·파기 정책

**인프라 이전은 별개의 큰 결정입니다.** Vercel + Supabase 조합은 CSAP
물리적 보호조치 심사를 통과할 수 없습니다. 공공조달을 실제로 추진한다면
국내 클라우드 이전이 선행 조건입니다.
