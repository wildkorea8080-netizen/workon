# 비서 응답 개선 가이드 (기관 관리자용)

**대상**: 기관 관리자 · 비서를 만들고 문서를 올리는 담당자
**최종 수정**: 2026-08-19

비서가 엉뚱하게 답하거나, 같은 질문에 매번 다르게 답할 때 무엇을 손봐야 하는지
정리했습니다. 이 시스템의 실제 동작을 기준으로 쓴 것이며, 추측이 아닌 부분에는
실측값을 함께 적었습니다.

---

## 1. 먼저 알아야 할 것 — 비서는 문서 전체를 읽지 않습니다

문서를 올리면 800단어 단위로 잘라(청크) 보관하고, 질문이 오면 **가장 비슷한
5조각만** 찾아 모델에게 보여줍니다. 문서 한 권을 통째로 읽고 답하는 것이
아닙니다.

여기서 대부분의 문제가 나옵니다.

| 증상 | 실제 원인 |
|---|---|
| 문서에 있는 내용인데 "모른다"고 답함 | 그 대목이 5조각 안에 안 뽑힘 |
| 같은 질문에 매번 다르게 답함 | 뽑히는 조각이 조금씩 달라짐 |
| 표의 값을 엉뚱한 항목으로 답함 | 표가 잘리면서 머리글과 값이 떨어짐 |

**그래서 "문서를 올렸으니 알아서 잘 답하겠지"는 성립하지 않습니다.**
아래 방법으로 도와줘야 합니다.

---

## 2. 가장 효과가 큰 것 — 비서 프롬프트에 정답을 직접 넣기

문서에만 의존하면 답이 흔들립니다. **꼭 이렇게 답해야 하는 내용은 비서의
'역할 설정'에 직접 적으세요.** 문서보다 훨씬 안정적입니다.

**나쁜 예** — 문서만 올리고 프롬프트는 비워 둠
```
(역할 설정 비어 있음)
```

**좋은 예**
```
당신은 우리 기관 복무 규정 안내 담당자입니다.

자주 묻는 것은 아래대로 답하세요.
- 연차 사용 신청 기한 → 사용일 3일 전까지 그룹웨어로 신청
- 병가 진단서 제출 기준 → 연속 3일 이상일 때 필수
- 초과근무 인정 한도 → 월 57시간

위에 없는 내용은 첨부 문서에서 찾아 답하고,
문서에도 없으면 "규정에서 확인되지 않는다"고 말하세요.
```

숫자·기한·금액처럼 **틀리면 안 되는 값**일수록 프롬프트에 넣으세요.

---

## 3. 문서는 FAQ 형식이 가장 잘 먹습니다

같은 내용이라도 어떻게 정리했는지에 따라 검색 성공률이 크게 달라집니다.

**잘 안 되는 형식** — 줄글로 이어진 규정문
```
제12조(여비) ① 국내출장의 경우 운임, 일비, 숙박비, 식비를 지급한다.
② 제1항의 지급 기준은 별표 2와 같다. 다만 …
```

**잘 되는 형식** — 질문과 답을 짝지어 둠
```
Q. 국내출장 숙박비는 얼마까지 나오나요?
A. 서울 7만원, 광역시 6만원, 그 외 5만원입니다. (여비규정 별표 2)

Q. 식비는 얼마인가요?
A. 1일 2만 5천원 정액입니다. 영수증 제출은 필요 없습니다.
```

직원이 실제로 던지는 말과 문서의 말이 가까울수록 잘 찾습니다.
**규정 원문은 그대로 두고, FAQ 파일을 하나 더 만들어 함께 올리는 것**을 권합니다.

---

## 4. 표는 그대로 올리세요 (중요)

HWP·엑셀·스캔 PDF의 표는 **표 구조를 유지한 채** 보관합니다. 셀을 순서대로
이어붙이지 않습니다. 그래서 "A사의 배분 물량은?" 같은 질문에 제대로 답합니다.

**하지 말아야 할 것**: 표를 줄글로 풀어서 다시 정리해 올리는 것.
오히려 대응 관계가 깨집니다. 원본 그대로 올리세요.

지원 형식: **PDF · DOCX · TXT · HWP · HWPX · XLSX · CSV**

스캔 PDF(글자를 긁을 수 없는 이미지 문서)도 올릴 수 있습니다. 자동으로 판독하며,
업로드 후 "스캔 문서로 판독했습니다"라는 안내가 뜹니다. **판독 결과가 원문과
다를 수 있으니 중요한 문서는 한 번 확인하세요.**

---

## 5. 날짜·공휴일은 프롬프트에 직접 쓰세요

"올해 공휴일이 언제인가요" 같은 질문은 검색으로 잘 해결되지 않습니다.
항목이 20개 이하면 프롬프트에 그냥 나열하는 편이 정확합니다.

```
2026년 기관 주요 일정
- 3월 12일(목) 정기 이사회
- 6월 30일(화) 상반기 실적 마감
- 9월 15일(화) 국정감사 자료 제출
```

---

## 6. 검색이 되는지 직접 확인하는 방법

`문서 관리` 화면 아래 **RAG 검색 테스트**가 있습니다.
비서를 고르고 직원이 물어볼 법한 말을 넣어 보세요.

- **결과가 나옴** → 검색은 되니 답이 이상하면 프롬프트 문제입니다
- **결과가 없음** → 문서가 안 잡히는 것입니다. 3번(FAQ 형식)을 적용하세요

### 참고: 유사도 값 읽는 법

실측한 분포입니다 (2026-08-19, 공문 1건 기준).

| 구분 | 유사도 |
|---|---|
| 질문과 관련 있음 | 0.41 ~ 0.49 |
| 전혀 무관 (요리·날씨 등) | 0.02 ~ 0.11 |

**0.25 미만이면 검색 결과에서 제외**됩니다. 관련 있어야 할 질문이 0.2대로
나온다면 문서의 표현과 직원의 질문이 너무 다른 것이니, 문서 쪽에 직원이 쓸
법한 표현을 추가하세요.

## 7. 비서를 나누세요

비서 하나에 문서 50개를 몰아넣으면 정확도가 떨어집니다. 5조각을 뽑을 때
관계없는 문서끼리 경쟁하기 때문입니다.

| 이렇게 | 말고 이렇게 |
|---|---|
| 규정 안내 비서 (복무·여비·보안 규정) | ~~만능 비서 (모든 문서)~~ |
| 사업 안내 비서 (사업계획·지침) | |
| 계약 비서 (계약 예규·서식) | |

## 8. 자주 묻는 것

**Q. 문서를 올렸는데 비서가 "자료에 없다"고 합니다.**
A. 정상 동작일 수 있습니다. 관련 대목을 못 찾으면 **근거가 없다고 밝히도록**
설계돼 있습니다. 없는 내용을 지어내는 것보다 안전합니다. RAG 검색 테스트로
확인하고, 결과가 없으면 3번을 적용하세요.

**Q. 답변에 출처가 안 보입니다.**
A. 문서를 참고했을 때만 출처가 붙습니다. 출처가 없다면 문서를 쓰지 않고
일반 지식으로 답한 것이니, 그 답은 기관 자료의 근거가 아닙니다.

**Q. 비서를 만들었는데 직원 화면에 안 보입니다.**
A. 새 비서는 **`노출 대기중`** 상태로 만들어집니다. 직접 써 보고 `메인 노출`을
눌러야 직원에게 보입니다. `비서 관리` 화면에서 배지를 누르면 됩니다.

**Q. 문서를 지우면 답변도 바뀌나요?**
A. 바뀝니다. 다만 이미 나눈 대화 기록은 그대로 남습니다.

**Q. 직원이 무엇을 물었는지 볼 수 있나요?**
A. 기본적으로 **앞부분만** 보입니다. 전문 열람은 `사용 내역 조회`에서 사유를
남기고 요청해야 하며, **열람 사실이 보안 로그에 기록**됩니다. 감사 대응은
가능하되 상시 감시는 되지 않도록 한 것입니다.

## 9. 점검 순서 (문제가 생겼을 때)

1. **RAG 검색 테스트**에서 결과가 나오는가?
   - 안 나옴 → 문서를 FAQ 형식으로 보완 (3번)
2. 결과는 나오는데 답이 틀리는가?
   - → 비서 프롬프트에 정답을 직접 명시 (2번)
3. 표의 값을 잘못 답하는가?
   - → 표를 줄글로 풀어 올리지 않았는지 확인 (4번)
4. 문서가 너무 많은가?
   - → 비서를 주제별로 나누기 (7번)
